# 데이터 사전과 검증 계약

버전 1.2 / 2026-09-22. 아래 필드는 구현 계약이다. 실제 SQL·JSON Schema는 해당 릴리스에서 만들고 자동 검증한다. 임의의 필드를 추가하거나 의미가 다른 값을 기존 필드에 넣지 않는다.

## 1. 공통 규칙

내부 ID는 UUID 문자열, PNU는 외부 식별자 문자열이다. 원·㎡·비율의 단위를 필드에 고정한다. 금액은 원 단위 정수, 계산은 Decimal을 우선한다. 큰 정수의 JS 전달은 안전한 범위를 검사한다. 결측은 `null + missing_reason`으로 표현한다.

| 시간 | 의미 |
|---|---|
| observed_at | 실제 관측 또는 자료의 대상 시각 |
| device_created_at | 기기에서 입력한 시각 |
| source_published_at | 출처 발표 시각 |
| collected_at | 자료 확보 시각 |
| recorded_at | 정본 최초 반영 시각. PC가 부여 |
| effective_from / effective_to | 적용기간. 종료는 반개구간의 끝 |
| reviewed_at / valid_until | 검토일과 확인된 유효기한 |

날짜만 알려졌으면 날짜 정밀도를 저장하고 시각을 만들어내지 않는다. 시각은 시간대 있는 ISO 8601, 정본 시각은 UTC로 정규화한다. 관측일과 소급 입력일을 혼동하지 않는다.

자료 종류는 `official_fact / field_observation / broker_report / asking_price / personal_estimate / scenario_assumption / calculated_result`로 구분한다. 출처의 종류, 사실 검증, 대상 매칭, 법적 적용 확인은 서로 다른 상태다.

subjects의 초기 타입은 `asset / parcel / building / survey_unit`이다. 관심 단계는 `unreviewed / background / watch / detailed_review / purchase_ready / hold / excluded / archived`로 구분하고, 매물 출회 상태와 분리한다. 실제로 사용하는 타입·단계만 해당 릴리스에 구현한다.

하위 테이블의 고정 subject_type은 CHECK, 부모의 `(subject_id, subject_type)`는 복합 FK로 검증한다. 기록 종류별 허용 대상은 공통 검증 함수에서 검사한다. 모든 연결은 외래키를 활성화한다. 범용 `subject_type + subject_id`만으로 FK를 대체하지 않는다. [ADR E06]

R1a는 SQLite 없이 파일 스키마를 사용한다. 알려진 물건 ID는 유지한다. 대상 미확인 기록에는 임시 매입 단위 ID와 `resolution_status=pending`을 부여하고 실제 PNU를 채우지 않는다. R1b에서 임시 단위를 만들고 나중의 연결 검토 이력을 남긴다.

R1a의 물건 목록은 `assets.seed.json`에서 불러오며 이 파일을 R1a의 임시 정본으로 사용한다. 파일은 물건 객체의 JSON 배열이고, `location_point`는 WGS84의 `[경도, 위도]`다. 위치점 또는 주소 중 하나 이상을 제공하며 `data_mode`는 `synthetic/private_real`이다. `created_at`은 생성일, `notes`는 비고다. R1b 정본 반영 시 시드의 `asset_id`를 그대로 승계하고 새 ID로 바꾸지 않는다. R1a 기록과 R1b 정본은 동일한 `asset_id`로 연결한다.

records는 종류별 전체 스냅샷이다. 임장·건물·필지·규제·권리·매물 사건·목표 매수가·투자판단·개발안·자금안·매입 준비 검토를 구분한다. 수정은 새 기록으로 하며 원래 기록을 덮어쓰지 않는다. 개인정보 오입력은 실제 삭제 예외로 처리하고 정본·기기·패키지·백업의 사본도 확인한다.

각 필드의 근거는 `record_evidence.field_path`로 연결한다. 전체 응답이 공통 출처이면 루트 근거를 상속하고 예외 필드만 추가 연결한다. 계산 결과는 입력 기록 ID와 계산식 버전을 근거로 가진다. 중개사 전달정보에 공식자료 출처를 붙이지 않는다.

## 3. R1 기록 교환

### 3.1 파일 구성

```text
<batch>.j5field.zip
  manifest.json
  observations.jsonl
  photos/<sha256>.<approved-extension>
```

manifest에는 `format, schema_version, study_id, package_id, created_at, data_mode, files[]`를 둔다. files는 경로·바이트·해시를 담는다. `data_mode=synthetic/private_real`을 구분한다. 확장자 자체는 암호화가 아니다.

관측에는 `event_id, record_type, asset_id, observed_at, device_created_at, route_version_id?, frame_version_id?, payload, attachment_refs[]`를 둔다. R1은 신규 관측과 그 정정 관측만 허용한다. 기존 정본 수정 명령·SQL·거래 연결 명령·관심도 갱신은 허용하지 않는다.

첫 내보내기에서 이벤트 JSON의 UTF-8 바이트를 고정해 보관한다. 재내보내기는 같은 이벤트 바이트를 사용한다. 이벤트 해시는 고정된 관측 행의 바이트로 계산하며 첨부 참조에 파일 해시를 포함한다. ZIP의 생성일·압축 메타데이터가 바뀌어도 이벤트는 같아야 한다. 기록 수정은 새 ID와 `corrects_event_id`로 추가한다.

### 3.2 반영 규칙

1. 경로 탈출·절대경로·중복 파일명·크기·형식·study_id·스키마·첨부 존재와 해시를 검사한다.
2. 같은 event_id·같은 해시는 건너뛴다. 같은 ID·다른 내용은 전체 입력을 보류하고 원본을 유지한다.
3. 사진은 임시 폴더에서 검사한 뒤 내용 해시 경로로 보관한다. DB는 참조 파일 존재를 확인한다.
4. 신규 기록·이벤트 수입 기록·dataset_version을 하나의 DB 트랜잭션으로 반영한다.
5. 실패 시 DB를 롤백한다. 이미 복사한 미참조 사진은 정리대기로 남기며 자동 삭제하지 않는다.
6. 중복 파일만 다시 입력한 경우 dataset_version을 증가시키지 않는다.
7. 결과를 PC 화면·로그에 표시한다. 별도 확인서 왕복은 없다. 백업·파생본 생성 결과는 각각 표시한다.

초기에는 유효한 패키지를 전체 반영하거나 전체 보류한다. 이벤트별 승인안·부분 반영 UI를 만들지 않는다. 서로 다른 날짜 관측이나 서로 다른 ID는 자동 병합·삭제하지 않는다.

R1a는 PC에서 ZIP의 목록·이미지·해시를 확인하는 소형 검사 도구와 별도 폴더 복사로 보존한다. 폰에는 `저장됨 / 내보냄`, R1b PC에는 `반영됨`을 표시한다. 폰의 반영확인 자동화와 자동 삭제는 없다. 조회자료를 바꿔도 폰의 기존 관측을 지우지 않는다.

### 3.3 최소 안전조건

ZIP 압축·해제 크기와 사진 수·단일 크기에 명시적 제한을 둔다. 초기 설정은 압축 100MB, 해제 250MB, 사진 20MB 이내이며 실제 기기 시험 후 조정한다. 제한 초과 기록은 작은 묶음으로 내보낸다.

R1a 사진은 시험한 JPEG/PNG/WebP 경로만 지원한다. 미지원 HEIC는 변환 안내 후 중단하며 성공으로 표시하지 않는다. 매번 변환해 이벤트 해시를 바꾸지 않는다. 촬영 사진이 사진첩에 자동 보관된다고 가정하지 않는다. 사진 방향·썸네일·외부 공유본의 메타데이터 제거는 R1b에서 검증한다.

## 4. 파생본 생성·실패 계약

정본 데이터가 바뀌는 승인 배치마다 dataset_version을 증가시킨다. 수집 요청 로그만 추가하거나 중복 입력만 처리했으면 증가시키지 않는다.

```text
정본 반영 커밋
→ 고정 버전의 일관된 읽기 확보
→ 읽기용 값·JSON·GeoJSON 전체 생성
→ 행수·참조·필수값·버전·파일 해시 검증
→ 새 파생본 게시
→ 최신본 포인터 교체
```

단일 작성 프로세스의 잠금과 읽기 트랜잭션으로 생성 중 정본 버전을 고정한다. 파생본에는 `source_dataset_version, projection_schema_version, generated_at, scope_ids, data_mode`를 저장한다. 산출물마다 서로 다른 정본 버전이 섞여 있으면 게시하지 않는다.

물리적 읽기 테이블을 도입한 뒤에는 전체 교체를 DB 트랜잭션 안에서 처리한다. 중간 실패는 이전 테이블과 버전으로 롤백한다. 정본 반영을 취소하지 않는다. 파일 산출물은 새 버전 경로에서 검증하고 작은 최신본 포인터 파일을 같은 파일시스템에서 교체한다. [ADR E04·E05]

실패 상태는 `정본 반영됨 / 파생본 재생성 실패`다. 이전 산출물의 버전을 최신 정본 버전으로 수정하지 않는다. PC에서는 버전 차이와 마지막 생성 성공일을 표시하고 최신용 내보내기를 막는다. 구본 보존용 내보내기는 별도 명령과 구버전 표시를 요구한다.

네트워크가 없는 폰은 더 최신 정본의 존재를 알 수 없다. `불러온 버전·생성일·최신 정본 여부 미확인`만 표시한다. 실제로 받지 않은 경고를 자동 수신했다고 설명하지 않는다.

실패 후 재시도는 파생본만 다시 만든다. 정본에 이벤트를 재입력하지 않는다. 첫 생성부터 실패했으면 지도 자료 없음·재생성 필요 상태로 둔다. 부분 파생본을 정상 조회자료로 제공하지 않는다.

## 5. 경로·점포·상권 표본

| 객체 | 필수 내용 |
|---|---|
| survey_routes | route_id, 이름, 조사 목적 |
| survey_route_versions | route_version_id, route_id, 순서 있는 구간 목록, 기준일, 이전 버전·변경 사유 |
| survey_units | unit_id, 물리적 점포 위치·층·구획, 연결 asset_id?, 생성·종료일 |
| survey_frame_versions | frame_version_id, 선택 규칙, 포함 unit_id 목록, 확정일, 변경 사유 |
| survey_sessions | session_id, route_version_id, frame_version_id, 시작·종료, 실제 방문구간, 누락 사유 |
| unit_observations | session_id, unit_id, observed_at, 확인 상태, 근거 기록 |

경로 수정과 표본 변경은 각각 새 버전을 만든다. 업체명·업종은 관측값이며 점포 ID를 대신하지 않는다. 점포 물리적 분할·통합은 이전·새 단위의 연결을 남긴다. 하나의 점포가 여러 구간에 걸려도 동일 세션에서 중복 분모로 집계하지 않는다.

표본은 `검토 대상 건물`과 다르다. 상권 조사를 위해 관찰하는 점포가 곧 매입 후보인 것은 아니다. R1a에서는 경로 버전 ID를 파일에 남기고 상세 편집기를 생략한다. R2에서 표본틀과 세션을 구현한다.

공실 집계의 기본 정의:

```text
N = 해당 표본틀의 조사 대상 점포 수
K = 해당 세션에서 점유 또는 공실 상태를 명확히 확인한 점포 수
V = K 중 공실로 확인한 점포 수
관측표본 공실비율 = V / K
상태 확인률 = K / N
```

N 또는 K가 0이면 해당 비율은 null이다. 미방문·확인 불가·당일 휴무·임대 광고만 확인한 점포는 공실 확정으로 처리하지 않는다. N, K, V와 제외·미확인 수를 함께 표시한다. 지역 전체 공실률로 명명하지 않는다.

시점 비교는 양쪽 표본틀에 있고 두 시점 모두 상태가 확인된 공통 점포로 별도 계산한다. 현재 표본 전체의 값과 공통 표본의 값을 섞지 않는다. 점포 분할·합병·업종 기준 변경은 비교 단절 또는 별도 계열로 표시한다. 기록 부재를 영업 지속으로 채우지 않는다.

보행량은 구간·방향·측정시간·시간대·날씨·행사 여부를 함께 기록한다. 실제 우회나 건너뛴 구간을 남긴다. 고정 조사 순서를 벗어났다는 이유로 원기록을 폐기하지 않는다.

## 6. 기초자료와 관찰 기록

필지는 공부면적·도형면적·CRS·도형 버전·주소 확인 상태를 분리한다. 건축물은 총연면적·용적률 산정용 연면적·건축면적·대장상 대지면적·층수·용도·사용승인일·주차·승강기·대장 종류를 저장한다. 총괄표제부와 개별 동을 동시에 합산하지 않는다.

규제는 발행기관·고시번호·문서 단계·발표일·효력일·종료일·공간 범위·용적률 체계·높이·건축선·인센티브 조건·적용 검토 상태를 가진다. 보도자료·심의결과를 현재 효력이 확인된 결정고시로 취급하지 않는다.

권리관계에는 열람 대상, 확인일, 전체/일부 이전, 이전일, 확인된 공유 여부·인원, 근저당·신탁 여부 등 최소 파생값을 둔다. 소유자 이름·주소·사적 사정과 실제 대출잔액 추정은 저장하지 않는다. 등기 원본의 앱 보관은 초기 제외한다.

매물 사건에는 광고 확인·전달된 매도의향·호가 변경·매각 철회·계약 확인 등 사건과 가격 종류·범위·조건·확인일·재확인일을 저장한다. 출회 확률을 계산하지 않는다. 기록 없음·매물 여부 미확인·매도하지 않겠다는 전달 확인을 구분한다.

현장 기록의 필수값은 대상·관측일·`변화 확인 / 변화 없음 / 확인 어려움`이다. 변화 확인 시 사진 또는 설명 하나를 요구한다. 사진 태그는 전면·1층·임대 광고·공사·도로·주차·인접 관계 등으로 제한해 시작한다. 반복 촬영은 viewpoint_id·방향·이전 사진 참조를 선택 입력한다.

현장 도로폭 추정, 공식 도로자료, 법적 접도 검토 결과를 각각 기록한다. 현장 관측을 법률 판단으로 자동 변환하지 않는다.

## 7. 거래 수집·연결

### 7.1 수집 범위

설정값: `history_target_start=2006-01`, `initial_focus_start=2021-09`. API 접근 승인이 확인되면 오래된 월·중간 월·최근 월의 표본 응답부터 확인한다. 최근 구간을 먼저 사용할 수 있도록 소급 수집을 나눈다.

`collection_runs`에는 제공자·엔드포인트 버전·시군구 코드·계약월·페이지·시도일·성공 상태·응답 수·원본 해시·필드 가용성을 둔다. 중단 후 이어받을 체크포인트를 남긴다. 전체 공개 시작일과 실제 수집 완료기간을 분리한다. [ADR E01·E02]

비교 블록이 같은 시군구에 속하면 원본 응답을 재사용하고 저장 후 분류한다. 미확인 주소를 임의 경계 안에 넣지 않는다. 핵심/비교 범위 밖 행은 원본에 남길 수 있으나 모바일·분석집계에 자동 포함하지 않는다.

과거 자료는 한 번 수집한 뒤에도 취소·정정 점검 대상이다. 초기 운영은 월 1회 최근 6개월, 분기·반기 실패구간 점검, 연 1회 누적 재검증으로 시작하고 실제 변경량·쿼터를 보고 조정한다. API 실패·정상 0건·페이지 누락을 구분한다.

### 7.2 거래 구조

transaction_observations는 배치·페이지·행·내용·수집시각을 보존한다. transactions는 내부 거래 ID, 계약일, 범위·상태를 가진다. transaction_links는 대상 ID, 연결 범위, 근거, 검토일, 철회 이력을 가진다.

범위는 `whole_asset / multi_parcel_bundle / land_only / building_only / partial_share / strata_unit / unclear`다. 일반건축물 지번 일부 공개에 따라 확정 연결이 안 되는 거래를 허용한다. 일괄 총액을 구성 필지마다 복제하지 않는다. 같은 금액·면적·날짜의 별개 행을 자동 한 건으로 합치지 않는다. [ADR E02]

미확인 → 후보 생성 → 근거 대기 → 확정 → 철회/대체 상태로 관리한다. 현재 통계에서는 취소 확정 거래를 제외한다. 제공 응답에서 사라졌다는 이유만으로 취소를 확정하지 않는다. 정정의 원본과 판단 시각은 보존한다.

공시지가는 정확한 PNU·가격 기준연도가 확인된 비교 대상에 연결한다. 현재 공시지가를 오래된 매매가의 동시점 분모로 쓰지 않는다. 확보하지 못한 과거 공시지가는 미확인이다.

## 8. 이력·투자판단

관측 기준 조회는 시점 T의 상태를 현재 확보한 근거로 재구성한다. 당시 기록 기준 조회는 정본 기록일이 K 이하인 근거·검토결정만 먼저 선택한 뒤 시점 T의 상태를 재구성한다. 기본 당시 보기에서는 K=T다. 이후 입력된 연결 철회·규제 해석·사진을 당시 보유정보로 넣지 않는다.

대표값·투자판단의 승인·철회 역시 불변 검토기록으로 보존한다. 현재 승인 상태를 과거 보기의 기본값으로 사용하지 않는다. 상태를 관측하지 않은 기간은 보간하지 않고 마지막 확인일을 표시한다. 당시 경계가 없으면 현재 경계 위의 과거 속성임을 표시한다.

목표 매수가는 `가격 종류, 가격, 판단일, 전략, asset 구성 버전, 비용·규제 전제, 비교 근거, 유효 조건, 수정 사유, 이전 기록 ID`를 가진다. 실제 거래가·호가와 별도 표시한다. 거래가격 예측 적중률로 평가하지 않는다.

정식 투자판단 10항목은 전략, 대체재, 현재 가격차, 가격차 변화 조건, 수요, 활용 가능성과 제약, 자금·현금흐름, 반대 근거, 판단 변경 조건, 매입 조건·다음 확인사항이다. 초안은 일부 항목만 작성할 수 있다.

사진·거래·임대·규제·목표 매수가 모두 자료 종류·시점·출처를 표시한다. 오래된 호가와 종료일 미확인 규제의 재확인 필요를 표시한다. 미래 시나리오가 현재 확정 값에 섞이면 검증을 실패시킨다.

| 필드 | 의미 |
|---|---|
| registered_parcel_area_m2 | 공부상 필지면적. 여러 필지는 구성 버전과 중복 제거 근거 필요 |
| register_site_area_m2 | 건축물대장에 기재된 대지면적 |
| statutory_site_area_m2 | 해당 개발안의 법정 산정 대지면적. 검토 근거 필수 |
| statutory_excluded_area_m2 | 법정 산정에서 제외한다고 확인한 면적 |
| placement_envelope_geometry / area_m2 | 건축선·배치 제약을 반영한 설계 검토 영역. FAR 분모와 별도 |
| area_constraints[] | 제약 종류·도형·적용 근거·분모 제외 여부 true/false/unknown·검토일 |

현행 시행령 제119조는 특정 건축선과 도로 사이 부분 및 도시계획시설 포함 부분 등의 제외를 규정한다. 모든 건축선 후퇴를 같은 제외 유형으로 처리하지 않는다. 개별 적용은 법령·지구단위계획·전문가 검토로 확인한다. 종로5가에서 해당 유형이 얼마나 흔한지는 전수 확인 전 단정하지 않는다. [ADR E03]

법정 제외 영역끼리 겹치면 면적을 이중 차감하지 않는다. 자동 도형 합계는 검토 보조값이다. 대지 구성·제외 근거가 확인되지 않으면 statutory_site_area_m2를 확정하지 않는다.

```text
A = statutory_site_area_m2
F = 해당 검토안의 적용 용적률(%)
C = 동일 구성 범위의 현재 용적률 산정용 연면적
용적률 기준 검토면적 = A × F / 100
용적률 기준 여유면적 = A × F / 100 − C
소진율 = C / (A × F / 100)
```

어느 입력이든 미확인이면 결과는 null이다. 분모 0은 오류, 음수 여유면적은 그대로 표시하고 원인을 검토한다. 적용 법령·규제 버전·면적 시점·계산식 버전을 저장한다. 배치 영역 면적을 A 대신 자동 대입하지 않는다.

가상 테스트: 법정 대지 100㎡, F=600%, C=240㎡이면 검토면적 600㎡·여유면적 360㎡다. 배치 검토영역이 60㎡라도 이 사실만으로 분모를 바꾸지 않는다. 별도 법정 제외 10㎡가 확인되어 A=90㎡이면 검토면적 540㎡·여유면적 300㎡다.

설계 가능 연면적·임대 가능 면적·주차·높이·구조 검토는 건축사의 안과 조건을 저장한다. 현상 유지·리모델링·철거신축·공동매입을 비교한다. 여유면적으로 신축 가능 여부나 저평가를 자동 판정하지 않는다.

인접 관계는 공유 경계·꼭짓점 접촉·거리 이내 후보를 구분한다. 원본 CRS·도형 버전·허용오차를 남기고 필지 변경 시 재계산한다. 공동매입안은 추가 가격·취득 순서·기간·한쪽만 확보했을 때의 운영안을 포함한다.

## 10. 가격 기준과 필요자기자본

### 10.1 입력 정규화

`price_input_basis`는 `gross_contract / net_after_deposit / settlement_residual / unknown`이다. `price_input_krw`, `deposit_already_deducted_krw`, `assumed_tenant_deposits_krw`, 기지급금·별도 비용·VAT 포함 여부·정산 근거를 저장한다.

계산의 기준 P는 보증금 차감 전 전체 계약금액이다. 순액 입력이고 차감액이 확인되면 P를 복원한다. 보증금 차감액은 승계 총액과 같다고 가정하지 않으며 부분 차감도 명시한다. 다른 채무·기지급금까지 섞인 잔금만 입력되면 총액을 확정하지 않는다.

```text
총액 입력: P = price_input_krw
보증금 차감 후 입력: P = price_input_krw + deposit_already_deducted_krw
매입 전체 필요자기자본 = P − L − D + T + B + V + R + E
```

L은 새로 조달하는 실제 대출 또는 명시한 시나리오, D는 정산에 반영되는 승계 보증금, T는 취득세 등, B는 거래·실사비, V는 별도 선지급 세액 등, R은 초기 수선, E는 예비현금이다. 각 비용이 가격·다른 비용에 포함되었는지 확인한다. 매도인 기존 담보대출의 상환액을 P에서 다시 차감하지 않는다. 해당 채무의 인수 등 특수 정산은 별도 검토안으로 둔다.

기지급 계약금·중도금은 지급 시점별 현금흐름에 반영한다. 전체 필요자기자본과 현재 시점의 추가 잔금 현금을 구분한다. P에 이미 보증금을 뺀 값을 넣고 D를 다시 차감하는 입력을 허용하지 않는다.

| 가상 검증 | 입력 | 결과 |
|---|---|---|
| 총액 입력 | P=40억원, L=24억원, D=1억원, 기타=2억원 | 17억원 |
| 순액 입력 | 입력 39억원, 이미 차감한 보증금 1억원, 위와 같은 조건 | P=40억원 복원 후 17억원 |
| 기준 미확인 | 입력 39억원, 차감 전후 미확인 | 완성 결과 미출력 |
| 보증금 반환 | 위 매입안에서 후속 반환 발생 | 후속 현금유출 1억원 반영 |

보증금·선순위 공제가 금융기관의 순대출 한도에 이미 들어갔으면 다시 차감하지 않는다. LTV 50·60·70%는 가정이며 실제 승인과 분리한다. 담보 기준은 매입가 가정·감정가·금융기관 확인을 구분한다.

### 10.2 사업기간 최대 필요자기자본

CF_t에는 매입·임대·운영비·이자·원금·세금·보증금 반환·명도·설계·공사·추가 대출·환급을 시점별 반영한다. 소유자의 자기자본 투입은 CF_t의 유입에서 제외한다. 기본안은 임대 잉여현금을 사업에 유보하는 조건이며 인출 계획이 있으면 별도 유출로 반영한다.

```text
최대 필요자기자본 = max(0, −min_t Σ CF_0..t) + 별도 예비현금
```

예비현금이 CF에 들어가 있으면 마지막에 더하지 않는다. 가상 누적 현금흐름이 -17, -20, -18억원이고 별도 예비 1억원이면 최대 필요자기자본은 21억원이다. 미확인 비용이 있으면 알려진 항목 합계만 표시하고 전체값을 확정하지 않는다.

NOI·Cap rate·DSCR은 비용과 분모 정의를 표시한다. 금융기관 RTI 기준과 동일하다고 취급하지 않는다. 세무 미확인 상태에서 세후수익률을 확정 출력하지 않는다.

## 11. 매입 준비 기록과 진입조건

`acquisition_case`는 asset 구성 버전, 전략, 검토 가격·범위, 비용·금융 시나리오, 매물 사건, 체크리스트 버전, 소유자의 승인, 검토 시각을 묶는다.

각 체크 항목은 `status, evidence_ids, reviewer_role, checked_at, valid_until?, recheck_triggers, open_issues, not_applicable_reason`을 가진다. 상태는 `not_started / in_progress / verified / conditional / blocked / not_applicable`다. 정해지지 않은 기한을 30일·90일 등으로 자동 채우지 않는다.

| 항목 | 준비 확인 내용 |
|---|---|
| 매입 범위·가격 | 전체/지분/구분소유, 포함 필지·건물, 총액·보증금·VAT·호가 확인 수준 |
| 금융 | 금융기관 사전 검토액·조건·감정·한도 유효성, 실행 전제와 실제 확보할 자기자본 |
| 세무·법적 검토 | 매수 주체, 취득·보유·매각 관련 검토, 필요한 허가·규제·거래 조건 |
| 권리·임대차 | 최신 권리 확인, 임대차·보증금 명세 대사, 권리 정리·승계·명도 조건 |
| 건축·토지 | 전략에 필요한 건축사 검토, 면적·접도·위반·구조·수선·현장 실사 |
| 사업·자금 | 유지·리모델링·신축 대안, 최대 필요자기자본, 공실·비용 증가 대응 |
| 계약 협상 | 협상 상한, 조건부 이행·해제·기한 등 협의할 조건, 전문가 확인·미해결 사항 |
| 최종 의사결정 | 같은 예산 대체재, 보류·중단 조건, 본인 승인 |

purchase_ready 전환은 필수 항목이 verified 또는 사유 있는 not_applicable이고, 유효기한 경과·중요 미확인·blocked가 없을 때 사용자가 승인한다. conditional은 조건 충족 또는 전문가가 검토한 계약 처리방안의 근거가 정리될 때까지 미완료다.

이 상태는 계약 협상 준비 상태다. 은행 사전 한도는 실행 확약으로 표시하지 않는다. 권리·규제·임대차 확인은 계약 직전과 잔금 직전 다시 점검한다. 새로운 위험을 확인하면 준비 상태를 철회하는 이력을 남긴다.

가격·대출·임대보증금·전략·구성 토지·규제·중요 실사 결과가 바뀌면 영향을 받는 체크를 재검토 상태로 바꾸고 purchase_ready를 해제한다. 자동 계약·송금·중개사 연락·전문가 예약은 구현하지 않는다. R7은 기록·검토·비교자료 내보내기까지다.

## 12. 백업·보안·이전

실데이터는 `J5_DATA_HOME`의 db, raw, photos, inbox, quarantine, exports/private, backups, logs에 보관한다. 경로는 DB에 상대경로로 저장한다. 코드 저장소·정적 배포에는 실제 기록과 API 키를 넣지 않는다.

정본 백업은 쓰기를 잠시 중단하고 SQLite 백업 API의 일관된 사본, 무결성·외래키 검사, 참조 파일·해시 목록을 함께 만든다. 실제로 다른 폴더에서 복구해 기록 수와 사진 해시를 확인한다. DB 실행 중 파일 하나를 임의 복사하지 않는다. [ADR E07]

R1a는 내보낸 ZIP을 PC와 독립된 위치에 한 번 더 보관한다. R1b 이후는 반영 배치마다 백업하고 원본 입력을 유지한다. 백업 실패는 반영 실패와 구분해 경고한다. 민감 백업의 암호화는 검증된 도구·기기 기능을 사용하고 자체 암호 알고리즘은 만들지 않는다.

조회 패키지는 필요한 범위·사진만 넣고 기본적으로 권리관계 제한자료를 제외한다. 공개 앱 코드 변조·XSS 방어, 배포 허용목록, ZIP 검사, 불필요한 네트워크 차단을 시험한다. 기기 잠금·저장 삭제·분실에 대한 한계를 안내한다. [ADR E08]

브라우저 저장은 사이트 origin에 연결된다. 도메인·기기 이전 전에 기록을 파일로 내보내고, 새 기기에서는 검증한 조회 패키지를 불러온다. 새 폴더 복구·구패키지 읽기·연말 CSV/JSONL/GeoJSON 보존본을 유지한다.
