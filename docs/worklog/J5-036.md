# J5-036 조건 찾기의 물건 조건과 필지 패널 관심 단계

기록일: 2026-09-28. J5-033(조건으로 필지 찾기)과 J5-029(관심 단계) 뒤에 남은 후속 후보 두 가지를 묶었다. 하나는 "조건 결과를 관찰목록 후보로 넘기는 흐름", 다른 하나는 "필지 패널 '안의 물건' 에 관심 단계 표시" 다. 후보를 넘기는 흐름은 J5-028(필지에서 물건 만들기)이 이미 한다. 조건에 맞으면서 아직 물건이 없는 필지를 찾을 수 없었던 것이 빠진 조각이라 그 조건을 더했다. 폰은 관심 단계를 바꾸지 않는다(ADR-22).

## 결과

- `web/app/parcels.js`:
  - `ASSET_CRITERIA`: `none` 물건 없는 필지, `any` 물건 있는 필지, `watch` 관찰목록 물건이 있는 필지.
  - `parseFilter` 가 `assets` 를 받고 목록에 없는 값은 오류로 돌려준다. `hasCriteria` 도 이 조건을 센다.
  - `filterParcels(…, { assetsOf })`: 필지 안의 물건 목록을 돌려주는 함수를 받아 물건 조건을 거른다. 물건 조건은 이 기기의 물건 목록으로 정해지므로 결측 집계가 없다. 다른 조건에서 이미 빠진 필지는 계산하지 않는다. 물건 조건이 있는데 함수가 없으면 오류를 낸다.
  - `filterRowText(attrs, inside)`: 물건 목록을 주면 "물건 n개 (관찰목록 k)" 또는 "물건 없음" 을 덧붙인다. 주지 않으면 이전과 같다.
- `web/app/main.js`:
  - 조건 찾기가 필지 패널과 같은 규칙(`parcelAssets`)으로 필지 안의 물건을 셈한다. 기준은 정본 연결(시드와 필지 파일이 같은 파생본일 때만) 또는 위치점 포함이다. 필지마다 한 번만 계산한다.
  - 필지 패널 "안의 물건" 줄에 관심 단계·확인 전 배지(`trackingBadges`)를 보인다.
- `web/index.html`: 조건 찾기에 "물건" 선택과 기준 설명 한 줄.
- 앱 0.2.13, SW 캐시 v0.2.13.
- 시험: `tests/web/parcels.test.mjs` 1건(없음·있음·관찰목록, 보류는 관찰목록 아님, 다른 조건과 함께, 결측 집계 유지, 결과 줄). `app.e2e.test.mjs` 조건 찾기 절에 물건 조건·결과 줄·필지 패널 배지를 더했다.
- 문서: 릴리스 계획 §10 J5-036, `web/README.md`, 색인(J5-035 #82).

## 데이터 사전에 없어 정한 값

- 관찰목록 물건은 관심 단계 watch·detailed_review·purchase_ready 다(`seed.js` `WATCHLIST_STATUSES` 와 같다). 보류·제외·보관은 넣지 않는다.
- 물건 조건의 "필지 안의 물건" 은 필지 패널과 같은 기준이다. 연결이 확정되지 않은 위치점 포함도 물건 있음으로 센다.

## 테스트 명령과 결과 (2026-09-28, 컨테이너 Linux, Node 22, Python 3.11)

- `python -m pytest -W error::UserWarning` → 390 passed (폰 변경만).
- `node --test --test-timeout=180000 "tests/web/*.test.mjs"` → 82 pass, 0 fail (새 시험 1건 포함).

## 리뷰 반영 (PR #83, Codex 1건)

- P2 물건 목록이 바뀌어도 결과가 그대로: 조건 찾기 결과·지도 테두리는 찾기를 누를 때만 계산됐다. 기기 물건 만들기·삭제나 시드 교체로 물건 목록이 바뀌어도 "물건 없음" 필지가 목록과 테두리에 남았다. 이제 마지막으로 찾은 조건을 기억하고(`state.parcelFilter`), `renderAssets` 가 물건 목록을 새로 그릴 때 그 조건으로 결과를 다시 그린다. 폼에서 고치고 아직 찾지 않은 값은 쓰지 않는다. 지우기·필지 파일 교체·잘못된 조건이면 기억을 지운다. e2e 에 "결과 필지를 물건으로 만들면 빠지고 지우면 돌아온다" 를 더했다. 다시 그리는 한 줄을 빼면 이 시험이 실패함을 확인했다.

## 실제 작업 시간

약 0.6시간 (설계 0.1, 구현 0.2, 시험 0.2, 문서 0.1). 리뷰 반영 0.3시간 별도.

## 미확인 변수

- 2,700필지 × 물건 수십 개의 위치점 포함 계산 시간을 iPhone 에서 재지 않았다. 물건 조건이 있을 때만 계산하고 필지마다 한 번으로 줄였다.

## 남은 인수조건·후속 작업

- 사용자: 실제 파생본을 폰에 넣고 "물건 없는 필지" 와 용도지역·면적 조건으로 후보를 좁힌다. 이어서 필지 패널의 "이 필지를 물건으로 기록" 으로 기기 물건을 만들고, PC 반영 뒤 `db asset-track` 으로 관찰 단계를 준다.
- 후속 후보: 조건 저장. 실제로 같은 조건을 반복해 쓰는지 확인한 뒤 정한다.
