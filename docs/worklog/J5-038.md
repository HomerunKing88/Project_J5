# J5-038 필지 목록으로 물건 만들기

기록일: 2026-09-28. J5-037(`db parcels-find`)로 후보 필지를 고른 뒤 관찰목록에 올리려면 두 가지 방법뿐이었다. 하나는 폰에서 필지마다 "이 필지를 물건으로 기록"(J5-028) 한 뒤 PC 에서 확정하는 것이고, 다른 하나는 시드 파일을 손으로 써서 `load-seed` → `parcels-suggest`/`parcels-link` → `asset-track` 을 차례로 하는 것이다. 이 과정을 PC 명령 하나로 묶었다.

## 결과

- `j5/db/parcel_assets.py`(새):
  - `interior_point`: 폰 `interiorPoint` 와 같은 규칙이다. 가장 큰 조각의 면적 중심을 쓰고, 그 점이 필지 밖이면 bbox 격자에서 안에 드는 점을 찾는다.
  - `pnus_from_csv`: `parcels-find --csv` 파일의 pnu 열을 읽는다.
  - `plan`: 만들 것과 건너뛸 것을 정한다.
  - `create_from_parcels`: 아래 셋을 한 트랜잭션으로 한다. 중간 실패면 모두 되돌린다.
    - 물건 만들기: `load_seed` 와 같은 경로. 이름은 "동 지번", notes 에 만든 경위를 적는다.
    - 연결: `apply_links`, basis manual, 시작일은 기본 오늘.
    - 관심 단계: `set_status`, `--track` 을 줄 때만.
  - 이미 물건이 있는 필지(기준일에 유효한 연결 또는 위치점 포함)는 건너뛰고 이유를 적는다.
  - 정본에 없는 PNU·형식 오류·50필지 초과·없는 날짜는 전체를 거절한다.
- CLI `db asset-from-parcels`: `--pnu`, `--csv`, `--track`(purchase_ready 제외), `--reason`, `--effective-from`, `--dry-run`, `--json`.
- `j5/db/parcel_find.py`: 필지별 물건 함수를 `assets_by_parcel` 로 이름을 드러내 두 모듈이 같이 쓴다. 이 이름 변경은 J5-037 리뷰 반영 커밋에 함께 들어갔다.
- 시험 `tests/test_j5_038_asset_from_parcels.py` 4건.
- 문서: 릴리스 계획 §10 J5-038, `j5/README.md`, `tests/README.md`, 색인.

## 데이터 사전에 없어 정한 값

- PC 에서 필지로 만든 물건은 resolution_status confirmed 다(사람이 PC 에서 고른 것). 폰에서 만든 물건은 pending(ADR-21)으로 둔다.
- 연결 basis 는 manual 이다. note 는 "필지에서 만든 물건 (asset-from-parcels)" 이다.
- 한 번에 50필지(릴리스 계획 §6 정기 관찰목록 30~50개 규모).
- dataset_version 은 물건·연결·단계 변경마다 오른다. 한 명령에서 여러 번 오를 수 있다.

## 테스트 명령과 결과 (2026-09-28, 컨테이너 Linux, Node 22, Python 3.11)

- `python -m pytest -W error::UserWarning` → 400 passed (새 시험 4건, J5-037 리뷰 반영 시험 보강 포함).
- `node --test --test-timeout=180000 "tests/web/*.test.mjs"` → 폰 변경 없음.

## 자체 검토 반영 (머지 뒤, 후속 PR)

- `create_from_parcels` 에 같은 PNU 가 여러 번 오면 한 필지에 물건이 둘 생겼다(CLI 는 중복을 걸렀지만 함수는 걸르지 않았다). `plan` 이 입력의 중복을 먼저 뺀다. 시험 보강(고치기 전 코드에서 실패함을 확인).

## 실제 작업 시간

약 0.8시간 (설계 0.15, 구현 0.3, 시험 0.25, 문서 0.1). J5-037 리뷰 반영 0.2시간 별도.

## 미확인 변수

- 실제 정본에서 만든 물건의 이름("동 지번")이 현장에서 쓰는 이름과 맞는지는 사용자가 본다. 이름은 나중에 시드로 고칠 수 있다(`load-seed` 는 서술 필드만 갱신).

## 남은 인수조건·후속 작업

- 사용자(PC):
  1. `j5 db parcels-find … --csv ~/J5_DATA_HOME/exports/후보.csv` 로 후보를 받는다.
  2. `j5 db asset-from-parcels --csv ~/J5_DATA_HOME/exports/후보.csv --dry-run` 으로 만들 것을 확인한다.
  3. `--track watch` 를 붙여 만든다.
  4. `j5 db project` → `project-copy` 뒤 폰의 "관찰목록만" 에서 확인한다.
