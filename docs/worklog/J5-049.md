# J5-049 운영 점검의 범위 규칙 시군구

기록일: 2026-09-28. J5-048 로 범위 규칙에 시군구(`lawd_cd`)를 줄 수 있게 됐다. 사용자의 실데이터 규칙에는 아직 시군구가 없다. 종로구만 모으는 동안은 결과가 같다. 다른 시군구의 거래를 반영한 뒤에는 같은 이름 법정동이 핵심·비교로 섞일 수 있는데, 이를 알려 주는 곳이 없었다.

## 결과

- `j5/db/ops.py` `_check_db`(읽기 전용 그대로):
  - 현재 범위 규칙과 정본 거래의 시군구 목록을 `zone_rule` 로 결과에 넣는다(판·규칙 시군구·거래 시군구).
  - 거래 시군구가 둘 이상인데 규칙에 시군구가 없으면 조치 항목 `zone_rule_sgg_missing` 을 낸다. 규칙 파일에 `lawd_cd` 를 넣어 `rt-zones apply` 로 반영하라고 안내한다. 규칙 반영은 정본을 바꾸므로 백업·파생본 조치보다 먼저 낸다(J5-042 리뷰 반영의 순서 규칙).
  - 글 출력에 "범위 규칙: v판 · 시군구 … · 거래 시군구 …" 줄.
- 시험 `tests/test_j5_049_ops_zone_sgg.py` 1건: 한 시군구뿐이면 통과, 두 시군구면 조치 항목과 순서, 시군구를 넣은 새 판이면 통과. 고치기 전 코드에서 실패함을 확인했다.
- 문서: 릴리스 계획 §10 J5-049, `j5/README.md`, `tests/README.md`, 색인(J5-048 #95).

## PR #95 늦은 리뷰 반영 (Codex 1건, 이 PR 의 별도 커밋)

- P2 시군구 코드의 숫자 검사: 게시 전 확인이 `zone_rule.lawd_cd` 와 `coverage[].lawd_cd` 를 `str.isdigit()` 로 검사해 `１２３４５` 같은 전각 숫자도 통과시켰다. 규칙 스키마와 폰 검증(`/^\d{5}$/`)은 ASCII 숫자만 받으므로 PC 확인과 폰 결과가 어긋났다. ASCII 숫자 다섯 자리만 받도록 고쳤다. 시험 추가(고치기 전 코드에서 실패함을 확인).
