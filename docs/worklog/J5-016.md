# J5-016 규제·개발안·자금 (R5)

기록일: 2026-09-25. 첫 조각 **A**: 계산기 세 종류(용적률 기준 여유면적, 매입 전체 필요자기자본, 사업기간 최대 필요자기자본)와 입력 계약. 둘째 조각 **B**: 개발안 비교와 후보별 현금표·CSV. 셋째 조각 **C**: 규제 검토·개발안·자금안을 정본 기록 종류로. 완료 조건 "면적·총액/순액·최대 현금 테스트"(릴리스 계획 §10)를 데이터 사전 §9~§10 의 가상 검증 사례로 재현한다.

## A. 결과

- `schemas/calc_inputs.schema.json`(`kind: far / equity / cash`): 면적·금액은 값과 근거를 함께 두고, 미확인은 `null` 과 사유다. 0 으로 채우지 않는다.
- `j5 calc far <입력.json>`: A(법정 산정 대지면적)·F(적용 용적률)·C(용적률 산정용 연면적)로 검토면적·여유면적·소진율. A 는 직접 입력 또는 공부면적 − 확인된 법정 제외면적(`statutory_basis: registered_minus_excluded`). 어느 입력이든 미확인이면 결과 null, 분모 0 은 오류, 음수 여유면적은 그대로 표시. 배치 검토영역은 기록만 하고 A 를 대신하지 않는다. 분모 제외 여부 `unknown` 인 제약이 있거나 규제 버전이 없으면 A·F 를 확정할 수 없어 결과를 내지 않는다. 총연면적 < 산정용 연면적이면 오류. 규제 버전·면적 시점·계산식 버전을 결과에 남긴다.
- `j5 calc equity <입력.json>`: 가격 기준 정규화(총액 / 보증금 차감 후 + 확인된 차감액 / 잔금·미확인은 P 미확정) 뒤 P − L − D + T + B + V + R + E. 총액 입력에 차감액을 함께 주면 거절(이미 뺀 값에 D 를 다시 빼는 입력 금지). 보증금 공제가 금융기관 순대출 한도에 이미 들어 있으면 D 를 다시 차감하지 않되 반환 의무는 그대로 표시. 가격·다른 항목에 포함된 비용은 0. 기지급 계약금·중도금은 빼지 않고 "현재 시점 추가 잔금 현금" 으로 따로 보인다. 미확인 항목이 있으면 알려진 항목 합계만.
- `j5 calc cash <입력.json>`: 시점별 CF_t 를 합쳐 누적 최저를 찾고 max(0, −최저) + 별도 예비현금. 예비현금이 CF 에 있으면 더하지 않는다(둘 다 주면 거절). 소유자 자기자본 투입(`owner_equity`)은 거절. 시점은 기간 번호 또는 날짜(혼용 금지). 미확인 금액·미확인 예비현금이면 결과 null.
- 종료 코드: 계산 완료 0, 미확정(미확인 입력·오류) 1, 입력 거절 3. 결과 JSON 에 `calculation_version`(1.0.0)·계산식·미확인 목록·주의·경고문을 넣는다.
- 가상 검증(`tests/fixtures/calc/`): 대지 100㎡·F 600%·C 240㎡ → 검토 600·여유 360(배치 검토영역 60 은 무시), 제외 10㎡ 확인 → A 90·검토 540·여유 300. 총액 40억·L 24억·D 1억·기타 2억 → 17억, 순액 39억 + 차감 1억 → P 40억 복원 → 17억, 기준 미확인 → 미출력. 누적 −17·−20·−18억 + 예비 1억 → 21억. 테스트 `tests/test_j5_016a_calc.py` 6건.

## B. 결과 (개발안 비교·후보별 현금표·CSV)

- `kind: plans` 입력: 후보(현상 유지 `keep` / 리모델링 `remodel` / 철거신축 `rebuild` / 공동매입 `joint_purchase`)마다 `equity`·`cash` 입력을 통째로 품고, 선택으로 감정가(`appraisal`), 공사기간·공실(`construction`, 리모델링·철거신축 필수), 공동매입 항목(`joint`: 추가 가격·가격/현금흐름 포함 여부·취득 순서·기간·한쪽만 확보했을 때의 운영안, 공동매입 필수), 건축사 검토(`architect_review`), 전제 목록을 둔다.
- `j5 calc plans <입력.json> [--csv 경로] [--json]`: 후보별 필요자기자본(P−L−D+T+B+V+R+E)·최대 필요자기자본·누적 최저 시점을 한 표로 낸다. 후보를 고르지 않는다. 미확인 입력이 있는 후보는 값이 없고 종료 코드 1. CSV 는 24열(구성 항목·결과·감정가 차이·공사기간·미확인 수·경고), 덮어쓰지 않는다.
- 후보별 점검 경고(결과를 막지 않음): 공사기간 공실(공사 창 안에 `vacancy` 항목이 없음, 창 안의 공실 시점이 공실 개월 수보다 적음, 공사 중 임대수입, 공실 개월 수 미확인, 공사비 항목 없음), 부가세 포함 여부 미확인(가격·거래비·수선비), 비용 중복(`included_in` 이 없는 항목을 가리킴, 예비현금이 매입 E 와 사업기간 예비현금 양쪽에 있음), 승계 보증금 반환 의무가 현금흐름에 없음, 감정가 × LTV 가정(순대출 한도면 보증금 공제를 같이 뺌)이 매입가 가정 대출보다 작을 때의 차이와 감정가 기준 필요자기자본, 공동매입 추가 가격·기간 미확인·가격 P 가 추가 가격보다 작음·단계 매입 흐름 없음, 리모델링·철거신축에 건축사 검토안 없음. 공동매입 추가 가격이 가격·현금흐름에 들어 있지 않다고 표시하면(`included_in_price: false`) 후보를 미확정으로 두고 임의로 더하지 않는다(리뷰 반영).
- 가상 fixture `tests/fixtures/calc/plans_compare.json`: 현상 유지 17억/최대 18억(감정가 36억이면 19.4억), 리모델링 공사 2개월 최대 25억, 철거신축 최대 33억, 공동매입(추가 12억) 22.6억. 테스트 `tests/test_j5_016b_plans.py` 4건.

## C. 결과 (규제 검토·개발안·자금안 기록 종류)

- db_schema 12 `r5_plan_records`: `records.record_type` 에 `regulation_review`·`development_plan`·`financing_plan` 을 허용한다. 표 재작성은 마이그레이션 9 와 같은 절차(외래키 끈 한 트랜잭션 + `foreign_key_check`, ADR-14)이며 공통 함수로 문구를 공유하되 마이그레이션 9 의 허용 목록은 `RECORD_TYPES_V9` 로 고정했다. 재확인(`judgment_rechecks`)·근거·첨부·수입 대장의 외래키가 재작성 뒤에도 살아 있다.
- payload 계약 `schemas/plan_records.schema.json`: 규제 검토(용도지역·적용 용적률·규제 버전·종료일 확인·면적 제약·근거, 미확인은 사유), 개발안(종류·이름·여유면적 계산 입력 `calc far`·공사기간·공동매입 항목·건축사 검토·전제·전제한 규제 검토 기록), 자금안(대응 개발안·시나리오·`calc equity`·`calc cash` 입력·감정가). 계산 입력은 `calc_inputs.schema.json` 의 정의를 상대 `$ref` 로 그대로 쓴다(스키마 registry 도입). 저장 payload 는 입력 + 결과 스냅샷(`far_result` / `equity_result` / `cash_result`) + `calculation_version` 이며 입력 파일에는 결과를 넣을 수 없다.
- `j5 db plan-add <입력.json>`: 저장 시점에 계산기를 돌려 결과와 계산식 버전을 붙인 불변 기록으로 넣는다. 미확인 입력이면 결과 null 과 미확인 목록으로 저장한다(거절하지 않음). 수정은 새 기록 + `supersedes_id`(같은 물건·같은 종류, 이미 수정된 기록은 다시 가리킬 수 없음). 개발안이 전제한 규제 검토, 자금안이 대응하는 개발안은 이 물건의 현재 기록이어야 한다.
- `j5 db plans --asset <id>`: 현재(수정되지 않은) 규제 검토·개발안·자금안과 저장 시점 결과를 나란히 보인다. 후보를 고르지 않는다. 파생본 `records.jsonl` 에 새 종류가 그대로 들어간다.
- 테스트 `tests/test_j5_016c_plan_records.py` 5건: 버전 11 정본(관측·첨부·근거·목표가·재확인)을 열 때 표 재작성과 보존·외래키, 마이그레이션 9 문구 고정, 계산 스냅샷·미확인 null·수정 체인·참조 검증, 입력 검증, 파생본, CLI.

## 데이터 사전에 없어 정한 값

- 결과 값은 면적 소수 3자리, 소진율 소수 6자리로 반올림한 뒤 담고, 금액은 원 단위 정수 그대로다.
- `included_in_price` / `included_in` 이 참인 비용은 0 으로 두고 주의에 적는다. 값이 함께 있어도 더하지 않는다.
- 총액 입력에 `deposit_already_deducted_krw` 가 0 이 아닌 값으로 오면 거절한다(모순 입력). `null` 이나 0 은 허용.
- 현금흐름의 시점은 정수 기간 번호 또는 `YYYY-MM-DD` 며 문자열 정렬로 시점 순서를 정한다. 같은 시점의 여러 항목은 합한다.
- 미확정 결과의 종료 코드 1 은 "실패" 가 아니라 "완성값 아님" 이다. 출력에 알려진 항목 합계를 남긴다.
- 입력 계약: 확인된 금액·면적에는 근거(`basis`)가, 미확인(`null`)에는 사유(`reason`)가 필수다(리뷰 반영). 현금흐름의 날짜 시점은 `YYYY-MM-DD` 만 받는다.
- 감정가 차이는 대출이 매입가 가정 LTV(`collateral_basis: purchase_price_assumption`)로 잡혔을 때만 본다. 감정가 × LTV 가정 < L 이면 차이만큼 자기자본이 더 드는 것으로 표시하고, 감정가가 높아도 대출을 늘리지 않는다(실제 한도는 금융기관 확인).
- 공사기간 공실 점검의 공사 창은 첫 설계·공사(`design`/`construction`) 항목이 있는 시점부터 `period_unit: month` 일 때 `months` 개 시점, 그 밖의 단위는 그 시점 하나다. 임대·공실 항목 모두 그 창 안에서만 본다. 판정이 아니라 확인 요청이다.
- 개발안·자금안의 계산 결과는 저장 시점의 스냅샷이다. 입력이 바뀌면 새 기록으로 다시 계산하며 저장된 결과를 고치지 않는다(기록 불변). `calculation_version` 이 바뀌어도 옛 기록은 옛 버전 표시를 유지한다.
- 규제 검토는 계산기가 판정하지 않는 확인값이다. `end_date_confirmed: false` 는 재확인 필요를 뜻한다(데이터 사전 §8 "종료일 미확인 규제의 재확인 필요").

## 공수

- 예상(J5-016 전체): 릴리스 계획 R5 예산 범위. A 실제 약 1.5시간(리뷰 반영 포함), B 실제 약 1.5시간(리뷰 반영 포함), C 실제 약 1.5시간.

## 미확인 변수·남은 인수조건

- 실제 물건의 법정 산정 대지·제외면적·적용 용적률은 법령·지구단위계획·전문가 검토로 확인해야 하며 계산기는 확인된 값을 받을 뿐이다(ADR E03). 취득세율·거래비용은 세무·법무 확인 전 가정이다.
- 공사기간 공실·부가세·비용 중복·감정가 차이는 경고와 가상 시험으로 다뤘고 실제 물건의 공정·세무·감정은 전문가 확인 전 가정이다.
- 실제 정본에서 마이그레이션 12 실행(백업 뒤 `j5 db status` 로 버전 12·외래키 켜짐·무결성 확인).
- J5-016 의 세 조각으로 릴리스 계획 §8 R5 항목(법정 산정 대지·배치 영역·규제 버전·여유면적·건축사 검토안·공동매입·유지/리모델링/신축 비교·후보별 현금표·CSV, 보증금 총액/순액·반환 의무·부가세·비용 중복·공사기간 공실·감정가 차이 시험)을 다뤘다. 규제 검토의 재확인 알림(`db recheck` 신호 연동)은 필요가 확인되면 별도 조각으로 둔다.
