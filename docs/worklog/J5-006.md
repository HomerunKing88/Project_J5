# J5-006 IndexedDB·임장·최소 캐시

기록일: 2026-09-22.

## 결과

- `web/index.html` + `app/main.js`: 설정(study_id·data_mode·경로 버전 ID), 시드 불러오기(가상 5개·기기 파일), 물건 목록·선택, 관측 입력(상태 3종·시각 또는 날짜만·설명·사진·태그 7종), 저장 목록과 상태(`저장됨`, PC 반영 여부 미확인 문구). 지도 없이 동작한다.
- `app/db.js`: IndexedDB `j5` v1. 관측(이벤트 객체 + 정규화 행 바이트 + 해시)과 사진을 한 트랜잭션으로 저장. 저장 실패는 화면에 실패로 표시. 시드 교체는 관측을 건드리지 않는다. 자동 삭제 없음.
- `app/event.js`: 이벤트 작성·정규화·검증. 정규화 바이트는 `make_packages.py`의 `line_bytes`와 바이트 단위로 같다(테스트로 fixture 전 행 대조). 검증 규칙은 JSON Schema와 같다.
- `app/sha256.js`: 순수 JS sha256(비보안 컨텍스트용). node:crypto 와 길이 0~300·블록 경계·70KB 무작위 입력으로 대조.
- `sw.js`: 최소 앱 캐시. 앱 실행 파일 목록만 캐시. 테스트가 목록의 파일 존재와 데이터 미포함, 모든 앱 모듈 포함을 검사.
- e2e(`tests/web/app.e2e.test.mjs`): 헤드리스 Chromium(CDP)으로 설정→시드→사진 포함 관측 저장→HEIC 거절→재접속 후 목록 유지→오프라인 재접속(서비스 워커)→IndexedDB 내용을 패키지 폴더로 꺼내 `python -m j5 inspect --seed --study-id`가 ok. 브라우저 콘솔 오류 없음.

## 데이터 사전에 없어 정한 값

- 행 바이트를 **저장 시점**에 고정한다(사전은 "첫 내보내기에서 고정"). 저장 후 수정이 없으므로 더 이른 고정이며, 내보내기(J5-007)는 이 바이트를 그대로 쓴다.
- 기기 기록 상태: `saved` → `exported`(J5-007). `exported_in[]`에 package_id를 남긴다.
- 사진 저장 키는 내용 sha256. 같은 사진을 여러 관측이 참조할 수 있다.
- 시드 파일은 기기에서 읽어 IndexedDB `assets`에 두며 `source`(bundled_synthetic / file:이름)를 기록한다.

## 공수

- 예상 8~12시간. 실제(세션 기준) 약 1.5시간.

## 미확인 변수·남은 인수조건

- 실제 iPhone Safari 시험(2026-09-23, iOS 18.7, J5-004 기록): IndexedDB Blob 저장·파일 선택·재접속 후 기록 유지 확인. 사진은 JPEG 로 들어온다.
- 저장공간 부족 시험: e2e 에서 재현하지 못했다. 코드 경로는 예외를 잡아 실패로 표시한다. 실기기에서 확인.
- 서비스 워커 오프라인 실행은 HTTPS(또는 localhost) 에서만 된다. LAN http 시험에서는 오프라인 재접속이 안 되는 것이 정상.
