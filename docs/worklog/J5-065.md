# J5-065 수집 종류 확장 (단독·다가구·토지 매매)

기록일: 2026-10-13. 사용자 결정: "수집 종류 늘리기도 이어서 진행" (J5-064 미확인 변수 "같은 종류만 비교할지" 와 후속 항목). 설계 결정은 ADR-26.

## 결과

- `j5/collect/rt.py`
  - 종류 등록부 `KINDS`(`RtKind`: 이름·화면 이름·서비스 이름·원본 폴더, 제공자와 기본 주소는 서비스 이름에서 만든다): `nrg` 상업·업무용 매매(기본, `raw/rt_nrg`), `sh` 단독·다가구 매매(`RTMSDataSvcSHTrade`, `raw/rt_sh`), `land` 토지 매매(`RTMSDataSvcLandTrade`, `raw/rt_land`). `rt_kind`, `kind_of_provider`.
  - `collect_months(..., kind=)`: 종류의 제공자·원본 폴더로 쌓는다. `endpoint` 를 주지 않으면 종류의 기본 주소. `list_run_ids`·`months_done_on_disk`·`list_runs`·`load_month_items`·`report_from_raw` 도 종류를 받는다(기본 상업·업무용). 요약(report)에 `kind`. 기존 상수 `PROVIDER`·`RAW_DIR`·`DEFAULT_ENDPOINT` 는 상업·업무용 그대로.
- `j5/db/transactions.py`
  - 종류별 식별 필드 `IDENTITY_FIELDS_BY_KIND`. 상업·업무용 식별 해시는 이전과 같다(이미 정본에 있는 거래가 새 거래로 갈리지 않는다). 다른 종류는 해시에 제공자를 넣는다(관측 조인이 제공자 없이 해시로 맞추는 곳이 있다).
  - `normalize(content, kind)`: 단독·다가구 연면적 `totalFloorAr` → `building_area_m2`, 대지 `plottageAr`, 주택유형 `houseType` → `building_use_raw`(단독·다가구면 건물 구분 general). 토지 거래면적 `dealArea` → `plottage_area_m2`, 용도지역 `landUse`, 연면적·건축년도는 null 과 사유 not_applicable, 범위 land_only(지분이면 partial_share). 상업·업무용은 그대로.
  - `load_run(..., kind)`: 그 종류 폴더의 실행 기록만 읽고, 기록의 제공자가 폴더 종류와 다르면 `run_invalid` 로 거절(정본 무변화). 오래된 실행을 나중에 반영할 때 "뒤의 완전한 실행" 은 같은 제공자만 본다(다른 종류의 빈 달로 사라짐을 적지 않는다).
  - `unloaded_run_ids`·`coverage`(`rt-coverage`)는 종류별. `coverage_by_year` 는 종류를 주지 않으면 이전처럼 가리지 않는다(PC `parcels-years` 와 폰이 같은 값). `coverage_rows` 줄마다 그해 완전히 받은 종류 `kinds`.
- `j5/db/ops.py`: 반영 대기 실행을 종류 폴더마다 찾는다(상업·업무용은 이전 키 `rt`, 다른 종류는 `rt_sh`·`rt_land`, 안내 명령에 `--kind`). 최근 수집 줄·경고를 시군구·종류마다 낸다.
- `j5/db/zones.py`·`j5/db/projection.py`: 파생본 거래마다 `deal_kind`, 토지 거래의 `land_category`(최신 응답 행의 `jimok` 그대로). 게시 전 확인이 모르는 `deal_kind` 와 잘못된 `coverage.kinds`(목록 아님·모르는 종류·중복)를 거절한다. 형식 버전 1.0.0 그대로, 이 칸이 없는 이전 파일도 받는다.
- `j5/cli.py`: `collect rt-sample/rt-fetch/rt-recheck/rt-report`, `db rt-load/rt-coverage` 에 `--kind nrg|sh|land`(기본 nrg). `--endpoint` 기본값은 종류의 주소. 다음 명령 안내에 `--kind` 를 붙인다.
- 폰 `web/app/view.js`
  - `DEAL_KIND_NAMES`. 거래 파일 검사에 `deal_kind`·`land_category`·`coverage.kinds`.
  - `dealKind`: 토지 매매는 토지, 단독·다가구 매매는 주택유형(단독·다가구) 또는 주택. `dealValueText`: 토지 거래의 연면적 단가는 "토지 거래 (건물 없음)", 면적이 없으면 "토지 면적 미확인". `dealDetailText`: 토지 거래는 "토지 n㎡ · 지목 대 · 용도지역".
  - 연도별 표: 그해 일부 종류만 받았으면 거래 수 칸에 "상업·업무만" 같은 메모, 줄 글에 "(수집 n/12개월, 상업·업무만)". 종류 정보가 없는 이전 파일은 그대로.
- 연습용 거래(`web/data/transactions.synthetic.json`): 모든 거래에 `deal_kind`, 수집 개월에 `kinds`, 토지 매매 1건(4-2, 2020)·다가구 매매 1건(3, 2020) 추가(11건).
- 앱 0.2.30 (`APP_VERSION`, `sw.js` 캐시, e2e 5곳).
- 시험
  - `tests/test_j5_065_rt_kinds.py`(9개): 등록부와 기존 상수, 종류마다 따로 쌓이는 원본·완료 월·요약, 종류별 정규화와 사유, 상업·업무용 식별 해시 유지(이전 계산과 같은 값)·종류 사이 해시 분리, 종류 섞인 반영(상업·업무용 빈 달이 토지 거래를 사라짐으로 적지 않음, 오래된 토지 실행 뒤 완전한 토지 실행이 없으면 사라짐 아님), 다른 폴더에 둔 실행 기록 거절, 반영 대기·최근 수집을 종류마다, 파생본 칸과 게시 전 확인(이전 형식 통과 포함), CLI(`--kind land` 의 기본 주소, 실제 주소로 받은 응답은 가상 정본에 넣지 않음, 반영·범위 현황, 모르는 종류 거절). 고치기 전 코드에서 실패한다(종류 등록부 없음).

## 데이터 사전에 없어 정한 값

- 종류 이름 `nrg`·`sh`·`land`, 원본 폴더 `raw/rt_sh`·`raw/rt_land`.
- 단독·다가구 주택유형은 `building_use_raw` 에 둔다(정본 스키마를 바꾸지 않는다). 토지 지목은 정본 열이 없어 원본 행에만 있고 파생본에서 최신 응답 행으로 읽는다.
- 토지 거래의 범위 기본값 land_only. 단독·다가구는 상업·업무용 일반건축물처럼 unclear(검토에서 정한다).
- 폰 "○○만" 메모는 그해 완전히 받은 종류가 셋보다 적을 때만.

## 미확인 변수

- 단독·다가구·토지 API 의 주소와 응답 필드 이름(`totalFloorAr`·`houseType`·`dealArea`·`jimok`)은 공식 명세를 이 컨테이너에서 열 수 없어(공공데이터포털 접속 차단) 확인하지 못한 가정이다. 이름이 다르면 그 값은 null 과 not_provided 로 들어간다. 첫 실제 응답의 `rt-sample` 요약(report)에서 필드 이름을 확인하고, 다르면 식별 필드·정규화를 고친 뒤 정본에 반영한다(반영 전이면 원본만 있어 다시 받을 필요가 없다).
- 단독·다가구 응답에 지분 구분(`shareDealingType`)이 있는지 모른다. 없으면 지분 거래도 일반 거래로 보인다.
- 토지 지번의 마스킹 모양이 상업·업무용과 같은지(번지대 대조 규칙)는 실제 응답으로 확인한다.
- 주변 사례가 건물 거래와 토지 거래를 한 중간값에 섞는 영향은 실자료로 본다(ADR-26 경계).
- 가상 응답 시험이다. 실제 공공데이터포털 응답·iPhone 실기기 확인이 아니다.

## 남은 인수조건·후속 작업

- 사용자: 공공데이터포털에서 "국토교통부_단독/다가구 매매 실거래가 자료" 와 "국토교통부_토지 매매 실거래가 자료" 활용신청(같은 인증키를 쓴다). 승인 뒤 PC 에서 `python -m j5 collect rt-sample --kind sh --lawd-cd 11110 --months 2026-08` 과 `--kind land` 를 한 번씩 돌려 요약을 공유한다(원본 행·인증키는 보내지 않는다). API 상세 페이지의 주소가 기본값과 다르면 `--endpoint` 로 준다.
- 필드 확인 뒤: `collect rt-fetch --kind sh|land` → `db rt-load --kind sh|land` → `project-copy` 로 폰에서 토지·단독·다가구 거래를 본다.
