# J5-031 VWorld 묶음 한 번에 넣기

기록일: 2026-09-27. J5-025 이후 작업 기록마다 사용자 측 남은 항목으로 "구역별 `parcels convert` → `db parcels-load` 3회" 가 남아 있었다. 구역마다 `parcels inspect` 로 범위를 읽고, 그 값을 `convert --bbox` 에 옮겨 적고, 반영하는 세 단계라 옮겨 적기 실수와 백업 누락의 여지가 있었다. 이 절차를 한 명령으로 묶었다. 실제 자료는 작업 환경의 임시 폴더에서만 다뤘고 저장소에 넣지 않았다.

## 결과

- `j5/db/ingest.py`(새): `ingest_vworld(db, home, sources, geometry_version, source_name, license, backup)`.
  - 변환: 입력마다 VWorld 묶음인지 확인하고(아니면 거절), 연속지적도의 WGS84 범위 전체(좌표 정밀도 한 칸 여유)를 범위로 번들을 만든다. 속성·열 이름 되돌리기·UTF-8 은 `parcels convert` 와 같다. 번들은 실데이터 홈 `parcels/bundles/<입력 이름>-<도형 기준일>-<입력 sha256 앞 8자>.j5parcels.json` 에 쓰고, 같은 입력·같은 기준일이면 있는 번들을 다시 쓴다. 하나라도 실패하면 아무것도 반영하지 않는다.
  - 백업: 반영 전에 `backup` 과 같은 일관된 사본(기본). 실패하면 반영하지 않는다. `--no-backup` 은 따로 백업했을 때만.
  - 반영: 번들마다 `load_bundle` 트랜잭션. 중간 실패면 앞 번들은 남고 결과에 몇 개가 들어갔는지 적는다. 재실행은 변화 없음.
- CLI(`j5/cli.py`): `db parcels-ingest <SRC>… --geometry-version [--source-name] [--license] [--data-home] [--no-backup] [--json]`. 성공·변화 없음 0, 실패 1, 실데이터 홈 없음 3.
- 테스트: `tests/test_j5_031_ingest.py`(6건, 리뷰 반영 뒤 8건).
- 문서: 릴리스 계획 §10 J5-031, `j5/README.md`·`tests/README.md`, 색인(J5-030 PR #76).

## 실측 (사용자 제공 VWorld 3구역, 작업 환경 임시 폴더, 가상 study 의 private_real 정본)

- 한 번에 넣기: 19.7초(변환·백업·반영 포함). 구역 1 724필지 신규 724 · 구역 2 552필지 신규 542·변화 없음 10 · 구역 3 1,448필지 신규 1,441·변화 없음 7. 정본 2,707필지·속성 2,707행·스냅샷 8,121행, 무결성 통과. J5-025 의 수동 절차 결과(2,707필지, 경계 겹침 17필지)와 같다.
- 재실행: 9.2초, 세 번들 모두 재사용·변화 없음. 번들 합계 5.4MB.
- 입력에 관측 패키지 ZIP 이 섞였을 때: 그 입력을 "VWorld 토지 자료 묶음이 아니다" 로 거절하고 나머지 3구역도 반영하지 않았다(백업도 만들지 않음).
- 실측용 임시 정본·번들은 확인 뒤 지웠다. 저장소에는 수치만 기록한다.

## 데이터 사전에 없어 정한 값

- 번들 파일 이름 규칙(입력 이름·도형 기준일·입력 sha256 앞 8자)과 위치 `parcels/bundles/`.
- 입력이 여럿이고 `--source-name` 을 주면 자료명 뒤에 입력 파일 이름을 붙인다(구역 구분). 생략하면 `VWorld 토지 자료 <파일 이름>`.
- 반영 전 백업을 기본으로 둔다.

## 리뷰 반영 (PR #77 머지 뒤 Codex 2건, 후속 PR)

- P1 마이그레이션 전 백업: `db` 명령은 정본을 열 때 대기 중인 마이그레이션을 바로 적용하므로, 도구보다 오래된 정본에서는 "반영 전 백업" 보다 마이그레이션이 먼저 일어났다. `parcels-ingest` 는 이제 CLI 가 정본을 미리 열지 않고, `ingest_vworld(정본 경로, …)` 가 변환·백업 동안 읽기 전용(`Db.open_readonly`)으로 연다. 백업은 그 읽기 전용 연결에서 만들어 마이그레이션 전 정본을 담고, 그 뒤 쓰기 모드로 열 때 마이그레이션이 적용되며 결과에 `migrated_from → migrated_to` 로 적힌다. 변환·백업이 실패하면 정본은 마이그레이션을 포함해 바뀌지 않는다.
- P2 번들 재사용과 출처 표기: 번들 키를 입력 바이트·자료명·이용조건·자료 종류로 만들고, 재사용할 때도 번들의 자료명·이용조건·기준일·자료 종류를 요청과 대조한다. 첫 실행이 백업 실패로 멈춘 뒤 `--license` 를 고쳐 다시 실행하면 새 번들로 반영된다.
- 시험 2건 추가(버전 16 정본에서 변환 실패·백업 실패면 스키마 그대로, 성공하면 백업 manifest 의 db_schema 16·반영 뒤 17 / 이용조건을 고친 재실행이 새 번들로 반영, 바뀐 번들은 쓰지 않음).


약 0.9시간 (설계 0.15, 구현 0.3, 시험 0.2, 실측 0.1, 문서 0.15).

## 미확인 변수
