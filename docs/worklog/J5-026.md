# J5-026 필지 속성 이력: 기준일별 스냅샷과 연도별 변화

기록일: 2026-09-27. J5-025 로 필지 속성(현재 값)이 정본에 들어갔고, 사용자의 목표("필지 번호가 있고 해당 필지에 대한 정보와 거래정보를 연도별로 쌓아나가는 것")에 맞춰 속성의 시간 축을 더했다. ADR-19 의 경계 절에 기록했다.

## 결과

- 정본(`j5/db/schema.py` 마이그레이션 16 `parcel_attribute_snapshots`): 필지·자료 종류(토지특성/토지이용계획/토지소유)·기준일마다 그때 읽은 값을 JSON 그대로, 출처 항목·출처 문서와 함께 둔다. `UNIQUE (parcel_id, kind, as_of)`. 마이그레이션이 기존 `parcel_attributes` 행을 출처 목록에 든 자료 종류만 첫 스냅샷으로 옮긴다(SQL 의 json_object·json_each, UUID 는 randomblob).
- `j5/db/parcels.py`: `parcels-load` 가 번들에 든 자료 종류마다 스냅샷을 계획한다(없으면 신규, 같은 값이면 그대로, 같은 기준일에 다른 값이면 교체). 값이 같아도 새 기준일이면 신규 스냅샷이며 정본 변경(dataset_version 증가)이다. `attribute_history(db, pnu)`·`history_text` 와 변화 계산 `_snapshot_changes`(종류마다 처음 확인은 값 있는 필드만, 이후는 바뀐 필드의 from/to). 파생본 `parcels.geojson` 필지마다 `attrs_history`(오래된 것부터, 상한 200건은 최근 것만).
- CLI: `j5 db parcels-history <PNU> [--json]`.
- 스키마: `$defs/attrs_change`, `properties.attrs_history`.
- 폰: `parcels.js` 에 `attrs_history` 검증·값 표기·변화 한 줄 글(코드·잘림·기준 연월은 이력 글에서 뺀다), `view.js` `attrHistoryItems` 가 필지 이력에 "토지 자료" 항목(토지특성/토지이용계획/토지소유 배지 + 처음 확인/변경 배지)을 기준일의 연도에 넣는다. `main.js` 배지, `styles.css` 색, 지도 안내 문구.
- fixture: `tests/fixtures/make_view.py` 가 가상 VWorld 번들(기준일 2026-09-05) 뒤에 기준일 2026-09-25 의 변형(필지 1 공시지가 13,000,000·소유 법인)을 넣어 파생본에 이력이 든다.
- 테스트: `tests/test_j5_026_attr_history.py`(7건), `parcels.test.mjs`·`view.test.mjs` 각 1건, `app.e2e.test.mjs` 필지 이력 절(토지 자료 항목 5건·현재 속성·연도 묶음). 마지막 마이그레이션 표를 참조하는 시험 3곳 갱신.
- 문서: ADR-19 경계, 릴리스 계획 J5-026, 데이터 사전 §2, `j5/README.md`·`web/README.md`·`schemas/README.md`·`tests/README.md`, 색인(J5-025 PR #71).

## 데이터 사전에 없어 정한 값

- 스냅샷 단위는 (필지, 자료 종류, 기준일) 한 행. 같은 기준일 재다운로드는 값 교체(정본 정정 기록은 남기지 않는다: 자료 파일 자체가 근거이며 출처 문서가 바뀐다).
- "처음 확인" 항목은 값이 있는 필드만 싣는다(모두 null 인 소유 행은 항목이 없다). 폰 이력 글에서는 코드 필드·잘림 표시·공시 기준 연월을 뺀다(PC `parcels-history` 에는 모두 있다).
- 파생본 이력 상한 200건(필지마다). 넘으면 최근 것만.

## 리뷰 반영 (PR #72, Codex 3건)

- P2 이력 필드 허용목록: 폰 검증이 `attrs_history` 의 바뀐 필드를 자료 종류별 허용 필드(`ATTR_GROUP_KEYS`)로 제한한다(소유자 이름 같은 필드는 이력으로도 거절). JSON 스키마도 `propertyNames` 와 종류별 if/then 으로 같은 제한을 둔다.
- P2 파생본 출처 누락: 이력 블록을 끼워 넣으며 출처 수집이 속성 행 반복문 밖으로 밀려 마지막 행의 출처만 모였다. 반복문 안으로 되돌리고 필지 하나만 든 다른 파일을 넣는 시험으로 출처 4개를 확인한다.
- P2 0 값: 처음 확인 항목에서 `0 == False` 때문에 0 이 빠졌다. `None`·`False`·빈 목록만 제외하고 0 은 값으로 싣는다(시험 추가).

## 미확인 변수

- 실제 정본의 마이그레이션 16 백필은 J5-025 의 실제 반영이 아직 없어 가상 정본으로만 확인했다. 백업 뒤 `db status` 로 적용한다.
- 연도별 이력은 사용자가 자료를 새 기준일로 다시 내려받아 `parcels convert` → `parcels-load` 할 때만 쌓인다(VWorld 공시지가 갱신 시점은 배포처 확인 항목).
- 파생본 크기: 필지 2,700개 × 종류 3 의 처음 확인 항목이 더해져 `parcels.geojson` 이 커진다(실기기 읽기 시간 확인 항목). 커지면 처음 확인 항목을 파생본에서 빼는 선택지를 둔다.

## 남은 인수조건·후속 작업

- 사용자: J5-025 절차로 실제 자료를 넣은 뒤 `db parcels-history <PNU>` 와 폰 필지 이력을 확인한다. 이듬해 자료를 새 기준일로 넣으면 공시지가 변화가 이력에 든다.
- 후속 후보: 지역지구 코드→이름 표, 건축물대장 연결, 공시지가 추이 표시(필지 패널의 연도별 값).
- 자동 테스트 통과는 실제 자료·기기 검증이 아니다.
