# J5-020 모바일 현장 앱 UX 재구성

기록일: 2026-09-26. J5-019(화면 정리) 직후 사용자 요청: 기능 코드와 테스트는 있지만 실제로 쓸 수 있는 UI/UX 가 없으므로, 현장 사용자의 작업 흐름을 기준으로 정보구조와 화면을 다시 짜고 브라우저에서 검증한다. J5-001~018 의 완료 상태는 바꾸지 않고 새 작업으로 기록한다. 릴리스 계획 §10 에 J5-020 행을 더했다.

## 목표

앱을 열면 준비된 대상 목록을 바로 보고, 목록이나 지도에서 대상을 골라 상태·사진·메모를 3분 안에 저장하고, 저장 확인 뒤 다음 대상으로 넘어가며, 임장 뒤 내보내기 단계를 이해하고, 파일 저장 확인 전에는 내보냄으로 표시되지 않고, PC 반영 여부는 미확인으로 남는 모바일 현장 앱.

## 변경 전 문제 (2026-09-26 첫 실사용 화면 기준)

1. 설정·파일·필지·지도·관측·내보내기·기기 이전·기록이 한 페이지에 나열돼 첫 화면이 개발용 페이지였다.
2. 오늘 할 일과 상태(대상 수·저장 수·미내보냄 수·최근 저장)가 요약되지 않았다.
3. 관측 입력이 페이지 중간 섹션이고 상태 선택이 작은 select 라 현장에서 다루기 어려웠고, 저장 뒤 다음 행동이 없었다.
4. 내보내기가 "묶음 준비 → 파일 저장 → 파일 저장 확인" 계약을 따르지만 어느 단계인지 보이지 않았다.
5. study_id·origin·해시·CLI 명령 같은 내부 용어가 기본 화면에 있었다.

## 변경 내용

- `web/index.html`: 화면 5개(`section.view[data-view]`: 오늘·지도·기록·내보내기·설정)와 하단 내비게이션(`nav.bottom-nav`, 데스크톱은 헤더 아래 고정 탭). 상단 바에 자료 종류 배지(`#mode-badge`)와 오프라인 배너. 오늘: 통계 3개·최근 저장·빈 상태(연습용 자료/설정으로)·관측 시작/계속하기·대상 카드 목록(`#asset-list`). 지도: SVG 지도·선택 카드(`#map-selected`, 기록 시작)·필지 패널·접힌 범례. 기록: 저장됨/내보냄 배지 설명·카드 목록. 내보내기: 4단계 표시(`#export-steps`)·요약·버튼 3개·안내. 설정: 작업 공간(내부 이름은 힌트에만)·자료 관리(물건 목록·필지 경계, 마지막 가져온 시각)·옮길 때(접힘)·고급 정보(상태 줄·기기 시험 페이지)·도움말. 관측은 전체 화면 작업 패널 `#sec-observe`(role=dialog, aria-modal): 대상 이름·위치 → 라디오 타일 3개(`input[name=change-status]`) → 사진 추가(무엇을 찍었는지 태그, 촬영 정보는 접힘) → 메모 → 관측 시각(접힘) → 저장/취소, 완료 화면(`#observe-done`: 다음 대상 기록·목록으로·기록 보기). 기존 요소 ID 는 유지했고 `#change-status` select 만 라디오로 바꿨다.
- `web/styles.css`: 디자인 시스템 토큰(배경·표면·글·보조·주요·선택·성공·경고·오류·테두리·간격·둥근 모서리·그림자·터치 44px·safe-area·내비 높이), 라이트·다크 재정의. 컴포넌트: 앱 헤더·모드 배지·배너(오프라인·오류)·통계·빈 상태·버튼(기본·주요·보조·위험·아이콘·큰)·파일 버튼·폼 필드·큰 상태 선택(:has 로 선택 표시)·배지(상태·모드·기록 상태)·카드 목록·사진 항목·disclosure·지도·선택 카드·단계 표시·작업 패널(sheet, 고정 머리·고정 저장 줄)·완료 화면·하단 내비게이션(배지)·데스크톱(900px 이상)·작은 폰(360px 미만). `[hidden]` 고정, focus-visible, prefers-reduced-motion.
- `web/app/ui.js`(새 파일, 순수 함수 + 전환기): `createNavigator`(hidden 토글·`#home` 등 해시·aria-current·화면 제목으로 포커스·hashchange), `viewFromHash`, `shortWhen`, `assetSummary`(물건별 마지막 상태·시각·기록·사진·미내보냄), `nextAsset`(기록 없는 다음 대상), `exportStep`.
- `web/app/main.js`: 화면 전환 연결(지도 화면을 열 때 `resize`·`fit`), 오늘 화면 렌더(`renderHome`: 통계·최근 저장·빈 상태·CTA·내비 배지), 대상 카드(요약 포함), 지도 점 탭 → 선택 카드(바로 열지 않음), 관측 패널 열기/닫기(포커스 이동·Esc·되돌림), 저장 중 버튼 문구, 상태 라디오, 같은 사진 중복 선택 오류, 완료 화면·다음 대상, 내보내기 단계 렌더와 화면 진입 시 요약 계산, 오프라인 배너, 자료 종류 배지, 물건 목록 상태(수·마지막 가져온 시각), 필지 안내에 가져온 시각과 "정본 버전 모름(구본 여부 알 수 없음)". 이벤트 생성·검증·저장·사진 해시·ZIP·서비스 워커 등록 로직은 그대로다.
- `web/sw.js`: 캐시 목록에 `app/ui.js`, 캐시 이름 `v0.2.0`(앱 버전 0.2.0).
- 테스트: `tests/web/cdp.mjs`(헬퍼 분리), `app.e2e.test.mjs`(화면 전환·지도 선택 카드·상태 타일·완료 화면에 맞춤, 필지 안내 정규식), 새 `ux.e2e.test.mjs`(아래), 새 `ui.test.mjs`(5건).
- 문서: 릴리스 계획 §10 J5-020 행, `web/README.md`(화면 구성·ui.js·테스트 명령), `tests/README.md`, 색인.

## 유지한 데이터 계약

- 이벤트 객체·정규화 바이트·해시(`event.js`), IndexedDB 스토어와 저장 트랜잭션(`db.js`), 사진 형식·해시 검사(`sniff.js`·`hash.js`), ZIP 작성·묶음 계획·manifest(`zip.js`·`export.js`), 지도 투영·필지 처리(`map.js`·`parcels.js`), 서비스 워커 캐시 정책(앱 파일만), CSP(`default-src 'self'`, 인라인 스크립트·style 없음, 외부 URL 없음).
- 내보내기 3단계 확인: 파일 저장 확인 전에는 `saved` 그대로, 확인 뒤 `exported`. 내보냄은 PC 반영·백업이 아니다(화면 문구·완료 화면·기록 화면 설명에 명시).
- 기존 e2e 가 저장한 이벤트를 `python -m j5 inspect` 로 검사해 ok 를 확인한다(바이트·해시 불변).

- `ux.e2e.test.mjs` 가 확인하는 것: 처음 실행 빈 상태(오늘 화면, 안내, 내부 용어 없음, 가로 스크롤 없음) → 연습용 자료 → 대상 카드(이름·위치 요약·기록 없음, 좌표 숫자 없음, 통계, 터치 대상 44px) → 관측 시작(제목 포커스, dialog) → 필수값 누락 오류 → 같은 사진 중복 오류 → 저장 실패(IndexedDB add 를 던지게 흉내: '저장 실패', 기록 0) → 저장 성공(완료 화면 포커스, 통계·배지, 다음 대상 제안) → 다음 대상·Esc 닫기·카드 요약 → 내보내기 4단계(1→3→4→1, 저장 확인 전 미내보냄 유지, 확인 뒤 0) → 재방문 유지·해시 이동 → 오프라인 배너 → 지도 실패 시 목록(SVG 생성 스텁) → 모바일 내비게이션(하단 고정, 콘텐츠 겹침 없음, 화면마다 가로 스크롤 없음, 제목 포커스) → 접근성 속성(레이블 없는 입력 0, aria-label 없는 아이콘 버튼 0, 상태 메시지 live 영역, 제목 단계 건너뜀 없음) → 콘솔 오류 0.

- iPhone Safari 실기기: 하단 내비게이션의 safe-area, 작업 패널의 고정 머리·저장 줄과 키보드, 사진 추가(카메라·사진첩) 흐름, `:has()` 선택 표시(iOS 15.4 이상), 다크 모드, 확대 200%.

- 저장 실패 표시는 IndexedDB 예외를 흉내 낸 시험이며 실제 용량 부족 상황은 실기기 항목이다.

## 남은 인수조건·후속 작업

- 사용자가 실기기에서 써 본 뒤 문구·순서 의견 반영.
- 후속 후보(이번 범위 밖): 오늘 화면의 정렬·필터(기록 없는 대상 먼저), 사진 미리보기 썸네일, 기록 화면의 물건별 묶기·검색, 내보내기 이력의 파일 재저장, 관측 시각을 사진 촬영 시각으로 제안, 지도의 현재 위치 표시(위치 권한은 사용자 승인 사항). 외부 타일·동기화·로그인·정본 수정·프레임워크 전환은 하지 않는다.
- 자동 테스트 통과는 실제 임장 검증이 아니다.
