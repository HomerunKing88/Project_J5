# J5-054 현장 앱 화면 개편

기록일: 2026-10-02. 사용자 의견: "디자인부터 글씨, 써 있는 내용까지 실제로 사람이 사용할 수 있는 서비스로 보이지 않는다. UI/UX 고민이 부족하다." 사용자가 고른 방향은 "지적 야장"(지적도의 적색 필지선과 현장 야장의 괘선 줄), 범위는 "구조까지 재구성"이다. 기록 형식·내보내기 파일·저장소 계약은 바꾸지 않는다.

## 결과

- 화면 구조 (J5-020 의 화면 5개 → 3개)
  - **현장**: 화면을 채우는 지도 + 아래 시트. 시트 접힘에는 대상 수·기록 수·보낼 기록 수(형광펜)·기록 시작, 펼침에는 시트 위 카드 하나(고른 대상 / 필지 / 처음이면 시작하기)와 대상 줄 목록. 줄을 누르면 지도에서 고르고, 오른쪽 "기록" 은 바로 기록하기를 연다. 대상 카드와 필지 카드는 동시에 열지 않는다. 대상 카드가 열리면 시트 머리의 "기록 시작" 은 숨겨 기록하기 버튼이 하나만 보인다.
  - **기록**: 위에 PC 로 보내기(지금 단계의 버튼만), 아래 이 폰의 기록(최근 것부터). 기록 탭 배지는 안 보낸 기록 수다. 예전 "오늘"·"내보내기" 화면의 내용은 이 두 화면에 들어갔다.
  - **설정**: 자료 가져오기·작업 공간·배경 지도, 나머지는 접힘.
  - 예전 해시 `#home` 은 현장, `#export` 는 기록으로 연다 (`ui.js` `VIEW_ALIASES`). 홈 화면에 저장한 북마크가 깨지지 않는다.
  - 처음 실행: 시트를 펼쳐 시작하기(PC 자료 파일 가져오기, 연습용 자료로 둘러보기)를 보인다. 연습용 자료는 대상·필지·건물 윤곽을 함께 넣고, 넣은 뒤 시트를 접어 지도를 보인다. PC 자료 파일도 시작하기에서 바로 가져올 수 있다.
- 지도 (`map.js`)
  - `setInset({top, bottom, …})`: 지도를 덮는 시트·찾기 칸의 두께. 전체 보기·필지 맞추기·확대 중심·축척 막대·출처 글이 덮이지 않은 영역 기준이다. 덮개는 `ResizeObserver` 와 목록·필지·배경을 다시 그리기 직전에 다시 잰다.
  - 배경 타일은 덮이지 않은 영역(여유 1장)만 요청한다. 시트에 가려진 곳의 타일을 받지 않는다.
  - `reveal(assetId)`: 줄이나 점으로 고른 대상이 펼친 시트에 가려졌으면 보이는 곳 가운데로 옮긴다(축척 유지).
  - 보이는 영역이 낮을 때 전체 보기 여백을 줄인다(40 px 상한, 짧은 변의 12%).
- 디자인 (`styles.css` 다시 씀, 외부 글꼴·URL·인라인 스타일 없음)
  - 토큰: 종이 #F5F7F8, 시트 #FFF, 먹 #1B1F24, 연필 #5E6670, 괘선 #D5DBE0, 청색 잉크 #2340A8(주 행동·선택), 지적 적색 #C8372D(지도의 필지선·지번에만), 형광펜 #FFE14D(아직 PC 로 안 보낸 기록), 경고 #8A4B00. 어두운 모드 토큰 따로.
  - 글: 기기 기본 한글 고딕, 굵기 둘, 크기 13·15·17·20·24·30, 숫자 tabular-nums. 필지 카드의 지번을 가장 크게(30px) 둔다.
  - 목록은 둥근 카드 대신 괘선 줄. 터치 대상 44px 이상, 포커스 테두리, `prefers-reduced-motion` 에서 시트 움직임 없음.
- 화면 글
  - 사용자 말로: 물건 → 대상, 이 기기 → 이 폰, 내보내기 → PC 로 보내기, 정본 → PC(설정의 자료 상태에는 정본 버전을 함께 적는다).
  - 상태 이름: 변화 확인·변화 없음 → 달라짐·그대로 (확인 어려움은 그대로). 저장 값 `change_observed`·`no_change`·`hard_to_confirm` 과 이벤트 바이트는 바뀌지 않는다. 필수 메시지 "달라짐을 고르면 사진이나 메모가 필요합니다".
  - 기록 종류 이름: 관측 → 현장 기록.
  - 존댓말 평서문, 오류는 무엇을 고치면 되는지 적는다 (예: "아직 저장하지 않았습니다. 달라짐·그대로·확인 어려움 가운데 하나를 고릅니다.").
  - 보내기 성공 뒤 "보냈습니다. 이제 파일을 PC 로 옮겨 반영합니다. 반영과 백업은 PC 에서 확인합니다." 보내기 성공을 PC 반영·백업으로 표시하지 않는다.
  - `migrate.js`(옮길 때 안내)·`parcels.js` 조건 찾기 결과 줄(대상 n곳)도 같은 말로.
- 앱 0.2.21 (`APP_VERSION`, `sw.js` 캐시, e2e 3곳). `sw.js` 앱 파일 목록은 그대로(새 파일 없음).
- 시험
  - `tests/web/ux.e2e.test.mjs`: 첫 실행 시트 펼침·시작하기, 연습용 자료 뒤 시트 접힘·필지 6개, 위치점이 모두 접힌 시트 위에 있음, 줄 고르기 → 대상 카드·기록 시작 숨김·포커스, 카드 닫기 → 손잡이로 포커스, 기록 탭 배지 = 안 보낸 기록 수, 보내기 단계별 버튼, 지도 실패 시 시트 펼침, 예전 해시 `#export`·`#home`, 자료가 있으면 시트 접힘으로 시작.
  - `tests/web/app.e2e.test.mjs`: 휴대폰 크기(390×844, 2배)로 돈다. 새 글·구조에 맞춤. 배경 타일 캐시 확인은 "이미 받은 타일을 다시 요청하지 않는다" 로 바꿨다(아래 미확인 변수).
  - 단위: `ui.test.mjs`(화면 3개·기본 화면·예전 해시), `event.test.mjs`·`view.test.mjs`(상태 이름), `migrate.test.mjs`, `parcels.test.mjs`(결과 줄).
  - 새 시험(`ui.test.mjs` 의 화면 목록·별칭, `ux.e2e`)은 고치기 전 코드에서 실패함을 확인했다.
  - 화면은 헤드리스 Chromium 으로 390×844(밝은·어두운)·1280×800 을 찍어 확인했다. 컨테이너에는 WenQuanYi 글꼴만 있어 iPhone(Apple SD Gothic Neo)과 글자 폭이 다르다.

- 리뷰 반영(PR #101)
  - 오프라인 배너가 여러 줄이 돼도(좁은 화면·큰 글자) 상단 바 아래 화면이 덮이지 않게, 배너의 실제 높이를 CSS 변수 `--banner-h` 로 재어 현장·기록·설정 모두에 쓴다(고정 37px, 현장만 적용하던 것을 고침).
  - 브라우저 저장소를 열 수 없을 때 화면을 채우는 현장 지도가 오류 안내를 덮던 것을 고쳤다. 화면과 탭을 숨기고 안내만 보인다.
  - `ux.e2e` 에 두 경우를 더했고, 고치기 전 코드에서 실패함(배너: 기록 제목이 배너 아래로 내려가지 않음, 저장소: 안내 자리에 지도 SVG)을 확인했다.

## 데이터 사전에 없어 정한 값

- 시트 상태: `peek`(접힘)·`open`(펼침). 처음 상태는 자료가 없거나 지도를 못 그리면 펼침, 그 밖에는 접힘. 상태는 저장하지 않는다.
- 위 덮개는 찾기 칸·지도 버튼 줄까지이고 용도지역 범례는 넣지 않는다(켜도 지도가 좁아지지 않게).
- `reveal` 여백 40 px.

## 실제 작업 시간

약 3.5시간 (추정: 방향·토큰 계획 0.5, 화면·스타일 1.0, 앱 연결·글 1.0, 시험·화면 확인 0.7, 문서 0.3).

## 미확인 변수

- iPhone Safari 실기기: 시트 손잡이·스크롤, `:has()` 선택자(Safari 15.4 이상), 안전 영역(노치·홈 막대), 한 손 조작, 햇빛 아래 대비. 가상자료 헤드리스 시험 통과는 실기기 확인이 아니다.
- 휴대폰 세로 화면에서는 지도가 화면을 채워, 전체 보기 범위가 "이 범위 미리 받기"(대상·필지 + 300 m) 보다 위아래로 넓을 수 있다. 그 바깥 타일은 오프라인에서 비어 보인다. 미리 받기 범위를 화면 비율에 맞출지는 실제 임장에서 필요가 확인되면 따로 다룬다.
- 큰 정본(대상 수백 곳)에서 시트 목록 길이와 지도 점 겹침은 실자료로만 확인된다.
