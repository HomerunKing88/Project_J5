# J5-009 SQLite·최소 부모/기록·근거

기록일: 2026-09-23.

## 결과

- `j5/db/schema.py`: db_schema 1 마이그레이션. `meta`, `schema_migrations`, `subjects`, `assets`, `source_documents`, `records`, `record_evidence`, `attachments`. 모든 테이블 STRICT. 열거값(대상 타입 4종, 관심 단계 8종, 확인 상태, data_mode, record_type, 자료 종류 7종, 문서 종류, 검증 상태, 정밀도, MIME)·UUID·sha256·정본 시각(UTC `Z`)·날짜 모양은 CHECK. `records.payload_json`·`attachments.tags_json`은 `json_valid`+`json_type`. 대상 존재는 `subjects(subject_id, subject_type)` 복합 FK(ADR-09), `assets.subject_type`은 `'asset'` 고정 CHECK. `records`는 UPDATE/DELETE 트리거로 불변.
- `j5/db/validate.py`: 공통 검증 한 곳. `RECORD_TYPE_SUBJECTS`(record_type↔허용 대상 타입), payload 스키마(`schemas/observation_event.schema.json`의 `$defs/field_observation_payload` 재사용), 시간대 있는 ISO 8601·날짜 정밀도·UTC 정본 시각·달력 유효성.
- `j5/db/store.py`: `Db.create/open`(SQLite 3.38 이상, 외래키 켜짐 확인, 도구보다 새 스키마 거절, 부족한 마이그레이션 적용), `transaction()`(바깥 BEGIN IMMEDIATE, 중첩 SAVEPOINT, 예외 시 그 단위만 되돌림), `load_seed`(asset_id 승계, 전체 성공/전체 거절, 서술 필드만 갱신, 변경 시 `dataset_version` +1), `add_source_document`(시각 검증), `insert_record(evidence, attachments)`, 조회, `status`(integrity_check·foreign_key_check). `recorded_at`은 저장소 시계(`Db.now`)가 부여하고 입력값은 거절.
- CLI `j5 db init|status|load-seed`. 경로는 `--db` 또는 `J5_DATA_HOME/db/j5.sqlite3`, 둘 다 없으면 사용 오류(저장소 안에 기본 경로를 두지 않음).
- 테스트 18건: 생성·열기·버전, 트랜잭션 없는 쓰기 거절·롤백, 시드 멱등·갱신·전체 거절·타입 충돌, FK(없는 대상·타입 불일치·검증 우회 직접 삽입·자식 있는 부모 삭제), STRICT 타입·범위·열거·경로 탈출, 시점 규칙(검증 함수와 DB CHECK 각각), JSON·payload 스키마·정규화 저장, 불변 트리거·정정 체인·자기 참조 거절, 근거·첨부 UNIQUE·참조 중 문서 삭제 거절, fixture 정상 이벤트 전부 → 기록 매핑, CLI 종료 코드.

## 데이터 사전에 없어 정한 값

- 정본 파일명 `db/j5.sqlite3`. `meta` 키: `study_id`, `data_mode`, `dataset_version`(정수 문자열, 초기 `0`), `created_at`. 스키마 버전은 `schema_migrations.version`과 `PRAGMA user_version`.
- `dataset_version`은 정본 데이터가 바뀐 배치마다 1 올린다(§4). 시드 승계도 신규·갱신이 있으면 올리고, 변화 없음만이면 유지한다. 이벤트 반영 배치는 J5-010에서 같은 `bump_dataset_version()`을 쓴다.
- `recorded_at`(정본 최초 반영 시각)은 입력이 정하지 못한다. 기록·근거·첨부·출처 문서 입력에 `recorded_at`이 있으면 거절한다.
- `source_catalog / source_documents`("R1b 최소")는 `source_documents` 한 테이블로 시작: `document_kind`(field_package/official_api/official_file/broker_report/manual_entry), `title`, `terms`(이용조건), `location`(상대경로 등), `sha256`, `source_published_at`, `collected_at`, `notes`. 수집 방식 목록(카탈로그)은 R3 API 수집에서 분리한다.
- `records` 공통 시간: `observed_at`+`observed_at_precision`, `device_created_at`, `source_published_at`, `collected_at`, `recorded_at`(UTC, PC 부여), `effective_from/to`. `reviewed_at/valid_until`은 R7 검토 기록에서.
- `records.source_kind` = 데이터 사전 §1의 자료 종류 7종. `record_type`은 R1b에 `field_observation`만. 허용 대상은 `asset`만(점포 관측은 R2).
- `records.schema_version`은 payload 스키마 버전(현재 `1.0.0`). R1a 이벤트는 `event_id → record_id`, `corrects_event_id → supersedes_id`로 승계.
- `record_evidence.field_path`는 `$`(루트) 또는 `$.…`. `(record_id, field_path, document_id)` UNIQUE.
- `attachments`: `(record_id, sha256)` UNIQUE, `rel_path`는 상대경로만(절대·`..`·백슬래시 거절), `tags_json` 배열, `original_ref`(변환 원본 sha256).
- 관심 단계 기본 `unreviewed`, 확인 상태 기본 `confirmed`(시드에서 온 물건). `pending`은 대상 미확인 임시 단위용.
- `assets` 서술 필드는 시드로 갱신되지만 `tracking_status`·`resolution_status`는 시드로 바뀌지 않는다.
- `records` 삭제 금지 트리거를 우회하는 명령은 두지 않는다. 개인정보 오입력의 실제 삭제 절차(정본·기기·패키지·백업 사본 확인)는 별도 작업으로 정한다.

## 공수

- 예상 6~10시간. 실제(세션 기준) 약 1시간 + 리뷰 반영 약 0.5시간. 재작업: 시드 `created_at` 달력 검사가 스키마의 date 형식 검사와 겹쳐 테스트 기대 메시지를 완화.
- 리뷰 반영(PR #35, Codex 4건): 중첩 트랜잭션을 SAVEPOINT로 바꿔 바깥이 예외를 잡아도 실패 단위가 커밋되지 않게 함; 시드 변경 시 `dataset_version` 증가; `recorded_at` 입력 거절; 출처 문서 `collected_at`(시간대 있는 시각)·`source_published_at`(날짜 또는 시각)·첨부 `taken_at` 검증.

## 미확인 변수·남은 인수조건

- 사용자 PC의 Python이 링크한 SQLite 버전(3.38 이상 필요). `j5 db status`가 버전을 표시한다.
- 실제 정본 운영은 J5-010(반영기)·J5-012(백업·복구) 이후. 이 작업은 스키마·검증·시드 승계까지이며 이벤트 반영·`dataset_version` 증가·`import_runs`는 J5-010에서 다음 마이그레이션으로 추가한다.
- 저널 모드(WAL 여부)는 백업 API 검증과 함께 J5-012에서 정한다.
