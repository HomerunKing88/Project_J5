# J5-060 배포 설정 고정

기록일: 2026-10-13. 사용자가 Cloudflare 대시보드에서 프로젝트 `project-j5` 를 만들고 첫 빌드(#0778764a)를 성공시켰다(화면 확인). 만든 방식은 J5-059 에서 적은 Pages 가 아니라 Workers 정적 자산이다. 빌드 설정은 빌드 명령 없음, 배포 명령 `npx wrangler deploy`, 루트 디렉터리 `/` 이고, 저장소에 `pyproject.toml` 이 있어 `pip install .` 도 돌았다. 저장소에 배포 설정 파일이 없으면 wrangler 가 올릴 폴더를 추측한다.

## 결과

- 확인: 같은 wrangler(4.149.0)를 컨테이너에 받아 설정 파일 없이 `--dry-run` 을 돌리면 자동 설정이 "Framework: Static, Output Directory: web" 를 고른다. 첫 배포도 `web/` 만 올렸을 가능성이 높다. 다만 추측 규칙이 바뀌면 저장소 전체(문서·시험·PC 도구 코드)가 올라갈 수 있다. 실제 빌드 기록의 뒷부분은 보지 못했다.
- `wrangler.jsonc`(저장소 루트): Worker 이름 `project-j5`, `compatibility_date` 2026-10-01, `assets.directory` `./web`, `html_handling` `auto-trailing-slash`(`index.html` 넘김, J5-059 의 서비스 워커 처리와 맞음), `not_found_handling` `none`(없는 주소는 404). 서버 코드(`main`)·바인딩·환경 값은 두지 않는다. 시험이 그대로 읽게 주석 없는 JSON 으로 적었다.
- 같은 설정으로 `--dry-run`: "Read 34 files from the assets directory …/web", "Ignoring asset: _headers"(헤더 파일은 규칙으로만 쓰이고 올라가지 않는다). 설정 검사 오류 없음.
- `tests/test_web_publish.py` `test_wrangler_config_publishes_only_web`: 설정 키가 이름·호환 날짜·정적 자산뿐인지, 이름이 `project-j5` 인지, 올리는 폴더가 `web/` 인지, 바인딩·`run_worker_first` 가 없는지, 404·`index.html` 넘김 값. 설정 파일을 치우면 실패함을 확인했다.
- `tests/test_repo_allowlist.py`: 비밀키 형태 검사 대상에 `.jsonc` 를 더했다(새 설정 파일도 검사되게).
- ADR-24 에 J5-060 보정(Workers 정적 자산, `wrangler.jsonc`, Workers 사용자 지정 도메인은 Cloudflare DNS 영역 필요)을 더했다. `web/README.md` "배포" 를 사용자가 실제로 지난 화면 순서로 고쳤다.
- 앱 동작·앱 판 변경 없음(0.2.25 그대로).

- 사용자 결정(2026-10-13): `j5.dooduk.com` 은 Workers 의 사용자 지정 도메인으로 연결하고, 이를 위해 dooduk.com 의 DNS 를 Cloudflare 로 옮긴다(등록처 가비아). Pages 로 다시 만들지 않는다.

## 데이터 사전에 없어 정한 값

- `compatibility_date` 2026-10-01. 정적 자산만 내주므로 날짜에 따른 동작 차이는 없다.

## 테스트 명령과 결과 (2026-10-13, 컨테이너 Linux, Python 3.11, Node 22)

- `python -m pytest -W error::UserWarning` → 445 passed.
- `node --test --test-timeout=180000 "tests/web/**/*.test.mjs"` → 90 pass.
- wrangler 4.149.0 `deploy --dry-run`(올리지 않음, 계정 연결 없음): 위 결과.

## 실제 작업 시간

약 0.8시간 (추정: 빌드 화면 읽기·wrangler 동작 확인 0.4, 설정·시험 0.2, 문서 0.2).

## 미확인 변수

- 실제 Cloudflare 빌드가 이 설정을 읽는지, `_headers` 가 응답에 붙는지는 머지 뒤 빌드 기록과 응답 머리글로만 확인된다. dry-run 은 실제 배포가 아니다.
- Workers 의 사용자 지정 도메인 조건(도메인이 Cloudflare DNS 영역)은 Cloudflare 문서 검색 결과로 확인했다. 이 컨테이너에서는 문서 사이트에 직접 접속할 수 없었다.
- 이 컨테이너에서는 dooduk.com 의 DNS 를 조회할 수 없어 지금의 네임서버를 확인하지 못했다.

## 남은 인수조건·후속 작업

- 사용자(Cloudflare): 머지 뒤 새 빌드 기록에 `web` 폴더를 읽었다는 줄이 있는지 보고, `project-j5.<계정>.workers.dev` 를 폰에서 연다.
- 사용자(도메인): Cloudflare 에 `dooduk.com` 을 더해 기존 DNS 기록을 확인하고, 가비아에서 네임서버를 Cloudflare 가 알려 준 두 개로 바꾼다. 영역이 활성이 되면 Worker 에 `j5.dooduk.com` 을 사용자 지정 도메인으로 더한다(web/README "배포" 4단계).
- J5-059 의 남은 항목(예전 주소의 기록 옮기기, iPhone 확인, VWorld 서비스 URL)은 그대로다.

각 명령의 세부는 `j5/README.md`, 폰 앱은 `web/README.md`.
