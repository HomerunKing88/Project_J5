# J5-062 지도에서 자리 고르기

기록일: 2026-10-13. 사용자 요구: "필지들을 직접 선택하고 메모를 남길 수 있어야지", "PC 에서 현재 작업할 상황이 못 되니까 직접 해 주거나 방법을 알려 줘. 폰으로 할 수 있으면 더 낫고." 필지를 골라 기록하는 흐름(J5-028)은 있었지만 필지 경계 파일이 폰에 있어야 했고, 그 파일은 PC 도구로만 만든다. 이 작업 환경에서는 VWorld 접속이 조직 정책으로 막혀(`api.vworld.kr:443` CONNECT 거절) 대신 받아 줄 수도 없었다.

## 결과

- 현장 지도 오른쪽 확대·축소 아래에 "자리 고르기" 버튼(`#map-pick`, 십자 그림, `aria-label`·`aria-pressed`). 처음에는 위 버튼 줄에 글자 버튼으로 넣었으나 390px 폰에서 줄이 두 줄로 넘어가 지도가 좁아지고(앱 e2e 의 필지 누르기가 대상 점에 가려 실패) 오른쪽 도구 줄로 옮겼다. 누르면 고른 대상·필지 카드를 닫고 시트를 접은 뒤, 덮이지 않은 영역 가운데에 십자(`.layer-pick`)를 그리고 위에 막대(`#pick-bar`: 안내, 이름 선택 입력, "이 자리를 대상으로 기록", 취소)를 연다. 막대도 위 덮개로 재어 십자가 막대에 가리지 않는다.
- "이 자리를 대상으로 기록": 십자 자리(`map.visibleCenter()`, 소수 7자리)가 불러온 필지 안이면 그 필지 카드를 연다(필지에서 대상 만들기·기존 대상 기록, J5-028). 밖이거나 필지가 없으면 이 폰의 임시 대상(`origin: device`, `pnu: null`, 위치점은 십자 자리, 이름은 넣은 것 또는 "지도에서 고른 곳 (월-일 시:분)")을 만들고 바로 기록하기를 연다. 내보내기의 `assets.new.json` 에 실리고, PC `db import` 는 기존대로 "필지 PNU 미지정" pending 대상으로 만든다(스키마가 이미 `pnu` null 을 허용, PC 코드 변경 없음).
- `map.js`: `setPick(on)`, `visibleCenter()`, `createMap({ home })`. 그릴 자료가 없을 때 전체 보기는 `home`(종로5가역 부근 `[127.0019, 37.5709]`, z16 `HOME_SCALE`)으로 간다(배경 지도만 켠 경우 세계 전체가 보이던 것을 고침).
- `ui.js` `pickLabel(name, now)`: 이름 다듬기(앞뒤 공백, 60자)와 기본 이름.
- 비어 있는 지도 안내에 "설정에서 배경 지도를 켜면 지도에서 자리를 골라 바로 기록할 수 있습니다" 를 더했다.
- ADR-21 에 보정 문단을 더했다.
- 앱 0.2.27 (`APP_VERSION`, `sw.js` 캐시, e2e 5곳: app 2·ux 1·deploy 2). `sw.js` 앱 파일 목록은 그대로.
- 시험
  - `tests/web/ui.test.mjs`: `pickLabel`(이름, 빈 이름의 기본 이름, 공백만, 60자 자르기).
  - `tests/web/ux.e2e.test.mjs` 13e: 연습용 필지를 넣고 자리 고르기를 켜면 막대·십자가 보이고 시트가 접힘, 십자는 막대 아래, 지도를 끌어 필지를 십자에 맞추면 그 필지 카드(같은 PNU), 필지 묶음 밖으로 끌고 이름을 넣으면 기록하기가 그 이름으로 열리고 IndexedDB `device_assets` 에 `pnu` null·`origin` device·종로 부근 위치점, 취소로 닫힘. 안내 칸은 live 영역.
  - 새 시험은 고치기 전 코드에서 실패함을 확인했다.

- 별도 수정(같은 PR, 시험만): 전체 웹 시험 5번 가운데 1번 실패가 있었다. `app.e2e` 를 6개, `ux.e2e` 를 2개 동시에 돌려 기존 경합 두 곳을 재현했다.
  - 확대로 시작한 타일 요청이 300ms 뒤에도 이어져 "위치를 읽어도 타일 요청이 늘지 않는다" 가 실패했다(96 !== 73). 요청 수가 0.25초 동안 그대로일 때까지 기다린다.
  - 지도 실패 단계에서 기록 목록을 대상 목록 직후에 바로 세어 0 이 나왔다. 기록 목록 1줄을 기다린다.
  - 고친 뒤 같은 8개 동시 실행이 모두 통과했다. 앱 동작 변경은 없다.

## 데이터 사전에 없어 정한 값

- 자료가 없을 때 처음 보이는 곳: 종로5가역 부근 `[127.0019, 37.5709]`, 축척 z16.
- 자리 고르기 이름 상한 60자, 기본 이름 "지도에서 고른 곳 (월-일 시:분)".

## 테스트 명령과 결과 (2026-10-13, 컨테이너 Linux, Python 3.11, Node 22)

- `node --test --test-timeout=180000 "tests/web/**/*.test.mjs"` → 91 pass (헤드리스 Chromium e2e 포함). 위 경합 수정 전 5번 중 1번 실패, 수정 뒤 반복·동시 실행 통과.

## 실제 작업 시간

약 1.5시간 (추정: 방법 조사(VWorld 접속·CORS·데이터 계약) 0.4, 구현 0.5, 시험 0.4, 문서 0.2).

## 미확인 변수

- iPhone Safari 에서 손가락으로 지도를 끌어 십자를 맞추는 감각, 막대가 키보드에 가리는지, 큰 글자에서 막대 높이는 실기기에서만 확인된다.
- 자료 없이 배경 지도만 켠 상태의 처음 화면(종로5가역 부근)은 e2e 로 확인하지 않았다(배경 타일 응답이 필요). 실기기에서 본다.
- 필지 번호가 없는 대상은 PC 에서 필지와 이어 확인해야 한다(`db asset-confirm` 등 기존 검토 흐름).
- 폰이 VWorld 필지 자료(데이터 API)를 직접 받는 길은 응답의 CORS 여부를 확인하지 못했고, 외부 자료 요청·CSP(`connect-src`)·키 사용 범위를 바꾸는 결정이라 새 ADR 과 사용자 승인이 필요하다.

## 남은 인수조건·후속 작업

- 사용자(폰): 설정에서 배경 지도를 켠 채(직접 입력 주소는 `{key}` 그대로, 키는 인증키 칸) 현장 → 오른쪽 십자 버튼(자리 고르기) → 지도를 움직여 가운데 십자를 맞추고 이름을 넣어 "이 자리를 대상으로 기록" → 메모·사진 저장. 기록 → PC 로 보내기로 파일을 만들어 둔다.
- 사용자(PC, 나중에): 받은 파일을 `j5 db import` 로 반영하고 필지 미지정 대상을 필지와 잇는다. 필지 경계를 폰에 넣으면(`parcels convert` 또는 `project-copy`) 그때부터 십자가 필지 안이면 필지 카드가 열린다.

각 명령의 세부는 `j5/README.md`, 폰 앱은 `web/README.md`.
