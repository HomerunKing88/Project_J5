# J5-034 건축물대장 표본 수집 도구 (J5-013B-3 첫 조각)

기록일: 2026-09-28. R2 의 "허용된 필지·건축물 자료를 수집·정규화한다. 총괄/개별 대장·다필지 관계" 중 건축물 쪽이 남아 있었다(J5-013B 기록 "건축물대장(J5-013B-3)은 별도"). AGENTS "약관·승인·실제 응답을 먼저 확인한다" 에 따라 실거래 수집(J5-014A)과 같은 순서를 쓴다. 이번 조각은 공식 API 를 지정 필지에만 불러 원본을 보관하고 필드 가용성을 요약하는 도구다. 정규화·정본 표·필지 연결·폰 표시는 사용자가 실제 응답을 받은 뒤 다음 조각에서 필드를 확정해 만든다.

## 결과

- `j5/collect/br.py`(새):
  - 대상: `--pnu` 로 준 PNU 와 정본의 현재 물건↔필지 연결(`--linked`, 읽기 전용). 한 번에 50필지까지(AGENTS "상세 필지·대장은 지정 대상만 수집한다").
  - PNU → 요청 변수: 시군구 5자리·법정동 5자리·대지구분(PNU 11번째 자리 1→0 대지, 2→1 산)·본번 4자리·부번 4자리. 형식이 맞지 않으면 요청 전에 거절한다.
  - 오퍼레이션 키 8개: 기본 다섯(`basis` 기본개요, `recap` 총괄표제부, `title` 표제부, `floor` 층별개요, `atch` 부속지번)과 선택 셋(`expos` 전유부, `area` 전유공용면적, `zone` 지역지구구역). 소유자·주택가격·오수정화시설은 넣지 않았다.
  - 필지 × 오퍼레이션마다 페이지를 끝까지 받아 `complete / empty(정상 0건) / partial(페이지 누락·totalCount 없음) / failed` 로 구분한다. 하나가 실패해도 나머지를 계속한다.
  - 원본은 `raw/br_hub/<PNU>/<키>/pNNN-<실행>.xml` 에 그대로 둔다. 기록은 `run-<실행>.json`, 요약은 `report-<실행>.json` 이다. HTTP 오류 본문은 가려서 `.txt` 로 둔다. 모든 파일은 배타적으로 생성해 덮어쓰지 않는다.
  - 응답 해석(DOCTYPE 거절·크기 상한·신형/구형 결과 코드), 재시도, 키 가림은 `j5.collect.rt` 의 함수를 그대로 쓴다. 필드 이름은 가정하지 않고 태그명→문자열로 보존한다.
  - 요약(`br-report`): 오퍼레이션별 필지 결과 수, 항목 수, 필드 채움 비율, 값 종류 수. 값 분포는 값 종류가 20개 이하이면서 모든 값이 12자 이하인 필드만 싣는다(용도 분류·층수 같은 코드성 값). 주소·건물명 같은 긴 글은 분포 없이 채움 비율만 싣는다.
- CLI: `collect br-sample`, `collect br-report`. 성공 0, API 실패가 하나라도 있으면 1, 잘못된 PNU·오퍼레이션·대상 없음·키 없음은 3.
- 시험 `tests/test_j5_034_br_collect.py` 4건: 요청 변수·URL, 로컬 HTTP 서버로 6가지 결과(3페이지 정상·0건·페이지 누락·API 오류·HTTP 403·이어서 다음 대상), 키 없음(원문·부호화 두 형태), 요약에 주소 글 없음, 재요약, 상한, CLI(`--linked` 가 끝난 연결을 빼고 정본을 바꾸지 않음).
- 문서: 릴리스 계획 §10 J5-034, `j5/README.md`, `tests/README.md`, 색인(J5-032 #79·#80, J5-033 #80).

## 데이터 사전에 없어 정한 값

- 원본 위치 `raw/br_hub/<PNU>/<오퍼레이션 키>/`, 실행 ID 는 실거래 수집과 같은 규칙.
- 페이지당 100행(상한 100), 대상마다 최대 20페이지, 요청 사이 0.2초 대기.
- 요약 분포의 값 길이 상한 12자(요약은 사용자가 공유하는 파일이라 긴 글을 싣지 않는다).

## 리뷰 반영 (PR #81, Codex 1건)

- P2 페이지 넘김 불일치: API 가 `pageNo` 를 무시하고 앞 페이지를 되풀이하면 겹친 행을 더하다 totalCount 에 닿아 뒷 행을 받지 않고도 `complete` 가 됐다. 이제 응답의 pageNo 가 요청한 페이지와 다르면 항목을 더하지 않고 그 대상을 `failed`(bad_response, "페이지 넘김이 맞지 않음")로 둔다. 응답에 pageNo 가 없으면 이전과 같다. 시험 보강(늘 1페이지를 주는 가상 응답).
- 같은 검사가 실거래 수집(`j5.collect.rt`)에는 없다. 이 작업 밖이라 바꾸지 않았고 별도 작업으로 뒀다(실측 3차에서 거래 월은 모두 1페이지라 드러나지 않았다). J5-035 에서 반영했다.

## 미확인 변수

- 작업 환경에서 공공데이터포털(data.go.kr)과 건축HUB(hub.go.kr) 문서 페이지에 접속하지 못했다(네트워크 정책 차단). 기본 주소 `https://apis.data.go.kr/1613000/BldRgstHubService` 와 오퍼레이션 이름(`getBrTitleInfo` 등), 요청 변수(`sigunguCd`·`bjdongCd`·`platGbCd`·`bun`·`ji`·`_type`)는 알려진 값을 코드에 적은 것이며 실제 응답으로 확인하기 전까지 가정이다. 이용허락범위·일일 트래픽 한도도 확인하지 못했다.
- 페이지당 행 수 상한(100)이 실제 서비스 한도와 맞는지 확인하지 못했다.
- 한 필지에 여러 동이 있거나(표제부 여러 행), 한 건물이 여러 필지에 걸친 경우(부속지번) 응답이 어떻게 나오는지는 실제 응답으로 본다. 다음 조각의 정규화(총괄/개별 대장 분리, FAR 산정용 연면적과 총연면적 분리, 다필지 관계)는 그 결과로 정한다.
- 가상 서버 시험 통과는 실제 API·승인 확인이 아니다.

## 남은 인수조건·후속 작업

- 사용자(PC):
  1. 공공데이터포털에서 "국토교통부_건축HUB_건축물대장정보 서비스" 를 활용신청한다.
  2. 승인 뒤 마이페이지의 요청주소·상세기능 목록을 코드의 기본값과 대조한다. 다르면 `--endpoint-base` 로 준다.
  3. 이용허락범위를 확인한다.
  4. `j5 collect br-sample --linked`(또는 `--pnu <PNU>` 몇 개)를 실행한다.
  5. `j5 collect br-report` 의 요약만 공유한다. 원본·키는 보내지 않는다.
- 다음 조각(J5-034 후속): 확인한 필드로 정본 표(총괄표제부·표제부·층별개요·부속지번), 필지·물건 연결, 파생본과 폰 필지 패널의 건물 줄을 만든다. 면적은 FAR 산정용 연면적과 총연면적을 나눠 담는다.
