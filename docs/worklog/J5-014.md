# J5-014 거래·2006년 소급·비교 깊이

기록일: 2026-09-23. 이 작업은 조각으로 나눈다. **A**(이 기록): 실거래 API 표본 월 수집 도구(R0 통과조건 실측). **B 이후**(별도): 실제 응답으로 확인한 필드로 거래 원본·정규화·범위·연결(데이터 사전 §7.2, R3).

## A. 결과

- `j5 collect rt-sample --lawd-cd 11110 --months 2026-08,2021-09,2006-03 [--endpoint] [--num-rows] [--max-pages]`: 상업·업무용 부동산 매매 실거래 API 를 시군구·계약월·페이지 단위로 호출해 원본 응답을 `J5_DATA_HOME/raw/rt_nrg/<시군구>/<YYYYMM>/pNNN-<실행>.xml` 에 그대로 두고, 요청·응답 기록 `run-<실행>.json`(URL 의 인증키 가림, HTTP 상태·바이트·해시·resultCode·totalCount·항목 수·시도 횟수), 요약 `report-<실행>.json`(필드 채움 비율·`*` 마스킹·값 종류·낮은 카디널리티 필드의 분포), `logs/collect.log` 를 남긴다. 정본에는 쓰지 않는다.
- 월 결과를 `complete / empty(정상 0건) / partial(페이지 누락) / failed(API 오류·HTTP 오류·네트워크·응답 이상)` 로 구분한다(데이터 사전 §7.1 "API 실패·정상 0건·페이지 누락을 구분"). 한 달이 실패해도 다음 달을 계속한다. 네트워크 오류만 3회 지수 대기 재시도.
- `j5 collect rt-report`: 저장된 원본만으로 요약을 다시 만든다(네트워크 없음). 사용자가 나에게 보낼 것은 이 요약이며 원본 행·인증키는 보내지 않는다.
- 인증키: 환경변수 `DATA_GO_KR_SERVICE_KEY` 또는 `J5_DATA_HOME/config.env`(`j5/collect/config.py`). 키에 `%` 가 있으면 이미 URL 부호화된 키로 보고 그대로, 아니면 부호화한다. 다른 사용자가 읽을 수 있는 권한이면 `chmod 600` 을 안내한다. 키는 로그·기록·요약·출력 어디에도 남기지 않는다(퍼센트 부호화 형태까지 가림).
- 응답 해석은 `xml.etree` 로 header/body 만 읽고 항목은 태그명→문자열로 보존한다(필드 이름을 코드가 가정하지 않는다). DOCTYPE/ENTITY 선언·20MB 초과 응답·XML 아님을 거절한다. resultCode 는 신형 `000`·구형 `00` 을 정상으로, `<OpenAPI_ServiceResponse><cmmMsgHeader>` 오류 형식도 읽는다.
- 테스트 `tests/test_j5_014_collect.py` 9건: 설정·키 출처·권한·가림, URL(부호화/이미 부호화), 응답 형식·거절, 요약, 로컬 HTTP 서버로 8가지 월 시나리오(3페이지 정상·구형 코드·0건·API 오류·HTTP 500·XML 아님·DOCTYPE·페이지 누락), 네트워크 재시도, 입력 검증, CLI. 실제 포털은 호출하지 않는다.

## 데이터 사전에 없어 정한 값

- 원본 경로 `raw/rt_nrg/<시군구 5자리>/<YYYYMM>/p<페이지 3자리>-<실행 ID>.xml`. 실행 ID 는 UTC 시각 `YYYYMMDD-HHMMSS`. 같은 월을 다시 받으면 새 실행 ID 의 파일이 옆에 쌓인다(덮어쓰지 않음). `collection_runs` 정본 테이블은 R3 에서 만들고, 지금은 파일 기록이 체크포인트다.
- 기본 엔드포인트 `https://apis.data.go.kr/1613000/RTMSDataSvcNrgTrade/getRTMSDataSvcNrgTrade` 는 알려진 최신 주소를 코드에 적은 것이며 실제 응답으로 확인하기 전까지 가정이다. 사용자가 API 상세 페이지의 주소와 대조해 다르면 `--endpoint` 로 준다. 실제 쓴 주소는 기록에 남는다.
- 페이지당 1000행, 월당 최대 50페이지(옵션). 페이지 사이 0.2초 대기. `totalCount` 를 채우기 전에 빈 페이지가 오면 `partial`.
- 요약의 값 분포는 값 종류 20개 이하인 필드만, 값 종류 집계는 필드당 200개까지만 센다(원본 행을 옮기지 않기 위한 상한).

## 리뷰 반영 (PR #43, Codex 4건)

- P1 실행 ID 충돌: 실행 ID 를 UTC 초 시각 + 무작위 6자리로 만들고, 원본·기록·요약 파일은 배타적 생성(`open(…, "xb")`)으로만 써서 같은 이름이면 실패한다(덮어쓰기 없음).
- P1 재요약 범위: `rt-report` 는 월마다 한 실행만 센다(`--run-id` 또는 가장 최근 실행). 다른 실행 목록은 `other_runs` 로 표시한다. 여러 실행을 합치지 않는다.
- P1 되비친 URL: 응답 앞부분을 담는 오류 문구·resultMsg 를 결과 객체에 넣기 전에 가리고, CLI 출력도 한 번 더 가린다.
- P2 totalCount 없음: 항목이 있어도 `totalCount` 가 없거나 숫자가 아니면 `complete` 가 아니라 `partial`(완전성 확인 불가)로 둔다.

## 실측 1차 (2026-09-23, 사용자 PC)

- `rt-sample --lawd-cd 11110 --months 2026-08,2021-09,2006-03` 이 세 달 모두 `HTTP 403 Forbidden` 으로 실패했다(기본 엔드포인트, config.env 의 키). 당시 도구는 HTTP 오류 본문을 저장하지 않아 포털의 거절 사유를 볼 수 없었다.
- 후속: HTTP 오류 응답 본문을 `pNNN-<실행>-http<코드>.txt` 로 보관(키 가림)하고 `resultMsg`/`returnAuthMsg`/`errMsg` 또는 본문 앞부분을 결과 줄에 보인다. 403 의 원인 후보는 (1) 신청·승인된 API 의 엔드포인트가 기본값과 다름, (2) 승인 직후 반영 지연, (3) 키 오기입. 사유 문구로 가른다.

## 리뷰 반영 (PR #44, Codex 1건)

- P1 되비친 키의 부호화 변형: 게이트웨이가 요청 URL 을 되비칠 때 `%2B` 를 `%2b` 로 바꾸면 값 비교 가림이 놓쳤다. `redact()` 를 두 겹으로 바꿨다. (1) `serviceKey=` 뒤 값은 내용과 무관하게 가린다. (2) 원문·복호화·부호화 형태를 16진수 대소문자 무관 정규식으로 가린다. 저장하는 HTTP 오류 본문도 같은 함수를 거친다.

## 실측 2차·3차 (2026-09-23~24 KST, 사용자 PC)

- 2차: PR #44 반영 뒤 같은 명령이 `HTTP 403 · 응답 사유: 30 등록되지 않은 서비스키` 로 실패했다. 포털 요청주소는 기본 엔드포인트와 같았다(사용자가 마이페이지에서 대조). 키 형태 점검(값을 찍지 않고 길이만) 결과 config.env 의 값이 66자였고, 다시 저장한 뒤에는 128자였다. 포털 키를 다시 붙여 넣어 대조하니 실제 키는 64자였다. 128자는 같은 키가 두 번 붙은 것이고, 66자는 잡문자가 섞인 것이었다. 원인은 붙여넣기 오류였고 포털·도구·엔드포인트는 문제가 없었다. 저장 직후 글자 수를 보여주는 명령으로 64자 저장을 확인했다.

## 리뷰 반영 (PR #45, Codex 2건)

- P1 실패한 실행의 재요약: 정상 페이지가 없는 실행(API 오류 XML 만 저장, 또는 오류 본문만 있는 실행을 `--run-id` 로 지정)에서 재요약이 실행 기록을 읽지 않아 `no_raw` 만 보였다. 선택한 실행이 있으면 기록을 항상 읽어 `수집 결과 failed` 와 실행 ID 를 보인다. 받은 적 없는 달(`no_raw`, 실행 없음)과 구분된다.
- P2 구조가 다른 기록 파일: JSON 이지만 `months` 가 목록이 아니거나 항목이 객체가 아니면 TypeError 로 CLI 가 중단됐다. 구조를 검사해 (None, None) 으로 돌아간다.

## R0 통과조건 판정 (부분)

- 확인됨: 세 시점 모두 API 응답이 있고 2006년 자료가 있다. 시군구 월 40건 안팎이라 페이지당 1000행이면 월 1페이지, 2006-01~2026-09 약 249개월 소급은 약 250회 호출이다(일일 트래픽 안). 주소 공개 수준은 지번 마스킹이다.
- 미확인: 핵심 범위(종로5·6가 주변 법정동)와 비교 블록의 월평균 행수·거래 범위 분포. `rt-report … --dist umdNm --dist buildingType --dist shareDealingType` 결과로 정한다. 연 30건 내외면 릴리스 계획 §4 대로 R3 의 연결 검토 화면을 만들지 않고 CSV 목록·수동 확인으로 대체한다.
