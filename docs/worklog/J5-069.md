# J5-069 앱 캐시 버전 지킴 시험

기록일: 2026-10-13. 사용자 지시: "머지하고 다음 작업 진행". PR #115 의 Codex 리뷰(P1)가 `web/app/view.js` 를 바꾸고 서비스 워커 캐시 이름을 올리지 않은 것을 잡았다. 이름이 같으면 이미 설치한 폰은 캐시해 둔 이전 파일을 계속 쓰므로, 새 PC 자료를 이전 코드로 읽는다(그 PR 에서는 시군구를 붙인 범위 항목을 범위 밖으로 보였을 것이다). 같은 실수가 사람 확인에만 걸리지 않게 시험으로 지킨다.

## 결과

- `tests/test_j5_069_app_cache_lock.py`
  - 캐시 목록(`web/sw.js` APP_FILES, `./` 는 index.html)의 파일마다 "경로\0내용 sha256" 을 이어 sha256 한 값과 캐시 이름(`CACHE`)을 고정값 파일 `tests/fixtures/app_cache.lock.json` 과 대조한다.
  - 캐시 이름이 고정값과 같은데 해시가 다르면 실패: "sw.js CACHE 와 main.js APP_VERSION 을 올리고(e2e 의 버전 기대값도) 고정값을 갱신한다".
  - 캐시 이름이 바뀌었으면 고정값 갱신을 안내하며 실패한다(`python tests/test_j5_069_app_cache_lock.py --write`). 캐시 목록이 바뀌어도 같다.
  - `APP_VERSION` 과 캐시 이름이 같은지 본다.
  - 시험 자체의 갈래: 앱 파일을 바꾸면 해시가 달라지고, `sw.js` 의 캐시 이름 줄만 바꾸면 해시는 그대로다(sw.js 는 해시에 넣지 않는다).
- `tests/fixtures/app_cache.lock.json`: v0.2.33, 24개 파일.
- 과거 커밋으로 확인: b1bb891(v0.2.32) 과 PR #115 첫 커밋 25fdb34(v0.2.32, view.js 바뀜)의 해시가 달라 이 시험이 그 커밋을 실패시켰을 것이다. 53a519e(v0.2.33) 는 고정값과 같다.
- 문서: `web/README.md`(sw.js 절), `tests/README.md`.
- 앱 동작은 바뀌지 않았다(앱 버전 그대로).

## 데이터 사전에 없어 정한 값
