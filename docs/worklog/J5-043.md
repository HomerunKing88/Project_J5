# J5-043 PC 필지 이력의 연도별 실거래와 실제 마스킹 지번 대조

기록일: 2026-09-28. 큰 목표는 필지(PNU)마다 속성과 거래를 연도별로 쌓아 보는 것이다. 폰 필지 이력(J5-023)에는 거래가 들어갔으나 PC `db parcels-history`(J5-026·030)는 속성 이력만 보였다. 이번에 PC 에도 거래를 넣으면서 폰 지번 대조가 실제 마스킹 표기를 읽지 못하는 것을 확인해 함께 고쳤다.

## 결과

- `j5/db/parcel_timeline.py`(새 모듈, 정본에 쓰지 않음):
  - `parcel_transactions(db, pnu)`: 정본 transactions 중 법정동 이름이 같고 지번이 닿는 거래. 같은 필지(exact)와 번지대(prefix, 필지 미확정)로 나눈다. 이 필지에 지금 연결된 물건에 확정 연결(confirmed)된 거래는 지번이 닿지 않아도 넣는다(linked). 지번 대조는 연결 후보 CSV 의 `txlinks.jibun_matches` 를 그대로 쓴다.
  - 취소 확정 거래는 목록에서 빼고 수만 센다. 범위(core/comparison/outside/unclassified)와 무관하게 정본 거래를 모두 본다. 폰 파생본에는 핵심·비교 범위의 거래만 들어간다.
  - 거래 시군구 코드와 필지 PNU 앞 5자리가 다르면 거래마다 표시한다. 대조에서 빼지는 않는다(아래 "정한 값").
  - `by_year`: 속성 변화(기준일 연도)와 거래(계약연도)를 연도별로 묶는다(최근 먼저). `with_transactions` 가 `attribute_history` 결과에 `transactions`·`transactions_cancelled`·`transactions_sgg_differs`·`years` 를 더한다.
  - `years_text`: 실거래 합계 줄(같은 필지·번지대·연결 물건의 거래·취소 확정 제외 수)과 연도별 거래 줄(금액·일반/집합·용도·건물·대지 면적·지분, 동·지번 표기 그대로, 확정 연결·제공자 목록에서 사라짐·시군구 코드 다름). 번지대가 있으면 "이 필지의 거래로 확정하지 않는다" 를 적는다. 금액 표기는 폰 `fmtKrw` 와 같다.
- `db parcels-history <PNU>` 가 속성 이력 글 뒤에 실거래 연도별 글을 붙인다. `--json` 에 위 키가 들어간다. 도움말 문구를 고쳤다.
- 폰 `web/app/view.js`:
  - `parseJibun`·`jibunMatch` 를 PC `parse_jibun`·`jibun_matches` 와 같은 규칙으로 고쳤다.
  - 이전 폰 규칙은 `1-*` 형태(본번 온전, 부번 전체 마스킹)만 읽었다. 실제 표기는 자릿수를 별표로 가린다(`1**`, `8*`, `1**-*`, `16*-3`, J5-014 실측). 그래서 실데이터에서는 번지대 거래가 폰 필지 이력에 하나도 들지 않았다. 고치기 전 코드에서 `jibunMatch({jibun:"1**"}, 본번 160 필지)` 가 null 임을 확인했다.
  - `1-*` 는 부번 한 자리 필지만 닿는다(이전 폰 규칙은 부번 자릿수를 보지 않았다). PC 규칙과 같다.
  - 앱 0.2.15, 서비스 워커 캐시 v0.2.15.
- 시험:
  - `tests/test_j5_043_parcel_timeline.py` 5건: 거래 모으기(같은 필지 2·번지대 1·연결 1, 다른 필지·다른 법정동·`*`·산 제외, 취소 확정 1은 수만), 4-2 필지의 번지대, 연도별 묶음·글, 거래 없는 정본, CLI 글·JSON. 실제 마스킹 표기 16사례 표를 PC 규칙으로 확인한다.
  - `tests/web/view.test.mjs`: 같은 사례 표(12사례)로 폰 `jibunMatch` 를 확인한다. 고치기 전 코드에서 이 시험이 실패함을 확인했다.
- 문서: 릴리스 계획 §10 J5-043, `j5/README.md`, `web/README.md`, `tests/README.md`, 색인(J5-042 #89).

## 데이터 사전에 없어 정한 값

- 연결 물건의 거래(linked): 필지 연결은 오늘 유효한 asset_components, 거래 연결은 확정(confirmed)만. 후보·증거 대기 연결은 넣지 않는다.
- 시군구 코드 대조: 필지 이력은 법정동 이름으로 대조하고 시군구 코드가 다르면 표시만 한다. 가상자료는 필지 시군구가 99999, 거래 시군구가 11110 이라 코드를 대조에 넣으면 기존 폰·연결 후보 시험 자료를 모두 바꿔야 한다. 여러 지역을 한 정본에 넣으면(ADR-23) 이름이 같은 다른 시군구 법정동이 섞일 수 있으므로, 코드 대조를 규칙에 넣는 일은 가상자료의 시군구 코드를 맞춘 뒤 별도 작업으로 한다.

## 미확인 변수

- 실데이터 정본에서 물건 필지마다 번지대 거래가 몇 건 붙는지 모른다. 일반건축물 지번은 전 시기 마스킹이라(J5-014) 한 번지대에 필지가 많은 곳은 번지대 거래가 많이 붙는다.
- 이름이 같은 다른 시군구 법정동이 실제 정본에 함께 들어가는지는 사용자가 넣는 지역에 달렸다. 들어가면 필지 이력 줄에 "시군구 코드 다름" 이 보인다.
- 폰 필지 이력의 번지대 표시는 가상자료 브라우저 시험만 거쳤다. iPhone 실기기 확인이 남았다.

## 남은 인수조건·후속 작업

- 사용자(PC): 물건 필지로 `j5 db parcels-history <PNU>` 를 돌려 실거래 연도별 줄을 확인한다.
- 사용자(폰): `project` → `project-copy` 뒤 PC 자료 파일을 다시 불러와 필지 패널 "이 필지 이력" 에서 번지대 거래가 보이는지 확인한다.
- 후속: 가상자료의 시군구 코드를 맞춘 뒤 지번 대조에 시군구 코드를 넣는다(폰·연결 후보·필지 이력 공통).

각 명령의 세부는 `j5/README.md`, 폰 앱은 `web/README.md`.
