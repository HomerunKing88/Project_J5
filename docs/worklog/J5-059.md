# J5-059 정적 HTTPS 배포 준비

기록일: 2026-10-13. 사용자 확인: "현재 휴대폰에서 조회가 되고 있지 않다"(앱 주소가 아예 열리지 않음). 앱은 PC 의 `python -m http.server` 를 같은 Wi-Fi 에서 `http` 로 여는 방식뿐이라, PC 가 꺼져 있거나 밖에 있으면 열리지 않고 `http` 라서 서비스 워커(오프라인)·현재 위치·WebCrypto 도 쓸 수 없다. 사용자 결정: 공급자 Cloudflare Pages, 사용자 도메인 dooduk.com 의 하위 주소. 도메인 루트는 재무관리용으로 두고 이 앱은 임장 앱으로 `j5.dooduk.com` 에서 연다.

## 결과

- `docs/ADR.md` ADR-24: Cloudflare Pages 무료 요금제, 비공개 저장소 Git 연동, 빌드 없이 `web/` 게시, 운영 판 `main`, 주소 `j5.dooduk.com`(루트는 이 저장소에서 다루지 않음), 서버 API·서버 저장 없음, 선택 사항 Cloudflare Access. ADR-01 의 "공급자는 계정 확인 후 확정" 을 채운다. 서버가 자료를 보관하는 웹서비스는 새 ADR 이 필요한 대안으로 적었다.
- `web/_headers`(공급자의 응답 헤더 설정, 사이트에서 내려받을 수 없음): `frame-ancestors 'none'`·`X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy`(현재 위치는 이 앱만, 마이크·결제·USB 끔. 카메라는 막지 않음: 사진 입력이 기기 카메라를 쓴다), 앱 진입점·`sw.js` 는 `no-cache`. 앱 CSP 는 지금처럼 각 페이지의 meta 에 있다.
- `web/sw.js`: 공급자는 `./index.html` 을 `./` 로 넘긴다(308). 설치 때 받은 이 응답에는 "넘겨받음" 표시가 붙고, 서비스 워커가 그대로 탐색에 돌려주면 브라우저가 페이지를 열지 않는다(홈 화면 북마크·예전 주소의 `index.html`). 캐시에서 꺼낸 응답에 표시가 있으면 같은 본문·머리글로 새 응답을 만든다.
- `web/devtest.html`: "처음으로" 링크를 `index.html` 에서 `./` 로(넘김 없이).
- 앱 0.2.25 (`APP_VERSION`, `sw.js` 캐시, e2e 3곳). `sw.js` 앱 파일 목록은 그대로.
- `web/README.md` "배포": 사용자 절차 7단계(계정, 저장소 연결, 빌드 설정, `j5.dooduk.com` 과 CNAME, 선택 Access, 예전 주소의 기록을 PC 로 보내고 옮기기, VWorld 서비스 URL 등록).
- 시험
  - `tests/test_web_publish.py`: 게시 폴더 `web/` 에 코드·문서·가상자료·`_headers` 만 있는지, `data/` 파일이 `synthetic` 으로 표시되고 실제 자료 표시가 없는지, 헤더가 현재 위치를 막지 않고 카메라를 끄지 않는지, 헤더의 CSP 가 `frame-ancestors` 뿐인지, `sw.js` 가 `no-cache` 인지. `web/data/parcels.real.json`·`web/photo.jpg` 를 임시로 넣어 실패함을 확인했다(확인 뒤 지움).
  - `tests/web/deploy.e2e.test.mjs`: 공급자처럼 `/index.html` → `/`, `/devtest.html` → `/devtest` 로 넘기는 서버에서 서비스 워커가 맡은 뒤 `/index.html` 열기, 기기 시험 페이지의 처음으로 링크, 오프라인으로 `/`·`/index.html` 열기, 콘솔 오류 없음. 고치기 전 `sw.js`(캐시 판만 올림)에서 `/index.html` 단계가 실패함을 확인했다.

## 데이터 사전에 없어 정한 값

- 게시 주소 `j5.dooduk.com`. 하위 주소 이름 `j5` 는 사용자가 고른 "하위 주소 j5.도메인" 을 따른다.
- 게시 폴더에 허용하는 파일: `.html`·`.js`·`.css`·`.svg`·`.md`, `data/*.synthetic*.json`, `_headers`.

## 테스트 명령과 결과 (2026-10-13, 컨테이너 Linux, Python 3.11, Node 22)

- `python -m pytest -W error::UserWarning` → 444 passed.
- `node --test --test-timeout=180000 "tests/web/**/*.test.mjs"` → 90 pass (헤드리스 Chromium e2e 포함).

## 실제 작업 시간

약 1.3시간 (추정: 원인 확인·공급자 비교 0.3, 헤더·게시 검사 0.3, 넘김 응답 재현·수정 0.3, 문서 0.4).

## 미확인 변수

- 실제 Cloudflare Pages 게시, `j5.dooduk.com` 연결, 응답 헤더 적용은 사용자 계정 설정 뒤에만 확인된다. 이 컨테이너에서는 dooduk.com 의 DNS 를 조회할 수 없어 DNS 관리처를 확인하지 못했다. 가상 서버 e2e 통과는 실제 공급자·iPhone Safari 확인이 아니다.
- 공급자의 `index.html` 넘김(308)은 공급자 문서의 동작을 가상 서버로 흉내 냈다. 실제 게시 뒤 `https://j5.dooduk.com/index.html` 을 한 번 열어 본다.
- iPhone 홈 화면 앱은 주소마다 저장소가 따로라, 예전 `http` 주소의 기록은 새 주소로 넘어오지 않는다.

## 남은 인수조건·후속 작업

- 사용자(계정): web/README "배포" 1~4단계로 Pages 프로젝트를 만들고 `j5.dooduk.com` 을 연결한다. 도메인 루트의 기존 연결 정리는 이 앱과 무관하게 따로 한다.
- 사용자(폰): 예전 주소에서 남은 기록을 모두 PC 로 보내고 PC 반영을 확인한 뒤, iPhone Safari 에서 `https://j5.dooduk.com/` 을 열어 홈 화면에 추가하고 PC 자료 파일 가져오기·현재 위치·비행기 모드에서 다시 열기를 확인한다.
- 배경 타일 키를 쓰면 VWorld 에 `https://j5.dooduk.com` 을 서비스 URL 로 등록한다.

각 명령의 세부는 `j5/README.md`, 폰 앱은 `web/README.md`.
