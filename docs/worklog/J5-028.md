# J5-028 필지에서 물건 만들기: 기기의 임시 매입 단위와 PC 승계

기록일: 2026-09-27. 필지 수천 개와 속성·검색·현재 위치가 폰에 들어오자, 물건 목록에 없는 필지를 현장에서 바로 기록할 길이 필요해졌다. 데이터 사전 §2 의 "임시 매입 단위 ID 와 resolution_status=pending" 규칙을 ADR-21 로 구현했다.

## 결과

- 폰(`web/app/db.js` v5 `device_assets`, `parcels.js` `interiorPoint`, `main.js`·`index.html`): 필지 패널에 "이 필지를 물건으로 기록" 버튼(그 필지에 물건이 없을 때만). 누르면 이 기기에만 임시 물건(`origin: device`, 이름 동·지번, 위치점 필지 안의 점, PNU 참고값, 자료 종류는 설정값)을 만들고 바로 관측 화면을 연다. 목록에 "이 기기에서 만듦 · PC 반영 전" 배지, 기록이 없으면 "삭제". 시드 교체에도 남고, 파생본·시드에 같은 ID 가 오면 사본을 지운다. 앱 0.2.7, SW 캐시 v0.2.7.
- 내보내기(`export.js`): 묶음의 기록이 가리키는 기기 물건만 `assets.new.json` 으로 싣고 manifest `schema_version` 1.1.0. 자료 종류가 다르면 거절. 준비 안내에 "기기가 만든 물건 N개".
- 계약: `schemas/assets_new.schema.json`(추가 필드 불가), `package_manifest.schema.json`(경로·버전 1.1.0), `j5/__init__.py` 지원 버전, 패키지 항목 허용목록.
- PC 검사(`j5/package/validate.py`): 파일 크기 한도·JSON·스키마·중복 ID·data_mode 검사, 시드 대조에서 새 물건 인정, 이미 시드에 있으면 정보, 어떤 이벤트도 가리키지 않으면 경고, `counts.new_assets`.
- PC 반영(`j5/db/importer.py`): 정본에 없는 새 물건을 `resolution_status=pending`(위치점·기기 시각·PNU 를 비고에) 으로 만든 뒤 기록 반영. 결과 `assets_created` 와 안내. `db asset-confirm <asset_id> [--label]` 로 확정(dataset_version 증가).
- fixture: `tests/fixtures/packages/new_asset/`(README 표 갱신).
- 테스트: `test_j5_008_inspect.py` 2건(검사·거절·경고), `test_j5_010_import.py` 3건(pending 생성·중복·필지 연결 제안·파생본 시드·asset-confirm, 시드에 있는 ID 유지, 잘못된 파일은 정본 불변), `export.test.mjs` 1건(j5 inspect 오라클), `parcels.test.mjs` interiorPoint, `app.e2e.test.mjs` 필지에서 물건 만들기 절.
- 문서: ADR-21, 데이터 사전 §3.1, 릴리스 계획 J5-028, `j5/README.md`·`web/README.md`·`schemas/README.md`·`tests/README.md`, 색인(J5-027 PR #73).

## 데이터 사전에 없어 정한 값

- 기기 물건의 이름은 동·지번(`parcelTitle`), 위치점은 라벨 위치가 안이면 그것, 아니면 bbox 격자에서 찾은 안쪽 점(소수 7자리). 자료 종류는 설정의 data_mode(없으면 synthetic).
- `assets.new.json` 은 묶음마다 그 묶음의 기록이 가리키는 물건만(정렬은 asset_id). 파일 크기 한도는 manifest 와 같다. 반영기는 `seed_created_at` 에 기기 시각의 날짜를 쓴다.
- 확정은 사람이 `asset-confirm` 으로 한다. 자동 확정·자동 필지 연결은 없다.

## 테스트 명령과 결과 (2026-09-27, 컨테이너 Linux, Node 22, Python 3.12)

## 실제 작업 시간

약 1.7시간 (계약·검사·반영 0.6, 폰 저장소·화면·내보내기 0.6, fixture·테스트·문서 0.5).

## 미확인 변수

- 실제 임장에서 만든 물건이 PC 반영·파생본 왕복 뒤 기기 사본이 정리되는 흐름은 가상 패키지·브라우저로만 확인했다.
- 같은 필지에 두 번 만든 경우의 PC 병합 명령은 없다(후속). IndexedDB v5 업그레이드는 기존 v4 저장소에 스토어만 더한다(기록 유지).

## 남은 인수조건·후속 작업

- 사용자: 실제 필지 파일을 넣고 현장에서 물건을 만들어 기록 → 내보내기 → `db import`(pending 생성 확인) → `parcels-suggest/link` → `asset-confirm` → `project` → 폰에서 사본 정리 확인.
- 후속 후보: 기기 물건 병합·이름 편집 CLI, 이력 화면의 pending 표시, 지역지구 코드→이름 표.
- 자동 테스트 통과는 실기기 검증이 아니다.
