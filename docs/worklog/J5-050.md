# J5-050 운영 점검의 거래 응답 시군구 대조

기록일: 2026-09-29. 지번 대조(J5-044)와 범위 규칙(J5-048)은 거래의 시군구를 수집 요청 시군구(`lawd_cd`)로 본다. 실제 응답 행의 `sggCd` 가 요청 시군구와 늘 같은지는 확인하지 않은 채 남아 있었다(J5-044 미확인 변수). 실제 응답에는 `sggCd` 가 있다(J5-014 실측 필드 22개). 정본에 반영한 응답 행은 그대로 보존되므로 사용자 PC 에서 바로 대조할 수 있게 한다.

## 결과

- `j5/db/ops.py`(읽기 전용 그대로)
  - `transaction_sgg_summary`: 정본 거래마다 최신 응답 행의 `sggCd` 를 요청 시군구와 대조해 같음·다름·응답에 없음(빈 값) 수와 다른 거래의 요청→응답 시군구별 수를 낸다. `sggCd` 는 식별 필드라 한 거래 안에서 바뀌지 않으며, 같은 달을 다시 받아도 거래마다 한 번 센다.
  - `ops-check` 결과 `transaction_sgg` 와 글 줄 "거래 응답 시군구: 요청과 같음 … · 다름 … · 응답에 없음 …".
  - 다른 거래가 있으면 안내를 낸다. 고칠 명령이 없으므로 조치 항목으로 두지 않고 점검은 통과한다. 이 줄을 공유하면 대조 규칙을 검토한다.
- 시험 `tests/test_j5_050_ops_tx_sgg.py` 1건. 고치기 전 코드에서 실패함을 확인했다.
- 문서: 릴리스 계획 §10 J5-050, `j5/README.md`, `tests/README.md`, 색인(J5-049 #96).

## 데이터 사전에 없어 정한 값

- 응답 행의 `sggCd` 가 비었거나 공백이면 "응답에 없음" 으로 따로 센다. 같음으로 보지 않는다.
- 대조는 정본에 반영한 거래만 본다. 받아 두고 반영하지 않은 실행은 J5-042 의 "반영 대기 수집" 이 따로 알린다.
