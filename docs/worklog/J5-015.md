# J5-015 이력·목표 매수가·판단 (R4)

기록일: 2026-09-25. 첫 조각 **A**: 목표 매수가·투자판단 기록 종류와 당시 기록 기준(K) 조회. 사후 정보 혼입 방지가 완료 조건(릴리스 계획 §10·§8). 둘째 조각 **B**: 사진 연차 비교(같은 촬영 지점의 사진 시계열).

## A. 결과

- db_schema 9 `r4_record_types`: `records.record_type` 에 `target_price`·`investment_judgment` 를 허용한다. CHECK 가 표 정의에 박혀 있어 표를 다시 만들었다(새 표 생성 → 복사 → 옛 표 삭제 → 이름 바꾸기 → 인덱스·트리거 재생성). 저장소의 마이그레이션 실행기가 외래키 검사를 끈 채 한 트랜잭션으로 실행하고 `foreign_key_check` 가 비어야 커밋한다(ADR-14). 마이그레이션 1 의 문구는 그대로 두었다(`RECORD_TYPES_V1`).
- payload 계약 `schemas/judgment_records.schema.json`: 목표 매수가(가격 종류 target_buy/walk_away/reference, 원 단위 가격, 판단일, 전략, 구성 기준일, 비용·규제 전제, 비교 근거, 유효 조건, 수정 사유)와 투자판단 10항목(status draft/formal, decision none/approved/withdrawn; formal 은 10항목 모두, 승인은 formal 만). 입력 파일(`kind: record`)에 물건·종류·자료 종류·판단일·이전 기록·근거 문서를 둔다.
- `j5 db record-add <입력.json>`: 불변 기록으로 넣는다. 수정은 새 기록 + `supersedes_id`(같은 물건·같은 종류, 이미 수정된 기록은 다시 가리킬 수 없음, 목표가 수정은 사유 필수, 승인 철회는 이전 기록 필수). 근거 문서는 `source_documents` 에 먼저 있어야 한다. 정본 반영 시각은 저장소가 부여한다.
- `j5 db asof --asset <id> --at T [--known-by K | --as-recorded]`: 시점 T 의 상태 재구성. 관측 기준은 현재 보유 근거 전부, 당시 기록 기준은 정본 기록일 ≤ K 인 기록·연결·검토 결정·거래·관측만 쓴다. 현장 관측(마지막 확인일), 목표 매수가(이력 수), 투자판단, T 에 유효한 구성 필지(도형 기준일이 T 뒤면 "현재 경계 위의 과거 속성"), 확정 연결 거래(계약일 ≤ T, 연결 상태는 K 이하의 검토 결정으로 재구성, 취소 표시는 K 이하에 기록된 관측에만).
- 테스트 `tests/test_j5_015a_judgment.py` 5건: 버전 8 정본(기록·근거·첨부·수입 대장 있음)을 열 때 표 재작성 뒤 행·외래키·트리거·인덱스 보존과 새 종류 삽입, 실패한 재작성의 되돌림과 외래키 재활성, 입력 검증·수정 체인·불변, 관측 기준/당시 기록 기준 조회(나중에 넣은 정정·연결 철회·과거 거래·취소 표시가 K 당시 보기에 들어가지 않음, T 뒤 판단은 T 상태를 바꾸지 않음, 경계 기준일 주의), CLI.

## B. 결과 (사진 연차 비교)

- 폰 앱: 사진마다 촬영 지점(`viewpoint_id`, 1~100자)·방향(`heading_deg`, 0 이상 360 미만)·이전 사진(`previous_photo_sha256`, 이 기기에 저장된 같은 물건의 사진 중 선택)을 선택 입력한다. 관측 이벤트 스키마에 이미 있던 선택 필드다. 값이 있을 때만 `attachment_refs` 에 키를 넣으므로 기존 이벤트의 정규화 바이트는 바뀌지 않는다. 이전 사진을 고르면 그 사진의 촬영 지점을 미리 채운다(비어 있을 때만).
- db_schema 10 `r4_photo_series`: `attachments` 에 세 열을 붙이고, 이미 반영된 첨부는 수입 대장(`import_events.line`)의 행 바이트에서 소급해 채운다(같은 기록·같은 sha256). 저장소는 열 범위·자기 자신 참조·빈 촬영 지점을 거절한다.
- `j5 db photo-series --asset <id> [--tag TAG] [--export] [--json]`: 물건의 사진을 촬영 지점 → 이전 사진 사슬 → 태그 조합 순으로 묶고, 묶음마다 연도별 첫 사진·인접 연도 비교 쌍·빠진 해를 낸다. 관측하지 않은 해는 비워 두고 보간하지 않는다. 정정된 관측의 사진은 `superseded` 로 표시하고 지우지 않는다. `--export` 는 `exports/private/photo_series/<물건>/<묶음>/<날짜>-<sha8>.<ext>` 로 해시 검증 복사하고 `index.json` 을 쓴다(덮어쓰지 않음, 다른 내용이면 문제로 보고). 파생본 `records.jsonl` 의 첨부에도 값이 있을 때만 세 필드가 들어간다.
- 테스트 `tests/test_j5_015b_photos.py` 4건(스키마 10·소급 채움·저장소 검증, 묶기·비교·태그 필터·정정 표시, 내보내기의 해시 검증·건너뜀·덮어쓰기 거절·파생본, CLI), `tests/web/event.test.mjs` 1건(키 생략·바이트 불변·거절 규칙), e2e 확장(두 번째 관측에서 촬영 지점·방향·이전 사진 선택 → IndexedDB 덤프의 이벤트 확인 → `j5 inspect` ok, 첫 이벤트에는 선택 키 없음). 기존 테스트의 스키마 버전 상수는 도구 버전에 상대화했다.

## 데이터 사전에 없어 정한 값

- 기본 당시 보기는 K=T(`--as-recorded`). K 는 날짜이며 그날 23:59:59Z 까지 기록된 것을 포함한다.
- 정정·수정 기록은 그 판단일(관측일)이 T 이하일 때만 원 기록을 대체한다. T 뒤에 내린 수정은 T 의 상태를 바꾸지 않는다.
- 거래 연결의 당시 상태는 `review_decisions` 를 K 까지 순서대로 따라간 마지막 결정이다. 거래 행 자체도 K 이하에 반영된 것만 본다(나중에 소급 수집한 과거 거래 제외). 취소 표시는 K 이하에 기록된 원본 관측에 `cdealType` 표시가 있을 때만 "취소 표시 있음" 으로 보인다.
- 목표 매수가의 `composition_as_of` 는 가정한 물건 구성의 기준일이며 그 날짜의 `asset_components` 를 뜻한다. 별도 버전 번호를 두지 않는다.
- 사진 묶음 순서: 1) 명시한 `viewpoint_id`, 2) `previous_photo_sha256` 로 이어진 사슬(이전 사진의 묶음을 잇는다. 정정되지 않은 첨부의 묶음을 우선), 3) 나머지는 태그 조합. 같은 사진이 정정 전·후 관측에 모두 붙을 수 있어 묶음은 사진 해시가 아니라 첨부(기록+사진) 단위다.
- 연차 비교 쌍은 묶음 안의 연도별 첫 사진(촬영 시각, 없으면 관측 시각 기준)끼리 인접 연도로 만든다. 빠진 해는 목록으로만 표시한다.
- 촬영 지점은 자유 문자열 1~100자(폰의 입력 상한 `VIEWPOINT_MAX`), 방향은 진북 기준 도(0 이상 360 미만)로 두며 기기 나침반을 읽지 않는다(수동 입력).
- 폰 화면의 당시 보기, 반대 증거·변경 조건 알림은 B 이후.

## 공수

- 예상(J5-015 전체) 32~48시간(R4 예산). A 실제 약 2.5시간(표 재작성 검증 포함). B 실제 약 2시간(폰 입력·마이그레이션·CLI·e2e).
