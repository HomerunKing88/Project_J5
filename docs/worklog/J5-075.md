# J5-075 파생본 검사의 PC·폰 일치

기록일: 2026-10-14. 사용자 지시: "머지하고 다음 작업 진행". PR #120(J5-073)이 머지된 뒤 달린 리뷰 "`kind_months_any` 가 `null` 이면 PC 게시 전 확인은 받고 폰 검사는 거절한다" 를 별도 작업으로 반영했다(PR #120 답글에 적은 대로).

## 결과

- `j5/db/projection.py` 게시 전 확인
  - 수집 개월의 `kind_months`·`kind_months_any`: 칸이 없으면 이전 형식으로 받고, 칸이 있는데 `null` 이면 거절한다(지금까지는 `c.get()` 이 `null` 과 칸 없음을 같게 봐서 받았다). J5-065 의 `kind_months` 도 같은 차이가 있어 함께 고쳤다.
  - 같은 갈래를 살피다 찾은 차이: 토지 지목 `land_category` 가 글자·`null` 이 아니면 폰은 거절하고 PC 는 보지 않았다. 거절한다. `deal_kind` 가 목록처럼 글자가 아니면 PC 가 형식 오류 대신 파이썬 오류로 멈출 수 있었다. 글자가 아니면 거절한다.
- `docs/DATA_DICTIONARY.md` §7.1: 두 칸은 있으면 `null` 이 아니라 객체.
- 폰 검사는 이미 같은 규칙이다. 시험에 `null` 갈래를 더했다.
- PC 생성기는 이 칸에 `null` 을 쓰지 않는다. 이미 만든 파생본에는 영향이 없다. 앱 변경 없음(앱 버전 그대로).
- 시험: `tests/test_j5_065_rt_kinds.py` 게시 전 확인 거절 4가지(`kind_months` null, `kind_months_any` null, `land_category` 숫자, `deal_kind` 목록), 칸이 없는 이전 형식은 그대로 받음. `tests/web/view.test.mjs` 폰 검사의 `null` 거절. PC 시험은 고치기 전 코드에서 실패한다.
