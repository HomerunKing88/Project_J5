# J5-047 폰 필지 연도별 요약

기록일: 2026-09-28. J5-045 는 PC 에서 필지마다 연도별 공시지가·거래 수·수집 개월을 표로 낸다. 폰 필지 이력은 항목을 연도별로 묶어 보였지만, 거래가 없는 연도를 모두 빠뜨렸다. 그 연도가 거래 0 건인지, 수집하지 않은 연도인지도 가를 수 없었다. 폰 파생본에는 수집 현황과 범위 규칙이 없었기 때문이다.

## 결과

- PC 파생본 `transactions.json`(형식 1.0.0 그대로, 키 추가):
  - `zone_rule`: 현재 범위 규칙의 판·핵심·비교 법정동 이름 목록. 거래 목록은 핵심·비교 범위만이므로, 폰이 범위 밖 법정동 필지의 거래 수를 모름으로 두는 근거다.
  - `coverage`: 시군구·연도별 수집 개월 `[{lawd_cd, year, months_complete, months_any}]`. `months_complete` 는 complete/empty 인 달, `months_any` 는 실행이 있는 달이다. `j5/db/transactions.py` `coverage_by_year`·`coverage_rows`(J5-045 의 계산을 옮겨 PC `parcels-years` 와 같이 쓴다).
  - 게시 전 확인(`verify_projection_dir`)이 두 키의 형식을 검사한다. 시군구 5자리, 연도, 수집 개월 0~12, 완전 ≤ 전체, 중복 없음을 본다. 두 키가 없는 이전 파일은 통과한다.
- 폰 `web/app/view.js`:
  - `validateTransactionsDoc` 가 두 키를 검사한다.
  - `parcelYearSummary(feature, items, txDoc, prices)` 는 최근 연도 먼저 연도마다 한 줄을 만든다. 그 연도 기준 공시지가·전년 대비, 필지 이력 규칙의 같은 필지·번지대·연결 거래 수, 그 필지 시군구(PNU 앞 5자리)의 수집 개월이 들어간다. 최근 20개 연도까지다.
  - 거래 수의 상태는 다섯 가지다.
    - `counted`: 그해 거래가 있거나 완전 수집한 달이 있다. 수는 센 값이다.
    - `not_collected`: 실행이 없다.
    - `incomplete`: 실패·부분 수집만 있다.
    - `outside`: 거래 범위 밖 법정동이다.
    - `unknown`: 거래 파일이나 수집 현황이 없다.
  - `counted` 가 아니면 수는 null 이고 화면에는 사유를 적는다.
  - `yearSummaryRow` 가 한 줄 글을 만든다.
- 폰 화면: 필지 이력(`#sec-history`) 위에 "연도별 요약" 목록(`#history-years`)과 안내를 둔다. 물건 이력에는 보이지 않는다. 표시 기준의 번지대 설명을 "지번 일부가 가려진 거래" 로 고쳤다(J5-043 에서 자릿수 마스킹도 번지대로 잡는다). 앱 0.2.17, 캐시 v0.2.17.
- 시험
  - `tests/test_j5_047_year_summary_data.py` 1건: 수집 개월(실패한 달은 전체에만), 범위 규칙, 파생본 파일의 두 키, 해시를 맞춘 변조 4종 거절, 이전 형식 통과.
  - `tests/web/view.test.mjs` 1건: 수집했고 거래 없는 해는 0, 미수집·실패·범위 밖·파일 없음·이전 형식, 다른 시군구 수집 현황은 쓰지 않음, 전년 대비, 최근 연도 제한, 형식 검사.
  - `tests/web/app.e2e.test.mjs`: 가상 파생본에서 필지 1 의 연도별 요약 두 줄(2026 은 수집했고 이 필지 거래가 없어 0, 2025 는 같은 필지 1·번지대 1)과 물건 이력에서 숨김.
  - 새 기능이라 고치기 전 코드와 비교할 동작은 없다.
- 문서: 릴리스 계획 §10 J5-047, `j5/README.md`, `web/README.md`, `tests/README.md`, 색인(J5-046 #93).

## 리뷰 반영 (PR #94, Codex 1건)

- P2 거래 0 건일 때의 수집 개월: 범위 거래가 하나도 없으면(수집했고 결과 없음·범위 밖·취소만) `transactions.json` 을 만들지 않아, 폰이 수집 개월을 받지 못하고 "수집 현황 모름" 으로 보였다. 범위 규칙이 있고 수집 기록이 있으면 빈 거래 목록과 수집 개월을 싣는다. 게시 전 확인은 "거래가 있으면 파일이 있어야 한다" 로 바꿨다(파일의 건수는 manifest 와 같아야 한다). 수집 기록도 거래도 없으면 이전처럼 파일이 없다. 시험 1건 추가(고치기 전 코드에서 실패함을 확인).

## 데이터 사전에 없어 정한 값

- 연도별 요약의 공시지가는 공시지가 추이(J5-030 `priceTrend`)의 기준연도로 정한다. 같은 기준연도에 값이 바뀌었으면 나중 값이다.
- 수집 개월은 필지 PNU 앞 5자리 시군구의 것만 쓴다(J5-044 규칙과 같다).
- 거래 범위 판단은 범위 규칙의 법정동 이름 목록으로 한다(정본 `classify` 와 같다).
