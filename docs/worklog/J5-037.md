# J5-037 PC 조건으로 필지 찾기

기록일: 2026-09-28. 폰 조건 찾기(J5-033·036)는 결과를 50개까지만 목록으로 보인다. 실제 3구역 2,707필지에서 후보를 고르고 비교하려면 PC 에서 같은 조건으로 전체 목록을 받아 표로 보는 편이 낫다. 같은 규칙을 PC 명령으로 옮겼다. 정본에 쓰지 않는다.

## 결과

- `j5/db/parcel_find.py`(새):
  - `zone_category`: 폰 `zoneCategory` 와 같은 이름 규칙. 공백을 빼고 위에서부터 포함 여부를 본다.
  - `check_criteria`: 음수·거꾸로 된 범위·목록에 없는 분류·빈 조건을 거절한다.
  - `find_parcels(db, criteria, on_date)`:
    - 규칙은 폰과 같다. 조건은 모두 만족해야 하고, 결측은 켠 조건마다 따로 센다. 결측만 있고 확인된 불일치가 없는 필지는 판단 불가로 센다. 정렬은 공부면적 큰 순이다.
    - 물건 조건의 기준은 기준일(기본 오늘)에 유효한 정본 연결 또는 위치점 포함이다. 물건마다 근거(`linked`·`inside`·`both`)를 적는다.
  - `find_text`: 화면용 글이며 `--limit` 줄까지 보인다.
  - `find_csv`: 전부를 담고 결측은 빈 칸으로 둔다.
- CLI `db parcels-find`: 공시지가는 만원/㎡ 로 받아 원/㎡ 로 바꾼다. `--csv` 는 덮어쓰지 않고 폴더가 없으면 거절한다. 잘못된 조건이면 종료 코드 3 이다.
- 시험 `tests/test_j5_037_parcels_find.py` 6건. 폰 시험(`parcels.test.mjs` J5-033·036)과 같은 가상 번들·조건에서 같은 결과가 나오는지 대조한다.
- 문서: 릴리스 계획 §10 J5-037, `j5/README.md`, `tests/README.md`, 색인(J5-036 #83).

## 데이터 사전에 없어 정한 값

- CSV 열: pnu, parcel, use_zone_1, zone_category, registered_area_m2, official_land_price_krw_m2, price_base_year, price_base_month, ownership_kind, restricted_codes(공백 구분), assets(수), watchlist_assets(수), asset_ids(공백 구분), attrs_as_of. 결측은 빈 칸이다.
- 물건 조건의 기준일 기본값은 오늘(UTC)이다. 폰은 파생본의 연결을 쓰므로 파생본 생성일 기준이다.

## 재작업

## 미확인 변수

- 실제 2,707필지 정본에서의 실행 시간을 재지 않았다. 필지마다 물건 위치점을 경계 상자로 먼저 거르므로 물건 수십 개면 짧을 것으로 보지만 실측이 필요하다.

## 남은 인수조건·후속 작업

- 사용자(PC): 실제 정본에서 `j5 db parcels-find --zone com --area-min 300 --assets none --csv ~/J5_DATA_HOME/exports/후보.csv` 처럼 후보 목록을 받는다(폴더는 미리 만든다). CSV 는 실데이터이므로 실데이터 홈에만 둔다. 이어서 실행 시간을 적는다.
