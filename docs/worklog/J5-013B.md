# J5-013B 필지 경계·지번 지도 (B-1), 정본 필지·물건 구성 (B-2)

기록일: 2026-09-23. J5-013 의 B 부분(필지·건축물) 첫 조각. 사용자 요구 "최소한 필지 구분과 번호가 지도에 있어야 필지별 자료를 넣을 수 있다" 에 대한 구현. ADR-13.

## 리뷰 반영 (PR #41, Codex 5건)

- P1 구멍 소속: Shapefile 링 순서에 기대지 않고 구멍의 꼭짓점을 품는 가장 작은 외곽에 붙인다. 어느 외곽에도 안 들어가는 반시계 링은 외곽으로 취급한다(버리지 않음). 테스트: 구멍이 먼저 오거나 다른 외곽 뒤에 오는 경우, 고아 링.
- P1 ZIP 누적 크기: 읽기 전에 .shp/.dbf/.prj/.cpg 의 선언 크기 합계(상한 1200MB)와 압축비(해제 1MB 초과 시 200배 초과 거절)를 검사한다. 테스트: 합계 상한, 0 으로 채운 .dbf 의 압축비.
- P2 출력 원자성: 같은 폴더의 임시 파일에 쓰고 다시 읽어 검증한 뒤 `os.replace` 로 교체한다. 검증 실패·중단은 최종 이름 파일을 남기지 않아 재시도가 `exists` 로 막히지 않는다.
- P2 지리좌표 면적: 원본이 경위도(EPSG 4326·4737·4162)이면 `area_m2_geom` 을 `null`, `area_missing_reason` 을 `source_geographic_crs` 로 둔다(스키마·폰 검증기·패널 표시 함께 변경). 0 으로 표시하지 않는다.
- P2 `--max-features`: 계약 상한 8,000 을 넘는 값은 거절하고, 상한에서 넘치면 "범위를 좁힌다" 로만 안내한다.

## 실행 환경에서 확인한 것

- 이 세션의 실행 환경은 nsdi.go.kr·data.go.kr·vworld.kr 에 접속할 수 없어(프록시 차단) 연속지적도 원본을 받지 못했다. 실제 파일 변환은 사용자 PC 에서 하거나 사용자가 파일을 전달해야 한다.
- 좌표계 변환 정확도: pyproj 3.7.2(PROJ 9) 를 별도 환경에 설치해 기준값을 만들고 EPSG 5186·5181·5179·5185·5187·5174·5175·5176 의 5점씩 대조. 최대 차이 0.0001 m 미만. pyproj 는 저장소 의존성에 넣지 않았다.

## 데이터 사전에 없어 정한 값

- 번들 파일 이름 `<이름>.j5parcels.json`, 형식 버전 `j5parcels 1.0.0`, `data_mode` 는 `synthetic | real`(연속지적도는 공공 자료라 `private_real` 이 아니지만 조사 범위를 드러내므로 저장소·공개 배포 밖).
- PNU 19자리(시도2·시군구3·읍면동3·리2·산1·본번4·부번4). 라벨은 PNU 에서 만든 `본번[-부번]`(산이면 `산` 접두), JIBUN 원문은 `jibun_raw` 로 보존하고 번호가 다르면 `jibun_mismatch=true`(PNU 우선). 지목은 JIBUN 끝 글자.
- 같은 PNU 의 여러 레코드는 MultiPolygon 한 필지로 합친다. 범위 판정은 필지 bbox 와 범위 bbox 의 교차(도형 자르기는 하지 않는다). 좌표는 소수 7자리. 상한 8,000 필지(`--max-features`).
- 좌표계는 .prj 를 알려진 EPSG 표(5173~5188·4326·4737·4162)와 대조해 확정하고 실패하면 `--crs` 를 요구한다. 잘못된 좌표계를 지정하면 조용히 어긋난 위치를 만들지 않도록 `inspect` 의 WGS84 bbox 를 확인하게 안내한다(범위 밖이면 0개).
- 인코딩은 `--encoding` > `.cpg` > .dbf 언어 구동기 바이트 > cp949.
- 폰: 필지 경계 로컬 단위 `2^28`(세계 좌표 기준, 북위 37.6° 에서 약 0.12 m), 라벨 최소 폭 24px 또는 글자 수×7px, 선택 필지 라벨 항상 표시, 선택 강조 채움. 필지 안 물건은 위치점의 다각형 포함(구멍 제외)으로 찾는다.

## 공수

- 예상(J5-013B 전체) 8~12시간. B-1 실제(세션 기준) 약 2시간. 재작업: 라벨 중심 계산을 첫 꼭짓점 기준 상대 좌표로 바꿈(절대 경위도의 상쇄 오차), pyproj 기준값을 손으로 옮기다 틀려 계산 결과를 그대로 상수로 넣음.

## 미확인 변수·남은 인수조건

- 실제 연속지적도 파일: 배포처(국가공간정보포털 오픈마켓 또는 공공데이터포털)의 이용허락 유형, 실제 .prj 유무·좌표계(5186 또는 5174), DBF 필드명(PNU·JIBUN 가정), 종로구 파일 크기. 사용자가 받아서 `j5 parcels inspect` 결과를 확인한 뒤 변환한다.
- 실기기 성능: 가상 6필지만 시험했다. 실제 범위(수백~수천 필지)의 렌더링·핀치 반응은 실기기에서 확인한다. 느리면 범위를 좁히거나 라벨 층을 줄인다.
- 정본 `parcels`·`asset_components`·PNU↔asset_id 연결·파생본 포함(J5-013B-2), 건축물대장(J5-013B-3)은 별도.
- 라벨 겹침·오목 필지의 라벨 위치(면적 중심이 밖으로 나갈 수 있음)는 처리하지 않았다.

# J5-013B-2 정본 필지·물건 구성

기록일: 2026-09-23. B-1 의 번들을 정본에 반영하고 물건(asset)과 필지(PNU)를 잇는다. 데이터 사전 §2 parcels / asset_components, §6.

## 결과

- db_schema 5 (`r2_parcels`): `parcels`(subjects 의 parcel 자식. PNU 외부 ID 와 parcel_id 내부 UUID 분리, 공부면적·도형면적을 각각 null + 사유로, `geometry_json`(EPSG:4326)·`source_crs`·`geometry_version`·`address_status`·출처 문서 참조·내용 해시), `asset_components`(물건 ↔ 필지/건물, 적용 기간, 연결 근거 `manual | location_point`, 복합 외래키).
- `j5 db parcels-load <번들>`: PNU 기준 반영. 같은 내용은 변화 없음, 더 새로운 도형 기준일이면 갱신(parcel_id 유지), 같은 기준일·다른 내용과 더 오래된 기준일은 거절(전체 롤백). 번들 data_mode(synthetic/real)와 정본(synthetic/private_real)이 맞아야 한다. 반영한 번들은 `source_documents`(official_file, SHP 해시·이용허락·기준일)로 남기고 필지 행이 참조한다.
- `j5 db parcels-suggest [--out 파일] [--effective-from]`: 물건 위치점을 품는 필지(구멍 제외)를 찾아 연결 제안 파일(`schemas/asset_components_input.schema.json`, basis `location_point`)을 만든다. 정본에 쓰지 않는다. 이미 유효한 연결은 제외하고 위치점 없는 물건·필지 밖 위치점 수를 stderr 로 알린다.
- `j5 db parcels-link <파일>`: 검토한 연결 파일을 반영한다. 물건·필지가 정본에 있어야 하고, 같은 (물건, 필지, 시작일)은 종료일·근거·비고만 갱신한다. 날짜는 달력 검증.
- 파생본(J5-011)에 `parcels.geojson` 추가: 정본 parcels 전체를 폰 번들 형식(j5parcels 1.0.0)으로, 필지마다 `geometry_version` 과 생성일 기준 유효한 연결 물건 `asset_ids`. manifest `counts.parcels`, 검증기가 번들 스키마·필지 수·연결 물건의 목록 포함·생성 시각을 대조한다. 출처가 섞이면 `warnings` 에 적는다.
- 폰: 필지 파일 입력이 `parcels.geojson` 도 받는다. 필지 패널이 정본 연결(`asset_ids`)과 위치점 포함을 합쳐 근거 배지(정본 연결 / 위치점 포함 (연결 미확정) / 둘 다)로 보여 주므로 주소만 있는 물건도 연결되면 필지에서 관측을 시작할 수 있다.
- 테스트 `tests/test_j5_013b2_parcels_db.py` 7건(마이그레이션·행 수, 반영 4경로·거절·data_mode·출처 문서, 제안·반영·멱등·갱신·오류, 구멍·다중 조각 포함 판정, 파생본 parcels.geojson·검증기·출처 혼합, 백업·복구, CLI), 기존 테스트의 스키마 버전·행 수 기대값 갱신, `parcels.test.mjs` 연결 근거, e2e 파생본 형식 파일 로드 → 위치점 없는 물건 3 이 필지 4-2 패널에 "정본 연결" 로. 전체 pytest 221건, node 34건 통과.

## 데이터 사전에 없어 정한 값

- 필지 갱신 규칙은 도형 기준일 비교다(같은 기준일·다른 내용은 오류로 사용자 확인). 분할·합필 이력(`parcel_lineage`)은 R5 까지 두지 않으며 PNU 가 사라진 필지는 이 반영기가 지우지 않는다.
- 공부면적은 아직 수집하지 않으므로 `registered_area_m2 = NULL`, 사유 `not_collected`. 건축물대장 연계 시 채운다.
- 연결 근거 `basis`: `manual`(사용자 직접 확인) / `location_point`(위치점 포함 제안을 검토 후 승인). 제안 파일은 정본에 자동 반영하지 않는다(연결 검토 이력은 사용자의 파일 검토·반영 명령이다).
- 파생본 `parcels.geojson` 의 출처 요약은 가장 최근 도형 기준일의 출처이며 `file` 은 `j5.sqlite3 (정본 parcels)`, `dbf_sha256` 은 0 채움(정본에서 만든 파생본임을 뜻함).
- 폰의 `asset_ids` 는 파생본에서만 온다. 폰은 PNU↔물건 연결을 편집하지 않는다(R1a 원칙 유지).

## 공수

- 예상(J5-013B 전체) 8~12시간. B-2 실제(세션 기준) 약 1시간. 재작업: 필지 행이 참조하는 출처 문서를 필지보다 먼저 넣도록 반영기를 계획·적용 2단계로 바꿈(외래키 위반).

## 미확인 변수·남은 인수조건

- 실제 종로구 번들 반영·연결은 사용자 PC 에서 한다. 실제 물건의 위치점이 필지 경계 근처면 제안이 빗나갈 수 있어 검토가 필요하다.
- 건축물대장(J5-013B-3), 공부면적·지목 공식 자료 연계, 필지 분할·합필 이력은 별도.
