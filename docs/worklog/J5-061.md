# J5-061 연습용 자료 지우기와 주소의 인증키 거절

기록일: 2026-10-13. 공개 주소(`https://project-j5.j5map.workers.dev/`, J5-060)를 iPhone 에서 처음 쓰며 확인한 두 가지를 고친다.

- 사용자 의견: "저 가상의 물건들은 이제 없어도 되지 않을까?" 연습용 자료로 둘러본 뒤 앱에 든 가상 대상 5곳·필지 6개·윤곽을 한 번에 치울 길이 없었다. 대상 목록은 다른 목록 파일로 바꾸는 길뿐이었다.
- 배경 지도의 직접 입력에서 사용자가 `{key}` 자리에 인증키를 중괄호째 넣었다. 앱은 그 주소를 그대로 저장하고 저장 안내에 키가 든 주소를 그대로 보였다. 타일 84장은 모두 실패했다. 주소를 `{key}` 로 고치고 키를 인증키 칸에 넣은 뒤에는 VWorld 기본 지도가 보였다(사용자 화면 확인).

## 결과

- `web/app/db.js` `Store.clearSample()`: 가져온 자리가 `bundled_synthetic`(앱에 든 연습용 파일)인 대상 목록·필지·건물·도로 윤곽만 한 트랜잭션으로 지운다. 대상 목록을 지우면 `seed_source`·`seed_loaded_at` 도 지워 연습용 목록에 맞춘 필지 연결을 더 믿지 않게 한다. 기록·사진·이 폰이 만든 대상·PC 자료 파일·다른 파일에서 가져온 자료는 건드리지 않는다. 지운 종류를 돌려준다. `SAMPLE_SOURCE` 상수를 내보낸다.
- 설정 → 자료 가져오기에 "연습용 자료" 항목과 "연습용 자료 지우기" 버튼. 연습용 자료가 하나라도 있을 때만 보인다. 지운 뒤 안내에 지운 종류를 적고, 작업 공간의 자료 종류가 연습용이면 실제 자료로 바꾸는 곳을 알린다. 다시 보려면 시작하기의 연습용 자료로 둘러보기를 쓴다.
- `web/app/tiles.js` `validateTemplate`: 주소에 인증키처럼 보이는 값(UUID 형식, 32자 이상 이어진 영숫자)이나 `{z}`·`{x}`·`{y}`·`{key}` 밖의 `{ }` 가 있으면 다른 검사보다 먼저 거절하고 "키 자리는 글자 그대로 {key}, 키는 인증키 칸에" 를 안내한다(`KEY_IN_TEMPLATE_ERROR`). 오류 글에는 주소를 다시 적지 않는다. 이미 그렇게 저장된 폰은 앱을 다시 열 때 이 오류가 보이고 배경 타일을 요청하지 않는다.
- 앱 0.2.26 (`APP_VERSION`, `sw.js` 캐시, e2e 4곳: app 2·ux 1·deploy 2). `sw.js` 앱 파일 목록은 그대로.
- 시험
  - `tests/web/tiles.test.mjs`: 중괄호째 넣은 키, 그대로 넣은 키, 32자 영숫자, 모르는 자리표(`{zoom}`)가 모두 같은 안내로 거절되고, 안내 글에 키가 없음. 실제 키 대신 가상 UUID 를 쓴다.
  - `tests/web/ux.e2e.test.mjs` 13c: 파일에서 가져온 대상 목록이 있을 때는 연습용 필지·윤곽만 지우고 목록 2곳은 남음, 항목이 감춰짐, 지도의 필지 0, 연습용 대상 목록을 다시 넣고 지우면 대상 0과 작업 공간 안내, 저장한 기록 수는 그대로. 안내 칸은 live 영역.
  - 새 시험은 고치기 전 코드에서 실패함을 확인했다(단위: 거절 안내 없음, e2e: 연습용 자료 항목 없음).
- 리뷰 반영(PR #108)
  - 예전 판(0.2.25 까지)이 저장한 인증키 든 주소는 거절만 하고 입력 칸·저장소·타일 캐시(요청 주소에 키가 든 캐시 키)에 그대로 남았다. 앱을 열 때 저장된 주소에 키처럼 보이는 값이 있으면 그 주소(직접 입력이면 제공자 선택도)를 지우고, 타일 캐시에서 캐시 키에 키처럼 보이는 값이 든 것만 지운 뒤 다시 넣는 방법을 안내한다(`hasKeyLike`, 퍼센트 인코딩을 풀어서 본다).
  - 짝이 맞지 않는 `{`·`}`(예: `{token.png`, `token}.png`, `{{z}}`)가 검사를 빠져나갔다. 허용 자리표 네 개를 뺀 뒤 남은 괄호는 하나라도 거절한다.
  - 시험: 단위(짝 안 맞는 괄호 3가지, 캐시 키의 키 찾기), ux e2e 13d(키 든 주소와 타일 1장을 넣고 다시 열면 주소·제공자·그 타일만 지우고 다른 타일은 남김, 화면에 키 없음). 고치기 전 코드에서 실패함을 확인했다.
- ADR-24 보정 줄에 계정 하위 이름 변경(`j5map`)을 적었다(사용자가 Cloudflare 에서 바꿈, 주소에 사용자 이름이 드러나지 않게).

## 데이터 사전에 없어 정한 값

- 인증키처럼 보이는 값: UUID 형식 또는 32자 이상 이어진 영숫자. 타일 주소 경로에는 이런 값이 쓰이지 않는다고 본다.

## 테스트 명령과 결과 (2026-10-13, 컨테이너 Linux, Python 3.11, Node 22)

- `python -m pytest -W error::UserWarning` → 445 passed.
- `node --test --test-timeout=180000 "tests/web/**/*.test.mjs"` → 90 pass (헤드리스 Chromium e2e 포함).

## 실제 작업 시간

약 0.9시간 (추정: 원인 확인 0.2, 구현 0.3, 시험 0.2, 문서 0.2).

## 미확인 변수

- iPhone Safari 에서 연습용 자료 지우기 뒤 화면(시작하기가 다시 보이는지)은 실기기에서만 확인된다.
- VWorld 기본 지도의 주소 형식은 사용자 iPhone 에서 실제 응답으로 보였다(2026-10-13). 이용약관(출처 표시, 타일 저장·오프라인 사용 범위)은 아직 확인하지 않아 VWorld 미리 설정은 그대로 막아 둔다(ADR-18).
- 인증키가 대화 화면 캡처에 드러났다. VWorld 키는 등록한 서비스 URL 에서만 동작하지만 재발급을 권했다.

## 남은 인수조건·후속 작업

- 사용자(폰): 설정 → 자료 가져오기 → 연습용 자료 지우기를 누르고 대상 0 이 되는지, 저장한 기록이 남는지 확인한다. 배경 지도 직접 입력에서 주소는 `{key}` 그대로, 키는 인증키 칸에 넣는다.
- 필지를 직접 골라 메모하려면 필지 경계가 폰에 있어야 한다. PC 에서 VWorld 연속지적도를 `j5 parcels convert`(필지 파일만) 또는 `db parcels-ingest` → `db project` → `db project-copy`(대상·필지·거래 함께)로 만들어 폰에 넣는다. 그 뒤 필지 카드의 "이 필지를 대상으로 기록" 으로 메모한다(J5-028).
- VWorld 이용약관 확인 뒤 미리 설정을 열지 정한다.

각 명령의 세부는 `j5/README.md`, 폰 앱은 `web/README.md`.
