# J5-008 PC 검사·독립 사본

기록일: 2026-09-22.

## 결과

- `j5/` CLI: `inspect`(패키지 검사), `copy`(독립 사본). 표준 라이브러리 + jsonschema 4.23.0.
- 테스트: fixture 9종 × (폴더, ZIP), 적대적 ZIP(경로 탈출·절대경로·백슬래시·제어문자·중복 항목·심볼릭 링크·암호화 플래그·미지원 압축·manifest 외 파일·매직바이트 불일치·해시 파일명 불일치·헤더 크기 거짓·한도 초과), 이벤트 형식(CRLF·BOM·빈 행·중복 키·비UTF-8·자기 정정), CLI 종료 코드·ASCII 콘솔, 사본(덮어쓰기 금지·손상 감지·원본 불변).
- CI를 Python 3.11·3.12 matrix로 확장 (zipfile의 항목 겹침 검사가 버전에 따라 달라 스트리밍 한도가 실제 방어선).

## 순서 변경 결정

릴리스 계획 §10은 J5-005 → 006 → 007 → 008 순이지만, PC 검사 도구를 먼저 만들어 폰 내보내기(J5-007)의 기준 검사기로 삼는다. 근거: 기기 없이 CI로 완전 검증 가능하고, "지도 실패 시 목록·기록·내보내기를 제공한다"(AGENTS 구성 절)이므로 목록·기록·내보내기가 지도보다 먼저다. 이후 순서: J5-004 → 006 → 007 → 005 → 006A. 릴리스 계획 문서 본문은 고치지 않았다.

## 데이터 사전에 없어 정한 값 (계약 확정 시 사전 반영 필요)

- 이벤트 해시는 `observations.jsonl` 행 바이트에 끝의 LF 1개를 포함해 sha256 한다. J5-007 내보내기는 같은 규약을 따라야 한다.
- `max_photos=1000` (§3.3 "사진 수" 제한의 값). 항목 수 한도는 `max_photos + 3`.
- `manifest.json` 크기 한도 10MB.
- 허용 항목 이름은 `manifest.json`, `observations.jsonl`, `photos/<sha256>.<jpg|png|webp>` 뿐이며 그 밖의 파일·디렉터리는 거절. 압축 방식은 STORED/DEFLATED만.
- `observations.jsonl`은 LF 줄바꿈, BOM 없음, 빈 행 없음, 마지막 행 줄바꿈 필수, JSON 중복 키 거절.
- 판정 우선순위 reject > hold > ok. hold는 같은 event_id·다른 내용이 있을 때.

## 공수

- 예상: 6~10시간. 실제(세션 기준): 약 1.5시간. 실제 폰 ZIP 검사와 첫 임장 수집 시험은 포함하지 않았다.

## 미확인 변수·남은 인수조건

- "첫 임장 수집 시험"(§10 J5-008 완료 조건 후반)은 기기·현장 작업이라 이 PR에서 하지 않았다. J5-004·007 이후 실제 폰 ZIP으로 검사한다.
- 사용자 PC OS 미확인. 콘솔 출력은 인코딩 오류 시 이스케이프로 대체하도록 했고 JSON 출력은 ASCII다.
- `copy`는 같은 장치 여부만 알린다. 독립 위치 판단은 사용자가 한다.
