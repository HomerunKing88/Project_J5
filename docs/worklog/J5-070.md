# J5-070 PC 연도별 표의 종류별 수집 개월

기록일: 2026-10-13. 사용자 지시: "머지하고 다음 작업 진행". J5-065 에서 폰 연도별 표는 종류별 수집 개월(`kind_months`)로 "상업·업무만" 같은 메모를 붙였는데, PC `db parcels-years` 는 종류를 가리지 않은 개월만 보였다. J5-058 은 폰과 PC 가 같은 값을 내는지 대조하는 시험이라 이 값도 맞춘다.

## 결과

- `j5/db/parcel_years.py`
  - 줄마다 `rt_kind_months`: 종류마다 그해 완전히 받은 개월(1 이상만). 파생본 coverage 의 `kind_months` 와 같은 값이다(같은 `coverage_by_year(…, 종류)`).
  - CSV 끝 열 `rt_kind_months`(`nrg:12;land:1`, 없으면 빈 칸). 기존 열 순서는 그대로다.
  - 글: `kinds_note` 는 폰 `kindsOnlyText` 와 같은 규칙이다. 모든 종류를 같은 개월 받았으면 붙이지 않고, 받은 종류가 모두 같은 개월이면 "(상업·업무만)", 개월이 다르면 "(상업·업무 12 · 단독·다가구 1 · 토지 1개월)". 이름표 `KIND_SHORT` 는 폰 `DEAL_KIND_NAMES` 와 같다.
- 시험
  - `tests/test_j5_045_parcel_years.py`: 메모 규칙(빈 값·모든 종류·일부 종류·개월이 다름), 이름표가 폰과 같은지(`web/app/view.js` 를 읽어 비교), 행 값과 CSV 열. 상업·업무용만 받은 가상 정본의 글에 "(상업·업무만)" 이 붙는다(기존 기대값을 고쳤다. 폰 `app.e2e` 와 같은 동작).
  - `tests/test_j5_058_years_parity.py`: 수집한 해마다 폰 `kindMonths` 와 PC `rt_kind_months` 가 같은지, 비교가 한 번 이상 일어났는지.
  - 새 시험은 main(3dbee36) 코드에서 실패한다(별도 작업 폴더로 확인).
- 정본·파생본·폰 앱은 바꾸지 않았다(앱 버전 그대로, 캐시 고정값 시험 통과).
