# J5-063 지도의 실거래 표시

기록일: 2026-10-13. 사용자가 다른 서비스(빌딩 실거래가를 지도에 종류+금액으로 찍는 서비스)의 화면을 보이며 요구했다: "실거래 데이터를 누적하여 확인하는 기능도 필요하다. 매매 이력과 근처 매각 사례를 통해 가격 적정성 검토도 가능할 것이다." 순서는 사용자가 골랐다(폰 지도 거래 표시부터). 그 서비스의 주소는 이 작업 환경에서 접속이 막혀 보지 못했고, 사용자 화면만 참고했다.

## 결과

- `web/app/view.js`
  - `placeDeals(transactions, features)`: 지번이 온전히 같은 필지(`jibunMatch` exact)마다, 가린 지번은 번지대(시군구·법정동·가린 지번이 같은 것)마다 묶고, 불러온 필지에 닿지 않는 거래는 수만 센다. 번지대는 후보 필지 목록만 갖고 어느 필지인지 확정하지 않는다(AGENTS "마스킹된 거래를 추정으로 특정 PNU 에 확정하지 않는다").
  - `dealKind`(건물 용도 → 근린·업무·숙박·판매 등, 건물 정보 없이 대지만 있으면 토지), `unitPrice`·`dealValueText`(총액, 대지 평당, 연면적 평당. 1평 3.305785㎡. 지분 거래는 단가를 내지 않음, 면적이 없으면 사유), `dealDetailText`, `dealsSince`·`dealSince`(기간).
- `web/app/map.js` `setDeals(items)`: 실거래 꼬리표 층(종류 칸 + 값 칸, 번지대는 점선). 점 위쪽에 두고, 앞(최근 거래)의 꼬리표와 겹치거나 화면 밖이면 감춘다. 누르면 `onSelectDeal(id)`. 실거래를 켰을 때는 가격을 보려는 것이라 대상 점 위에 그린다(가린 대상은 필지 카드의 "이 필지의 대상" 에서 기록).
- 현장 지도
  - "실거래" 버튼: 거래 파일이 있고 필지가 있을 때만 보인다. 켜면 아래에 값(총액·대지 평당·연면적 평당)과 기간(1·3·5년·전체), 거래 수·번지대 수·지도 밖 수를 적은 줄이 나온다. 이 줄은 위 덮개로 재어 꼬리표가 그 아래에 놓이지 않는다. 켬·값·기간은 이 폰(`deal_view`)에 저장한다.
  - 필지 꼬리표 → 필지 카드(최근 거래·연도별 표, J5-055·057). 번지대 꼬리표 → 번지대 카드(거래마다 날짜·종류·총액, 대지·연면적과 평당, 건축연도, 지분, "필지 n곳 가운데 어느 필지의 거래인지 확정하지 않습니다"). 카드는 하나만 연다.
  - "전체 보기" 버튼 글을 "전체" 로 줄였다(`aria-label` 은 "전체 보기"). 390px 폭에서 버튼 네 개가 두 줄로 넘어가 지도가 좁아지고 대상 점이 필지를 덮어 앱 e2e 가 실패한 것을 확인하고 고쳤다.
- 연습용 거래: `web/data/transactions.synthetic.json`(가상 9건, PC 파생본 `transactions.json` 형식, 폰 검사기 통과). 온전한 지번 4필지, 가린 지번 `1-*`(후보 1·1-1), 불러온 필지 밖 `3*`, 지분 거래 1건. "연습용 자료로 둘러보기" 가 PC 자료 자리(`view`, 가져온 자리 `bundled_synthetic`)에 넣는다(PC 자료가 이미 있으면 넣지 않는다). 꼬리표가 대상 점을 덮으므로 저절로 켜지 않는다. "연습용 자료 지우기" 가 함께 지우고, 설정의 PC 자료 상태는 "연습용 거래 n건 (실제 거래가 아님)" 으로 적는다.
- 별도 수정(같은 PR): J5-063 에서 처음 쓴 CSS 클래스 `.seg` 가 기존 대상 목록 거르기(`#asset-filter.seg`)와 이름이 겹쳐 `deal-seg` 로 바꿨다(머지 전에 고침).
- 앱 0.2.28 (`APP_VERSION`, `sw.js` 캐시, e2e 5곳).
- 시험
  - `tests/web/view.test.mjs`: 종류·단가·사유 글, 기간 거르기, 연습용 거래·필지로 배치(필지별 최근 순, 번지대 후보 2필지, 지도 밖 1건, 다른 시군구 거래는 닿지 않음).
  - `tests/web/ux.e2e.test.mjs` 13f: 거래 없으면 버튼 감춤, 연습용 거래를 넣어도 꺼져 있음, 켜면 꼬리표 5개·번지대 1개·거래 수 줄, 대지 평당·전체 기간, 번지대 카드(2건, 필지 미확정 안내), 필지 꼬리표 → 필지 카드의 최근 거래, 다시 열어도 설정 유지, 끄기, 연습용 자료 지우기에 거래 포함. 실거래 줄의 버튼도 44px 터치 대상 검사를 통과.
  - 새 시험은 고치기 전 코드에서 실패한다(함수·버튼 없음).

## 데이터 사전에 없어 정한 값

- 1평 = 3.305785㎡. 단가는 거래 총액 ÷ (면적 ÷ 1평). 지분 거래는 단가를 내지 않는다.
- 기본 기간 5년. 기간의 기준일은 폰의 오늘 날짜다.
- 번지대 꼬리표 위치: 후보 필지들의 라벨 위치 평균(표시용, 정본에 쓰지 않음).

## 미확인 변수

- 실제 정본의 거래(종로 상업업무용, 수십~수백 건)에서 꼬리표 겹침 처리와 낮은 확대에서의 가독성은 실자료로만 확인된다. 겹친 꼬리표를 숫자 묶음으로 보여 줄지는 실사용 뒤 정한다.
- 지금 PC 수집은 상업업무용 매매뿐이다. 단독·다가구·토지 매매는 아직 없다(후속, 사용자 API 활용신청 필요).
- 사람이 확정 연결한 거래(필지와 지번이 닿지 않는 연결 물건의 거래)는 지도에 따로 찍지 않는다. 필지 카드에서는 지금처럼 보인다.
- 가상자료 시험이다. iPhone 실기기 확인이 아니다.

## 남은 인수조건·후속 작업

- 사용자(PC, 나중에): `db project` → `db project-copy` 로 거래가 든 PC 자료 파일을 만들어 폰에 넣고 실거래를 켠다.
- 후속(J5-064 후보): 대상·필지 카드의 "주변 사례"(같은 동·같은 종류·기간의 단가 중간값과 범위, 이 필지 공시지가 대비 배율, 이 필지의 매매 이력). 자동 추정가는 만들지 않는다.
- 후속: PC 수집에 단독·다가구·토지 매매 더하기.
