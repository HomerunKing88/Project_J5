# J5-023 PC 자료 파일 한 번에 가져오기·연도별 이력

기록일: 2026-09-27. J5-022(배경 층) 다음 순서. 사용자가 원한 "필지를 누르면 그 필지의 정보와 연도별 거래·기록" 을 위해, 폰이 PC 의 조회 파생본 `.j5view.zip` 을 직접 읽어(J5-011 이 미뤄 둔 항목) 물건·필지·정본 기록·거래를 한 번에 넣고, 물건·필지의 이력 화면을 연도별로 보인다(ADR-17, R4 의 조회 항목을 앞당김).

## 결과

- `web/app/unzip.js`(새): 파생본 ZIP 읽기. 중앙 디렉터리 파싱, PC 검사기(`j5/db/viewpkg.py`)와 같은 항목 이름 규칙(허용 목록·경로 탈출·절대경로·백슬래시·제어문자·`photos/` 외 디렉터리), 암호화·심볼릭 링크·중복·ZIP64 거절, 항목 수·선언 크기·실제 바이트 한도(파일 256MB·텍스트 항목 64MB·합계 256MB), STORED/DEFLATE(`DecompressionStream("deflate-raw")`) 해제, CRC·크기·manifest sha256 대조, manifest 에 없는 항목 거절. 사진 항목은 세기만 하고 읽지 않는다.
- `web/app/view.js`(새): manifest 검증(형식·버전·필수 파일·설정의 작업 공간·자료 종류 대조), `records.jsonl` 파싱, `transactions.json` 검증, 금액 표기(억·만), 제공자 지번 파싱·필지 대조(`exact`/`prefix`/null), 물건 이력(이 기기 관측 + 정본 기록 + 확정 연결 거래, 정본에 같은 record_id 가 있으면 정본 것으로 대체, 정정으로 대체된 기록 표시), 필지 이력(지번 일치 거래 + 부번 마스킹 거래 + 안의 물건 이력, 동 전체 마스킹 제외), 연도 묶음.
- `web/app/db.js` v4: `view` 스토어(manifest 요약·정본 기록·거래·가져온 시각). 기존 스토어·이 기기의 관측·사진은 그대로.
- `web/app/main.js`: 설정 자료 관리 맨 위 "PC 자료 파일 (한 번에 가져오기)"(`#view-file`·`#clear-view`·`#view-status`·`#view-note`): 읽기 → manifest 검증(설정과 다르면 거절, 설정이 비어 있으면 파생본 값으로 채움) → 시드·필지·기록·거래 검증 → 물건 목록·필지 교체, view 저장 → 화면 갱신. 이력 화면 `#sec-history`(role=dialog, 제목 포커스, Esc·닫기, 되돌릴 포커스): 대상 카드의 "이력", 지도 선택 카드의 "이력", 필지 패널의 "이 필지 이력" 에서 연다. 항목은 날짜·종류 배지·(물건 이름)·이 필지/번지대/확정 연결·이 기기/정본 배지·내용·법정동 지번. 물건 이력에서는 "이 물건 기록 시작". 정본 버전·PC 생성 시각·가져온 시각을 보이고 "더 새 정본이 있는지는 PC 에서 확인" 을 붙인다. 앱 0.2.3, SW 캐시 v0.2.3.
- `web/index.html`·`web/styles.css`: 설정 블록, 선택 카드 버튼 두 개(`.selected-actions`), 필지 패널 버튼, 이력 화면·타임라인·배지 스타일, 카드의 조용한 "이력" 버튼(터치 44px).
- `tests/fixtures/make_view.py`(새): 임시 실데이터 홈에 가상 정본(시드 5 → 관측 패키지 반영 → 가상 필지 6 반영·위치점 연결 → 가짜 서버(127.0.0.1)로 가상 실거래 2개년 7건 수집·반영 → 범위 규칙 → 거래 1건 확정 연결 → 목표 매수가 기록) 을 만들고 `j5 db project` 로 `.j5view.zip` 을 지정 폴더에 낸다. 생성 시각·run_id 가 들어가 바이트가 매번 다르므로 저장소에 넣지 않고 시험 때 만든다.
- 테스트: `tests/web/unzip.test.mjs`(4건: 이름 규칙, 정상 ZIP(DEFLATE·STORED·사진 건너뜀), 적대적 ZIP 10종, 실제 파생본), `tests/web/view.test.mjs`(5건), `app.e2e.test.mjs` 에 PC 자료 파일 절(다른 정본 거절 → 설정 맞춘 뒤 가져오기 → 안내·필지 정본 연결·이 기기 기록 보존 → 물건 이력(연도·항목·배지·포커스·Esc) → 필지 이력(이 필지·번지대·동 전체 마스킹 제외·기록 시작 없음) → 재접속 유지 → 지우기 뒤 물건·필지·기록 유지). 대상 카드에 버튼이 둘이 되어 기존 선택자를 `#asset-list li > button` 으로 바꿨다.
- 문서: ADR-17, 릴리스 계획 §10 J5-023 행, `web/README.md`, `tests/README.md`, `j5/README.md`(project-copy → 폰), 색인(J5-011 비고).

## 유지한 계약

- 파생본 형식·manifest(`view_manifest.schema.json`)·PC 검사기는 바꾸지 않았다. 폰은 읽기만 한다.
- 이벤트 바이트·해시·ZIP 내보내기·IndexedDB 의 기존 스토어·내보내기 3단계·"내보냄 ≠ PC 반영" 은 그대로다. 파생본에 있는 관측에 "정본" 배지를 다는 것은 파생본에 들어 있다는 사실의 표시다.

## 테스트 명령과 결과 (2026-09-27, 컨테이너 Linux, Node 22, Python 3.12)

- `python -m pytest -q` → 전체 통과 (fixture 생성기는 e2e·단위 테스트에서 `python3 tests/fixtures/make_view.py` 로 실행).
- `node --test tests/web/*.test.mjs` → 64 pass, 0 fail (단위 + e2e 2개).
- 헤드리스 Chromium 390×844 캡처 7장(설정 블록, 물건 이력 라이트·다크, 필지 패널, 필지 이력 라이트·다크, 대상 카드)으로 배치·배지·문구를 확인했다. 파일은 세션 임시 폴더에 있고 저장소에는 넣지 않았다.

## 리뷰 반영 (PR #69, Codex 3건)

- P1 한 트랜잭션: 설정(비어 있을 때만)·물건 목록·필지·정본 기록·거래를 `Store.replaceProjection` 한 IndexedDB 트랜잭션으로 넣는다. 중간에 실패(용량 부족 등)하면 이전 상태가 그대로 남는다.
- P1 필지 삭제: 파생본에 `parcels.geojson` 이 없으면 기존 필지 기록을 같은 트랜잭션에서 지워, 옛 필지 도형이 새 물건·기록·거래와 섞이지 않게 한다. `make_view.py --no-parcels` 로 만든 파생본을 e2e 에서 확인.
- P2 대조: `transactions.json`·`parcels.geojson` 의 `study_id`·`source_dataset_version`·`generated_at`(거래는 `data_mode` 도)이 manifest 와 다르면 거절한다(PC 검증기와 같은 규칙, `checkProjectionConsistency`). 단위 테스트 추가.

## 실제 작업 시간

약 2.5시간 (파생본 형식·기존 코드 확인 0.4, fixture 생성기 0.3, ZIP 읽기·이력 조립 0.6, 화면·저장·연결 0.6, 테스트·캡처·기록 0.6).

## 미확인 변수

- iPhone Safari 에서 `DecompressionStream("deflate-raw")`(iOS 16.4 이상)과 큰 파생본(수만 거래·기록) 읽기 시간·메모리.
- 실제 정본의 `project-copy` 파일에는 사진이 들어 있을 수 있다(`--photos`). 폰은 읽지 않지만 파일 크기 한도(256MB)에는 들어간다. 크면 PC 에서 사진 없이 만든다.
- 제공자 지번 표기("1-*", "*")는 가상자료와 실측(J5-014)의 형식을 따랐다. 다른 표기가 나오면 `parseJibun` 이 null 을 내어 어느 필지에도 붙지 않는다(누락이지 오연결은 아니다).

## 남은 인수조건·후속 작업

- 사용자: Mac 에서 `j5 db project` → `project-copy` 로 만든 파일을 폰 설정의 "PC 자료 파일 선택" 으로 넣고 물건·필지 이력을 본다.
- 후속 후보: 이력에서 사진 썸네일(파생본 사진을 넣기로 하면), 목표 매수가·판단의 상세 보기, 거래 연결 검토 결과(근거 대기·후보)의 표시, R3 소급 수집으로 연도 축 채우기.
- 자동 테스트 통과는 실제 임장·실제 파생본 검증이 아니다.
