# J5-032 토지이용계획 이름 목록 정정: 코드와 위치로 짝짓지 않음

기록일: 2026-09-28. J5-025 의 후속 후보였던 "지역지구 코드→이름" 을 같은 자료 안에서 채울 수 있는지 실제 3구역 자료로 재보다가, J5-025 가 코드와 이름을 위치로 짝지은 결과가 틀릴 수 있음을 확인했다. 예를 들어 일반상업지역 코드(UQA220)가 371필지에서 '도시지역' 이름과 짝지어졌다. 폰에 "이름(저촉)" 으로 보이던 관계도 다른 규제에 붙을 수 있었다. ADR-19 에 정정으로 적고 고쳤다. 실제 자료는 작업 환경의 임시 폴더에서만 다뤘고 저장소에는 수치만 기록한다.

## 실측 (사용자 제공 VWorld 3구역 토지이용계획, 2,724행)

- 코드 목록(`prpos_area_dstrc_code_list`)과 관계 목록(`cnflc_at_nm_list`)은 모든 행에서 열 한도(254바이트)에 닿지 않았고 수가 1:1 로 같았다.
- 이름 목록(`prpos_area_dstrc_nm_list`)은 모든 행이 254바이트 한도에 닿아 잘렸다. 마지막 이름은 '지구단위계획구역(종로4' 처럼 중간에서 끊겼다.
- 모든 행에 같은 코드가 두 번 나온다(UQQ600 등). 401행은 이름도 중복된다(상대보호구역이 학교마다 따로 나옴). 이름 목록에 코드에 없는 항목이 끼어 순서가 밀리는 행이 있다. 코드 46종 가운데 위치로 짝지으면 이름이 둘 이상인 코드가 10종이었다(정비구역·지구단위계획구역처럼 같은 코드에 구역마다 다른 이름이 붙는 정상적인 경우도 섞여 있다).
- 새 규칙으로 다시 해석: 2,724행 모두 잘림 판정, 끊긴 조각이 남은 이름 0(괄호 짝 기준), 모든 코드에 관계가 붙음, 저촉·접함이 있는 필지 1,201개. 필지당 이름 중앙값 7개(2~9), 코드 중앙값 12개(8~22).

## 결과

- 파서(`j5/parcels/vworld.py` `_plan_attrs`): `plan_zones` 는 코드·관계 짝(이름 칸 null, 관계 수가 코드 수와 다르면 관계 null), `plan_zone_names` 는 자료에 적힌 순서 그대로의 이름 목록. 이름 목록의 바이트 길이가 .dbf 열 한도(3바이트 여유)에 닿으면 `plan_zones_truncated` 이고 끊긴 마지막 조각은 뺀다. `PLAN_PARSER_VERSION = "2"`.
- 계약(`schemas/parcels_bundle.schema.json`): `attrs.plan_zone_names`(문자열 배열, 100개·200자 상한), 토지이용계획 이력의 허용 필드에 추가. 옛 형식(이름이 코드에 붙은 J5-025 번들)도 그대로 받는다.
- 정본(`j5/db/schema.py` 마이그레이션 18, `j5/db/parcels.py`): `parcel_attributes.plan_zone_names_json`. 이름 목록이 비면 내용·스냅샷에서 키를 빼, 옛 번들을 다시 넣어도 헛된 갱신이 생기지 않는다. 옛 형식 값은 새 형식 번들을 같은 기준일로 다시 넣으면 속성 행 갱신·스냅샷 교체로 바뀐다. 파생본 필지 번들에 이름 목록이 실린다. PC 글(`parcels-history`)은 코드를 관계와 함께, 이름 목록은 따로 보인다.
- 묶음 넣기(`j5/db/ingest.py`): 번들 재사용 키에 해석 규칙의 판을 넣어, 옛 규칙으로 만든 번들을 다시 쓰지 않는다.
- 폰(`web/app/parcels.js` `planZonesText`, `index.html`): 규제·지역지구 한 줄은 "이름 목록 … (잘림 표시) · 코드 N개 (저촉 코드… · 접함 코드…)". 옛 형식 번들은 코드에 붙은 이름을 순서대로 쓴다. 이력 글의 코드 변화·이름 목록 변화, 검증 허용 필드. 안내 문구에 "이름은 코드와 짝지어진 것이 아님". 앱 0.2.11, SW 캐시 v0.2.11.
- fixture: 가상 VWorld 생성기에 실측 모양의 행(한 코드의 이름이 두 번 나와 순서가 어긋남)을 넣고 `synthetic_vworld.j5parcels.json` 을 다시 만들었다(재생성 바이트 동일).
- 테스트: `tests/test_j5_032_plan_names.py`(4건), `tests/web/parcels.test.mjs` 1건과 기존 기대값, J5-025·026·029·031·017a 의 기대값·구버전 흉내(새 열 제거)를 새 형식·db_schema 18 에 맞췄다.
- 문서: ADR-19 정정, 데이터 사전 §2, 릴리스 계획 §10 J5-032, 작업 기록 J5-025 에 정정 표시, `j5/README.md`·`web/README.md`·`schemas/README.md`·`tests/README.md`, 색인(J5-030·031 PR #76·#77·#78).

## 데이터 사전에 없어 정한 값

- 잘림 판정은 이름 목록의 UTF-8 바이트 길이가 열 길이에서 3바이트 안쪽이면 참이다(한 글자 최대 3바이트). 잘렸으면 마지막 이름을 뺀다(끊겼는지 모를 때도 뺀다).
- 코드와 이름은 어떤 경우에도 위치로 짝짓지 않는다. 폰은 포함이 아닌 관계만 코드로 덧붙인다.

## 리뷰 반영 (PR #79 머지 뒤 Codex 1건, 후속 PR)

- P1 옛 형식 번들이 정정된 이름을 지움: 이름 목록 키가 없는 J5-025 형식 번들을 반영하면 이름 목록이 비고 위치 짝이 되살아났다. 이제 옛 형식을 반영할 때 코드에 붙은 이름을 떼어 순서대로 이름 목록으로 옮기고(잘림 표시가 있으면 끊긴 마지막 조각은 뺀다), 같은 기준일에 정정된 이름 목록이 이미 있으면 그것을 지킨다. 더 새로운 기준일의 옛 형식 번들은 그 자료의 이름을 정규화해 쓴다. 폰의 옛 형식 표시도 같은 규칙이다. 시험 1건 추가, 옛 형식 흉내가 끊긴 조각을 포함하도록 고침.


약 1.6시간 (실측·원인 확인 0.4, 파서·계약·정본 0.5, 폰 0.3, 시험·fixture 0.3, 문서 0.1).

## 미확인 변수

- 이름이 코드보다 많은 이유(한 코드 아래 여러 지정, 코드 목록의 중복 방식)는 VWorld 자료 설명서로 확인할 항목이다. 여기서는 짝짓지 않는 쪽으로 안전하게 둔다.
- 코드→이름 공식 표(국토교통부 토지이용규제 지역지구 코드)는 여전히 후속 과제다. 표가 있으면 코드마다 이름을 붙일 수 있다.
