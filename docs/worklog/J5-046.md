# J5-046 여러 필지 거래 모으기 단축

기록일: 2026-09-28. J5-045 의 미확인 변수였던 "500필지 × 수십 개 연도의 `parcels-years` 실행 시간" 을 작업 환경에서 가상자료로 재고, 가장 큰 병목을 줄였다.

## 실측 (작업 환경 컨테이너, Python 3.11, 가상 정본)

- 자료
  - 가상 필지 10,000개: 한 시군구(99999)의 법정동 5개, 법정동당 2,000필지, 속성 포함.
  - 가상 거래 38,400건: 2016-01~2026-08, 월 300건. 지번은 온전·부번·자릿수 마스킹을 섞었다.
  - 실측 스크립트와 정본은 저장소 밖 임시 폴더에 두었고, 확인 뒤 정본을 지웠다.
- 준비 시간: 필지 반영 13.4초, 거래 수집·반영 12.8초.
- 고치기 전
  - `parcels-years` 100필지 9.25초, 500필지 47.2초.
  - 프로파일 결과(100필지 11.8초)에서 11.7초가 `parcel_transactions` 에 쓰였다.
  - 원인: 필지마다 같은 법정동의 거래 약 7,600건을 다시 읽고 지번을 다시 해석했다(100필지에 해석 76만 번).
- 고친 뒤
  - `parcels-years` 100필지 0.17초, 500필지 0.79초.
  - 필지 하나의 `parcels-history` 거래 모으기는 0.09초에서 0.17초가 됐다. 법정동 거래를 한 번 읽어 색인을 만드는 비용이다.
- 같은 결과 확인: 실측 정본에서 무작위 500필지(거래 항목 49,546건)를 고치기 전 코드와 대조해 목록·순서·수가 모두 같음을 확인했다.
- 가상자료 실측이며 실제 PC·실제 자료의 시간이 아니다.

## 결과

- `j5/db/parcel_timeline.py`
  - `parcels_transactions(db, pnus)`(새 함수): 법정동마다 거래를 한 번 읽고 지번을 한 번 해석한다. 온전한 지번은 (산, 본번, 부번), 마스킹 지번은 (산, 본번 자릿수) 색인을 만들어 필지마다 후보만 대조한다.
  - 수동 확정 연결 거래는 연결 물건 전체에 대해 한 번 읽는다.
  - 규칙(J5-043·044: 같은 필지·번지대·연결 물건, 시군구 코드, 취소 확정·다른 시군구 수)과 순서(계약월·계약일·지번·순번)는 그대로다.
  - `parcel_transactions(db, pnu)` 는 이 함수를 필지 하나로 부른다.
- `j5/db/parcel_years.py`: 대상 필지 전체를 `parcels_transactions` 로 한 번에 모은다.
- 시험
  - `tests/test_j5_046_batch_transactions.py` 1건: 여러 지번 표기·취소 확정·다른 시군구·수동 확정 연결(다른 시군구 포함)을 넣는다. 한 번에 모은 결과가 필지마다 정본 거래 전체를 하나씩 대조하는 기준 구현과 목록·순서·수까지 같은지 본다. 필지 하나의 결과와도 같은지, 정본에 없는 PNU 가 빈 결과인지도 본다.
  - J5-045 리뷰 시험의 가짜 함수를 새 함수에 맞췄다.
- 문서: 릴리스 계획 §10 J5-046, `tests/README.md`, 색인(J5-045 #92).

## 실제 작업 시간

약 0.7시간 (실측 스크립트·측정 0.25, 프로파일·수정 0.2, 대조·시험 0.15, 문서 0.1).

## 미확인 변수

- 실제 자료는 한 법정동의 거래 수가 가상자료보다 많거나 적을 수 있다. 가장 큰 비용은 법정동당 한 번 읽기이므로 필지 수보다 법정동 수와 법정동당 거래 수에 따라 시간이 정해진다.
- `parcels-history` 필지 하나는 조금 느려졌다(0.09초 → 0.17초, 가상). 한 번 보는 명령이라 받아들일 만하다고 본다.
