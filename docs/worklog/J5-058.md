# J5-058 폰·PC 연도별 표 대조 시험

기록일: 2026-10-02. J5-055 부터 폰 필지 카드의 연도별 표를 "PC `db parcels-years` 와 같은 규칙" 이라고 적었지만, 폰과 PC 를 같은 자료로 직접 대조한 시험은 소유 변동일(J5-053)뿐이었다. J5-057 리뷰에서 위치로만 찾은 대상의 거래가 폰의 연결 수에 들어가던 차이가 나온 것처럼, 규칙이 같다는 설명만으로는 차이를 잡지 못한다.

## 결과

- `tests/test_j5_058_years_parity.py`: 가상 파생본 생성기(`tests/fixtures/make_view.py`)의 정본으로 PC(`parcel_years`, 2000~2026)가 만든 줄과, 같은 정본에서 만든 파생본 파일(대상 목록·필지·PC 기록·거래)로 폰이 만든 줄을 필지·연도마다 대조한다. 폰 쪽은 화면과 같은 함수(`parcelAssets` → `parcelHistory` → `parcelSummaryItems` → `priceTrend`·`ownershipChanges` → `parcelYearSummaryInfo`)를 Node 로 실행한다.
  - 대조 칸: 공시지가, 같은 필지·번지대·연결 거래 수, 완전 수집 개월, 모름의 사유(미수집 ↔ `not_collected`, 일부만 ↔ `collection_incomplete` 와 시도 개월), 소유 변동일·자료 여부.
  - 폰이 판정할 수 없는 칸은 대조하지 않는다: 거래 범위 밖 동(파생본에 거래가 없다), 거래 파일이 없는 경우.
  - 빈 비교로 통과하지 않게 대조한 줄 수를 확인한다.
- `tests/fixtures/make_view.py` `build(..., inspect=None)`: 정본을 닫기 전에 부를 함수를 받는다. 파생본 내용·e2e 는 그대로다.
- 결과: 가상 정본의 필지 6개 × 2개 연도(2025·2026) 12줄이 모두 같다.
- 시험이 차이를 잡는지 확인: 폰의 거래 집계를 일부러 바꾸면(번지대를 같은 필지로 셈) 이 시험이 실패한다. 바꾼 코드는 되돌렸다.
- 앱 동작 변경은 없다.
