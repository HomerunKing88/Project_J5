# J5-011 조회 파생본·버전·게시

기록일: 2026-09-23.

## 결과

- `j5/db/projection.py` `build_projection(db, data_home, photos=False)`: 단일 작성자 잠금 안에서 고정 dataset_version 의 정본을 전부 읽고, 임시 폴더에 `assets.seed.json`(시드 스키마 그대로, 폰 앱이 바로 불러옴)·`assets.geojson`(위치점 있는 물건의 Point + 물건별 관측 요약, 미배치 물건 ID 목록)·`records.jsonl`(기록 전량, 첨부 참조)·선택 `photos/` 를 전량 생성한다. manifest(`schemas/view_manifest.schema.json`)를 쓰고, 디스크에서 다시 읽어 행수·참조·필수값·버전·해시를 검증(`verify_projection_dir`)한 뒤 ZIP 을 만들어 항목 해시를 대조하고, 정본 버전이 그대로인지 재확인한 뒤 `exports/private/projections/ds<버전>-<run8>/` 로 게시하고 `latest.json` 포인터를 같은 파일시스템에서 `os.replace` 로 교체한다.
- 실패 시 이전 파생본·포인터는 그대로, 부분 산출물은 `failed-<run8>/` 로 격리(조회자료 아님, 자동 삭제 없음), 정본은 손대지 않는다. 결과 문구가 `정본 반영됨 / 파생본 재생성 실패` 와 이전 파생본 버전·생성일을 함께 알린다.
- db_schema 3: `projection_runs`(source_dataset_version, projection_schema_version, data_mode, status, 산출물 위치·ZIP 해시, 건수, 시각, 보고 JSON). 생성 로그이므로 `dataset_version` 은 바꾸지 않는다.
- `projection_status`: 정본 버전 vs 게시 버전, 마지막 게시·실패 시각, `최신 / 구본 (정본 vN, 파생본 vM) / 없음 (재생성 필요)`. `j5 db status` 가 표시한다.
- `copy_latest`(CLI `j5 db project-copy <dest> [--allow-stale]`): 게시된 최신 ZIP 의 독립 사본(J5-008 `copy_package` 재사용, 덮어쓰기 금지·재검증·sha256 사이드카). 파생본이 정본보다 오래되면 최신용 내보내기를 막고, `--allow-stale` 일 때만 구본임을 표시하며 내보낸다(데이터 사전 §4).
- CLI `j5 db project [--photos] [--json]`. 종료 코드 0 published / 1 failed / 3 사용 오류.
- 테스트 `tests/test_j5_011_projection.py` 8건: 전량 생성·검증·게시(파일 해시·ZIP 항목·포인터·실행 기록·dataset_version 불변), 반영 후 기록·요약·사진 포함/제외, 반영 후 구본 표시·내보내기 차단·`--allow-stale`·재생성, DB 반영 후 파생본 실패(이전본·포인터 유지·부분 산출물 격리·정본 불변·재시도), 빈 정본·사진 손상·누락, 생성 중 정본 버전 변경, 검증기 변조 감지(버전·해시·manifest 밖 파일), CLI.

## 데이터 사전에 없어 정한 값

- 조회 패키지 형식 `j5view`, `projection_schema_version 1.0.0`, 파일 `manifest.json`·`assets.seed.json`·`assets.geojson`·`records.jsonl`·`photos/<sha>.<ext>`(선택). manifest 는 `format, projection_schema_version, study_id, data_mode, source_dataset_version, generated_at(UTC), run_id, scope_ids, counts, files[]`.
- 산출물 위치 `J5_DATA_HOME/exports/private/projections/ds<버전>-<run8>/` 와 그 안의 `<study>-ds<버전>-<YYYYMMDD-HHMMSS>.j5view.zip`, 최신본 포인터 `projections/latest.json`. 같은 정본 버전을 다시 생성하면 새 폴더가 생기고 포인터가 새 것을 가리킨다(이전 폴더는 지우지 않음).
- 기본은 사진 제외(§12 "필요한 범위·사진만"). `--photos` 로 기록이 참조한 사진을 포함하며 보관소의 해시를 재검증한다.
- 물건별 요약(`observation_count`, `last_observed_at`, `last_change_status`)에서 정정으로 대체된 기록(다른 기록의 `supersedes_id` 대상)은 최신 판단에서 제외하고 건수에는 포함한다.
- `records.jsonl` 은 `recorded_at`(정본 반영 시각)을 포함해 이후 당시 기록 기준 조회(§8)의 K 를 폰에서도 알 수 있게 한다. 근거(`record_evidence`)와 출처 문서는 넣지 않는다.
- 빈 정본(물건 0)은 파생본을 만들지 않는다(실패). 생성 중 정본 버전이 바뀌면 게시하지 않는다.
- 폰 앱은 아직 `.j5view.zip` 을 직접 읽지 않는다. 사용자가 ZIP 을 풀어 `assets.seed.json` 을 "시드 파일 불러오기" 로 넣는다. 앱의 ZIP 읽기·버전 표시(`불러온 버전·생성일·최신 정본 여부 미확인`)는 J5-012 이후 별도 작업으로 둔다.

## 공수

- 예상 6~10시간. 실제(세션 기준) 약 1시간 + 리뷰 반영 약 0.5시간.
- 리뷰 반영(PR #37, Codex 3건): 게시 기록 행과 포인터 교체를 한 트랜잭션 안에서 묶고(교체 실패 → 롤백, 커밋 실패 → 이전 포인터로 복구), 상태 표시가 포인터·ZIP 파일을 실제로 확인하며 data_home 없이는 '최신' 이라 하지 않음(`j5 db status --data-home`), SQLite 오류를 파생본 실패 결과·종료 코드 1 로 처리.

## 미확인 변수·남은 인수조건

- 실제 폰에서 파생본의 `assets.seed.json` 을 불러오는 흐름은 실기기 시험 이후.
- R2 의 물리적 읽기 테이블·GeoJSON 필지 도형은 이 작업 범위 밖. 지금 GeoJSON 은 위치점만 담는다.
- 백업(J5-012)은 파생본 게시와 별개다. 결과 문구가 이를 알린다.
