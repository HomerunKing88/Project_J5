# J5-004 기기 파일·사진 시험

기록일: 2026-09-22 (페이지 작성), 2026-09-23 (실기기 결과 기입). 결과는 사용자가 실제 iPhone 에서 시험한 값이며 devtest 결과 JSON 3개와 본 앱 내보내기 ZIP 1개로 확인했다.

## 페이지

`web/devtest.html`. 아무것도 전송하지 않는다. 결과 JSON을 저장하거나 복사해 이 문서에 옮긴다.

## 절차 (iPhone + Safari)

1. PC에서 `python -m http.server 8000 --directory web` 실행, 폰에서 `http://<PC IP>:8000/devtest.html` 접속. (HTTPS 경로가 있으면 그쪽에서도 한 번 더.)
2. 1절 환경 표를 읽는다. 보안 컨텍스트·crypto.subtle·IndexedDB 왕복·저장 용량 값을 기록한다.
3. 2절에서 **사진첩 선택**으로 최근 촬영 사진 1장(기본 설정이면 HEIC일 가능성), 스크린샷 1장(PNG), 큰 사진 1장을 고른다. 각 항목의 `보고된 type`, `매직바이트 판정`, 크기, 읽기·해시 ms를 기록한다.
4. 2절에서 **카메라 촬영**으로 1장 찍는다. 형식과 크기를 기록한다.
5. "이 사진을 그대로 저장"을 눌러 이진 파일 저장이 어디로 가는지(공유 시트 → 파일 앱 등) 기록한다.
6. 3절 "결과 JSON 저장"을 누르고 '파일' 앱에서 열어 확인한다. 3절 목록에서 그 저장 항목(과 5번의 사진 저장 항목)을 체크한 뒤 "결과 JSON 저장"을 한 번 더 누른다. 마지막 JSON이 확인 상태까지 담은 최종 결과이며 이것을 PC로 옮긴다(AirDrop·케이블·iCloud 등 실제 쓴 방법을 기록).
7. 비행기 모드로 페이지를 다시 연다. 열리는지(캐시 없음이므로 안 열리는 것이 정상)와 `온라인` 값을 기록한다.

## 이 결과로 정한 것

- HEIC 처리: iPhone(iOS 18.7)은 사진첩 선택·카메라 촬영 모두 JPEG 로 넘겨 준다. HEIC 거절 경로(J5-006 안내 문구, J5-007)는 다른 기기·설정을 위한 안전장치로 그대로 두고 안내 문구는 바꾸지 않는다. 사진첩의 '파일' 앱 경로로 HEIC 원본을 고르는 경우는 시험하지 않았다.
- §3.3 한도(압축 100MB·해제 250MB·사진 20MB)는 유지한다. 실제 사진은 2.4~3.0MB 로 한도의 15% 수준이다. 해시는 http 폴백에서 장당 약 1초라 사진 10장 이상을 한 번에 첨부하면 체감될 수 있다. HTTPS 에서 `crypto.subtle` 로 다시 잰다.
- `내보냄` 확인 절차(ADR-02): '파일' 앱 저장 → 사용자가 확인 후 "파일 저장 확인" 버튼. 실기기에서 이 순서가 동작한다.
- 저장 용량 API 가 없으므로 앱은 용량 경고를 미리 낼 수 없다. 저장 실패 시 '저장됨' 으로 표시하지 않는 현재 동작(J5-006)이 유일한 방어선이다.

## 공수

- 페이지·테스트 작성 예상 3~5시간, 실제(세션 기준) 약 45분. 실기기 시험 시간은 사용자 기록.

## 미확인 변수

- HTTPS 시험 경로 없음. 오프라인 재접속(서비스 워커)과 `crypto.subtle` 해시 속도는 HTTPS 배포 후 확인한다.
- 스크린샷(PNG)·비행기 모드 재접속·저장공간 부족·100MB 급 묶음·홈화면 모드는 이번 회차에서 시험하지 않았다.
- iOS 버전별 `<input capture>`·다운로드 동작 차이.
