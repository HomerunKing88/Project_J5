# J5-022 오프라인 배경 층: 도로·건물 윤곽·도로명

기록일: 2026-09-27. J5-021(외부 지도 링크) 다음 순서. 사용자가 원한 "네이버 지도 같은 배경" 을 외부 타일 없이 얻기 위해, 공공 도형 자료의 건물·실폭도로·도로 중심선을 필지처럼 파일로 넣어 지도 아래 층에 그린다(ADR-16).

## 확인한 사실과 미검증

- 도로명주소 전자지도의 층 이름·필드(`RN` 등)는 이 도구가 기본 후보로 두었을 뿐이며, 실제 배포 파일의 필드 이름·좌표계(보통 EPSG:5179)·인코딩은 `j5 parcels inspect` 로 사용자가 확인한다. 배포처의 신청·이용허락 절차는 작업 환경에서 확인하지 못했다(사용자 항목).
- Shapefile 폴리라인 레코드 배치는 폴리곤과 같다(ESRI 규격). 가상 SHP 로만 시험했다.

## 테스트 명령과 결과 (2026-09-27, 컨테이너 Linux, Node 22, Python 3.12)

- `python -m pytest -q` → 전체 통과.
- `node --test tests/web/*.test.mjs` → 54 pass, 0 fail (단위 + e2e 2개).
- 헤드리스 Chromium 390×844 캡처 5장(전체 보기·확대, 라이트·다크, 설정 블록)으로 배경 층 배치와 도로명 라벨을 확인했다. 다크에서 실폭도로가 바탕보다 어둡게 나와 배경 색 토큰(`--bm-road`·`--bm-building`)을 따로 두었다. 파일은 세션 임시 폴더에 있고 저장소에는 넣지 않았다.

## 실제 작업 시간

약 2시간 (설계·기존 코드 확인 0.4, PC 변환기·스키마·테스트 0.6, 폰 층·저장·화면·테스트 0.7, 캡처·기록 0.3).

## 미확인 변수

- 실제 배포 SHP 의 필드·좌표계·인코딩, 신청·이용허락.
- 실기기 성능: 조사 범위 배경 수천 개(건물 폴리곤은 필지보다 많다)에서 이동·확대 반응. 상한 20,000 은 계약값이지 성능 보증이 아니다.
- 도로명 라벨은 선분 길이 기준이라 곡선 도로에서는 회전 각도가 가운데 선분 기준이다.

## 남은 인수조건·후속 작업

- 사용자: 도로명주소 전자지도(건물·실폭도로·도로구간)를 허가받아 받고 `parcels inspect` 로 확인한 뒤 `basemap convert` 로 번들을 만들어 폰에 넣는다. 이용허락을 `--license` 로 기록한다.
- 다음 순서: 조회 파생본(`.j5view.zip`)을 폰이 읽어 필지·물건을 누르면 연도별 거래·기록 타임라인을 보이는 작업.
- 자동 테스트 통과는 실제 임장 검증이 아니다.
