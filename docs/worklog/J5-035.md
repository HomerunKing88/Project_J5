# J5-035 페이지 넘김이 맞지 않는 응답 거절

기록일: 2026-09-28. PR #81 의 Codex 지적(P2)에서 나온 후속이다. 건축물대장 수집에는 그 PR 에서 반영했고, 같은 검사가 없던 실거래 수집과 정본 반영에 이 작업으로 넣었다.

## 문제

- API 가 `pageNo` 를 무시하거나 잘못 읽어 앞 페이지를 되풀이해 주면, 수집 도구는 겹친 행을 더하다 totalCount 에 닿는다. 그러면 뒷 행을 받지 않고도 그 달을 `complete` 로 적었다.
- 정본 반영(`rt-load`)은 같은 응답 안에서 식별 필드가 완전히 같은 행을 순번(0, 1, …)으로 나눠 별개 거래로 둔다(데이터 사전 §7.2, J5-014B-1). 그래서 되풀이된 페이지의 행이 가짜 별개 거래로 정본에 들어갈 수 있었다.
- 실측 3차(2026-09-23)의 표본 월은 모두 1페이지라 드러나지 않았다. 달마다 1,000건을 넘는 범위나 페이지당 행 수를 줄인 수집에서 생길 수 있다.

## 결과

- `j5/collect/rt.py`:
  - `page_mismatch(parsed, page_no)`: 응답 pageNo 가 요청과 다른지 본다. 응답에 pageNo 가 없으면 확인할 수 없으므로 다르다고 보지 않는다.
  - `page_of_file(name)`: 원본 파일 이름에서 페이지 번호를 읽는다.
  - `collect_months` 는 맞지 않는 페이지를 `bad_response`("페이지 넘김이 맞지 않음")로 두고 항목을 더하지 않는다. 그 달은 `failed` 가 된다. `rt-sample`·`rt-fetch`·`rt-recheck` 가 모두 이 함수를 쓴다.
  - 재요약(`load_month_items`)은 그런 원본 파일을 넣지 않는다.
- `j5/db/transactions.py` `load_run`: 원본의 pageNo 가 기록된 페이지와 다르면 실행 전체를 `raw_page_mismatch` 로 거절한다. 트랜잭션 전 검증 단계라 정본은 바뀌지 않는다. 이 검사 전 도구로 받아 아직 반영하지 않은 실행을 막는다. 이미 반영한 실행은 다시 읽지 않는다.
- `j5/collect/br.py`: 같은 도우미를 쓰고, 요약(`load_target_items`)도 그런 원본을 뺀다.
- 시험 `tests/test_j5_035_page_mismatch.py` 4건(가상 응답, 네트워크 없음). 옛 도구를 흉내 낸 실행은 `complete` 4건으로 적혔지만 반영은 거절되고 정본은 그대로다. 다시 받은 정상 실행은 4건이 반영된다.

## 데이터 사전에 없어 정한 값

- 응답에 pageNo 가 없으면 이전처럼 받는다(확인할 수 없음을 실패로 보지 않는다). 실제 응답에 pageNo 가 들어 있는지는 기존 실측 기록에 없어 확인하지 못했다.

## 테스트 명령과 결과 (2026-09-28, 컨테이너 Linux, Node 22, Python 3.11)

- `python -m pytest -W error::UserWarning` → 390 passed (새 시험 4건 포함), 40.0초.
- `node --test --test-timeout=180000 "tests/web/*.test.mjs"` → 81 pass (폰 변경 없음).

## 실제 작업 시간

약 0.5시간 (확인 0.1, 구현 0.15, 시험 0.15, 문서 0.1).

## 미확인 변수

- 실제 공공데이터포털이 pageNo 를 무시하는 경우가 있는지는 확인하지 않았다. 이 검사는 그런 응답이 오면 조용히 틀린 결과를 만들지 않게 막는 것이다.
- 사용자 PC 의 기존 실행 기록 중 이미 `rt-load` 로 반영한 실행은 다시 검사하지 않는다. 실측 3차 실행은 달마다 1페이지라 해당하지 않는다. 그 뒤 여러 페이지로 받은 달이 있었다면 `db rt-coverage` 의 달별 건수와 포털 조회 건수를 대조한다.

## 남은 인수조건·후속 작업

- 사용자: 다음 `db rt-load` 에서 `raw_page_mismatch` 가 나오면 그 달을 `collect rt-fetch --lawd-cd … --from … --to … --refresh` 로 다시 받고 반영한다.
