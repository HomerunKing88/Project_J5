# J5-084 대상에 조회 결과 저장

기록일: 2026-10-15. 사용자 지시: "조회 결과 함께 저장하는 방향으로 진행해". ADR-27 보정. 앞서 제안한 다음 작업 후보 4번(조회한 필지 관심 목록에 저장)을 ADR-22(관심 단계는 PC 에서만 정함)에 맞춰 좁힌 것이다.

## 결과

- `web/app/vworld.js`
  - `lookupSnapshot(parcel, zoning, lookedUpAt)`: 조회 결과를 대상에 남길 모양으로 바꾼다. 항목은 `source, looked_up_at, pnu, addr, lot, jimok, jiga, gosi, area_m2, zoning, zoning_status, zoning_error, polygons, bbox` 이고, 값이 없으면 `null` 이다. 필지 객체(feature)는 넣지 않는다.
  - `lookupFacts(snapshot, { rawBelow })`: 카드 줄(지번·지목·용도지역·공시지가·도형면적). 조회 카드와 대상 카드가 같은 함수를 쓴다.
- `web/app/main.js`
  - 조회 카드는 위 기록에서 줄을 만든다(보이는 글은 이전과 같다).
  - "이 필지를 대상으로 기록" 은 대상과 그 기록을 한 트랜잭션으로 저장한다. 기록은 대상과 따로 `asset_lookups` 스토어(대상 ID 로 찾음, IndexedDB 판 6)에 둔다.
  - 대상을 고르면 대상 카드에 주소·필지 번호와 그 값, "VWorld …, 언제 조회한 값입니다. 지금 값과 다를 수 있고, PC 로는 보내지 않습니다." 를 보이고, 저장한 경계를 다시 그린다. 선택을 풀면 경계도 지운다.
- `web/index.html`: 대상 카드에 조회 기록 칸(`map-selected-lookup`).
- `web/app/db.js`: IndexedDB 판 6, `asset_lookups` 스토어, `addDeviceAsset(asset, lookup)`, `listAssetLookups()`. 파생본 시드 교체(`replaceProjection`)는 이 스토어를 건드리지 않고, 사용자가 대상을 지우면(`deleteDeviceAsset`) 함께 지운다.
- 내보내기는 바꾸지 않았다. 기록이 대상 객체 밖에 있어 `assets.new.json` 에 실리지 않는다.
- 앱 0.2.43(앱 캐시 잠금 파일 갱신).
- 문서: ADR-27 보정, DATA_DICTIONARY(패키지 절에 기기 전용 `lookup`), RELEASE_PLAN 행, 이 기록.

## 리뷰 반영 (PR #129, Codex)

- 처음에는 기록을 기기 대상(`device_assets`)의 `lookup` 에 두었다. PC 정본이 같은 대상을 돌려주면 기기 사본이 지워지므로 보내지 않은 기록이 함께 사라졌다(AGENTS.md "미반영·미확인 기록을 자동 삭제하지 않는다"). 기록을 따로 두는 스토어로 옮겼다.
- 대상 카드에 주소와 필지 번호가 빠져 있었다. 앞에 두 줄을 더했다.
- VWorld 이용약관의 기기 보관 범위 확인 전에 저장해도 되는지는 사용자에게 묻는다(아래 미확인 변수).

## 판단

- PC 로 옮기지 않는다. PC 의 `assets_new.schema.json` 은 정해진 항목 밖을 거절하고, 폰에서 본 조회 값을 정본 근거로 넣는 것은 R1a 범위(폰에서 정본을 고치지 않음)와 ADR-27 본문(온라인 조회는 PC 정본의 근거가 아님) 밖이다. 필요해지면 새 ADR 로 정한다.
- 관심 단계·관찰목록은 ADR-22 대로 PC 에서만 정한다. 폰의 대상은 PC 로 보내면 확인 전 대상으로 들어간다(기존 J5-028 흐름).
- 저장한 값은 조회 그때의 값이라 시각과 출처를 늘 함께 보인다. 이 폰에서 다시 조회해 갱신하는 기능은 만들지 않았다.

## 시험

- `tests/web/vworld.test.mjs`: 기록 항목, JSON 저장, 카드 줄 순서(대상 카드의 주소·필지 번호 포함), 미확인, 용도지역 없음·실패·이름 없음.
- `tests/web/export.test.mjs`: `lookup` 이 든 기기 대상으로 패키지를 만들고 `j5 inspect` 가 통과한다(추가 항목을 거절하는 PC 스키마를 통과하므로 실리지 않았다는 확인).
- `tests/web/lookup.e2e.test.mjs` 6b: 조회 카드에서 대상을 만들고 목록에서 고르면 대상 카드에 주소·필지 번호·값·출처·안내가 보이고 경계가 그려진다. 대상 객체에는 기록이 없고 `asset_lookups` 에 기록(PNU·공시지가·경계·조회 시각)이 있으며 키가 없음을 본다. 선택을 풀면 경계가 지워진다.
- 같은 시험 7: 파생본 시드가 같은 대상을 돌려주면 기기 사본은 지워지고 조회 기록은 남는다.

## 테스트 명령과 결과 (2026-10-15, 컨테이너 Linux, Python 3.11, Node 22)

- 구현 전 `node --test tests/web/vworld.test.mjs` → 새 시험 실패(함수 없음)를 확인했다.
- `python -m pytest -W error::UserWarning` → 474 passed (61초).
- `node --test --test-timeout=180000 "tests/web/**/*.test.mjs"` → 121 pass.
- 리뷰 반영 중 웹 시험 전체를 병렬로 여러 번 돌릴 때 간헐 실패가 있었다.
  - ux.e2e: CDP 명령(평가·마우스) 응답이 20초 동안 오지 않음. 매번 다른 단계에서 났고 새로고침 직후가 많았다.
  - lookup.e2e: 확대 시험(4단계)의 시간 조건.
  - 비교: 이 브랜치는 ux.e2e 6개 동시 실행 12회 중 1회 실패, main 은 같은 조건 12회와 전체 5회 모두 통과했다.
  - lookup.e2e 는 원인을 찾았다. 대상 선택 시험(6b)이 지도를 대상 쪽으로 옮겨 다음 확대 시험의 출발 화면이 달라졌다. 그 시험을 확대 시험 뒤로 옮겼다.
  - ux.e2e 의 멈춤은 앱 코드에서 원인을 찾지 못했다(이 작업은 그 경로에 IndexedDB 판 6 과 조회 기록 읽기만 더한다). 옮긴 뒤 전체 4회는 모두 통과했다. 원인은 확정하지 못했다.
