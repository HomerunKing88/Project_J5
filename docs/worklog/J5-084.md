# J5-084 대상에 조회 결과 저장

기록일: 2026-10-15. 사용자 지시: "조회 결과 함께 저장하는 방향으로 진행해". ADR-27 보정. 앞서 제안한 다음 작업 후보 4번(조회한 필지 관심 목록에 저장)을 ADR-22(관심 단계는 PC 에서만 정함)에 맞춰 좁힌 것이다.

## 결과

- `web/app/vworld.js`
  - `lookupSnapshot(parcel, zoning, lookedUpAt)`: 조회 결과를 대상에 남길 모양으로 바꾼다. 항목은 `source, looked_up_at, pnu, addr, lot, jimok, jiga, gosi, area_m2, zoning, zoning_status, zoning_error, polygons, bbox` 이고, 값이 없으면 `null` 이다. 필지 객체(feature)는 넣지 않는다.
  - `lookupFacts(snapshot, { rawBelow })`: 카드 줄(지번·지목·용도지역·공시지가·도형면적). 조회 카드와 대상 카드가 같은 함수를 쓴다.
- `web/app/main.js`
  - 조회 카드는 위 기록에서 줄을 만든다(보이는 글은 이전과 같다).
  - "이 필지를 대상으로 기록" 은 그 기록을 이 폰의 대상(`device_assets`)의 `lookup` 에 함께 저장한다.
  - 대상을 고르면 대상 카드에 그 값과 "VWorld …, 언제 조회한 값입니다. 지금 값과 다를 수 있고, PC 로는 보내지 않습니다." 를 보이고, 저장한 경계를 다시 그린다. 선택을 풀면 경계도 지운다.
- `web/index.html`: 대상 카드에 조회 기록 칸(`map-selected-lookup`).
- 내보내기는 바꾸지 않았다. `export.js` 는 정해진 항목만 옮기므로 `lookup` 은 `assets.new.json` 에 실리지 않는다.
- 앱 0.2.43(앱 캐시 잠금 파일 갱신).
- 문서: ADR-27 보정, DATA_DICTIONARY(패키지 절에 기기 전용 `lookup`), RELEASE_PLAN 행, 이 기록.

## 판단

- PC 로 옮기지 않는다. PC 의 `assets_new.schema.json` 은 정해진 항목 밖을 거절하고, 폰에서 본 조회 값을 정본 근거로 넣는 것은 R1a 범위(폰에서 정본을 고치지 않음)와 ADR-27 본문(온라인 조회는 PC 정본의 근거가 아님) 밖이다. 필요해지면 새 ADR 로 정한다.
- 관심 단계·관찰목록은 ADR-22 대로 PC 에서만 정한다. 폰의 대상은 PC 로 보내면 확인 전 대상으로 들어간다(기존 J5-028 흐름).
- 저장한 값은 조회 그때의 값이라 시각과 출처를 늘 함께 보인다. 이 폰에서 다시 조회해 갱신하는 기능은 만들지 않았다.

## 시험

- `tests/web/vworld.test.mjs`: 기록 항목, JSON 저장, 카드 줄 순서, 미확인, 용도지역 없음·실패·이름 없음.
- `tests/web/export.test.mjs`: `lookup` 이 든 기기 대상으로 패키지를 만들고 `j5 inspect` 가 통과한다(추가 항목을 거절하는 PC 스키마를 통과하므로 실리지 않았다는 확인).
- `tests/web/lookup.e2e.test.mjs` 3b: 조회 카드에서 대상을 만들고 목록에서 고르면 대상 카드에 값·출처·안내가 보이고 경계가 그려진다. IndexedDB 의 기록(PNU·공시지가·경계·조회 시각)을 확인하고 키가 없음을 본다. 선택을 풀면 경계가 지워진다.

## 테스트 명령과 결과 (2026-10-15, 컨테이너 Linux, Python 3.11, Node 22)

- 구현 전 `node --test tests/web/vworld.test.mjs` → 새 시험 실패(함수 없음)를 확인했다.
- `python -m pytest -W error::UserWarning` → 474 passed (63초).
- `node --test --test-timeout=180000 "tests/web/**/*.test.mjs"` → 첫 실행 120 pass·1 fail(ux.e2e, 사유를 남기지 못함), 그 뒤 ux.e2e 단독 1회와 전체 2회는 모두 통과(121 pass). 재현되지 않아 원인은 확정하지 못했다.

## 실제 작업 시간

약 1시간.

## 미확인 변수

- VWorld 이용약관이 조회 결과를 기기에 보관하는 것을 허용하는 범위. 사용자 확인 전이다.
- 큰 필지 경계를 여러 대상에 저장할 때 IndexedDB 사용량. 꼭짓점 상한(20,000)은 조회 해석에서 이미 건다.

## 남은 인수조건·후속 작업

- 사용자: 머지·배포 뒤 폰에서 지도를 눌러 조회하고 "이 필지를 대상으로 기록" 으로 대상을 만든 다음, 대상 목록에서 그 대상을 골라 값·조회 시각·경계가 보이는지 본다.
